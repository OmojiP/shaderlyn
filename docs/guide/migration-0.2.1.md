## 書き換えが要るか

以下の場所に、下の表の「前の ID」が書かれている場合は、書き換えが必要です。前の ID は使えません。

- 抑制コメント (`// shaderlyn-disable-next-line SL1055` など)
- 設定ファイルの `rules:`
- ベースライン
- 出力 (text / json / sarif / github) をルール ID で絞り込んでいる CI の設定やスクリプト

どれにも書いていなければ、書き換えは要りません。

## ルール ID の付け替え

ID の接頭辞の意味をそろえました。`HL` はどの環境でも出るもの、`SL` は ShaderLab、`UN` は Unity に固有の振る舞い
(シェーダーコンパイラ・プリプロセッサ・ファイルの読み込み) です ([ルール一覧](../rules/README.md))。

| 前の ID | 今の ID | 内容 |
| --- | --- | --- |
| SL0002 | [HL0005](../rules/HL0005.md) | 一部の検査を見送った |
| SL0003 | [HL0006](../rules/HL0006.md) | 調べていないシンボルの経路がある |
| SL0004 | [HL0007](../rules/HL0007.md) | 条件を追えなかった箇所がある |
| SL1056 | [UN0001](../rules/UN0001.md) | Unity は UTF-16 のファイルを読めない |
| SL1055 | [UN0101](../rules/UN0101.md) | Unity では #pragma once が効かない |
| SL1050 | [UN0201](../rules/UN0201.md) | コンパイラの指定が無視される |
| SL1051 | [UN0202](../rules/UN0202.md) | コンパイラの指定についての注意 |
| SL1053 | [UN0203](../rules/UN0203.md) | DX11 で使えなくなるコンパイラの指定 |
| SL1054 | [UN0204](../rules/UN0204.md) | Unity のバージョンでコンパイラが変わる指定 |
| SL1052 | [UN0205](../rules/UN0205.md) | 16 ビットの型を有効にしたパスの定数バッファに half がある |
| HL0302 | [UN0301](../rules/UN0301.md) | シェーダーステージの指定が無い |

Unreal Engine の環境では、欠けているのがエンジンが生成するファイルだけのとき、SL0002 ではなく
[UE0001](../rules/UE0001.md) / [UE0002](../rules/UE0002.md) が出ます。前に SL0002 を書いていたなら、そちらに書き換えてください。

### 書き換え方

抑制コメントと設定ファイルは、ID を置き換えてください。たとえば Git Bash や Linux では次のようにできます
(書き換える前に、変更を確かめられるようにしておいてください)。

```bash
grep -rlE 'SL000[234]|SL105[0-6]|HL0302' Assets .shaderlyn.yaml | xargs sed -i -E \
  -e 's/SL0002/HL0005/g; s/SL0003/HL0006/g; s/SL0004/HL0007/g' \
  -e 's/HL0302/UN0301/g; s/SL1050/UN0201/g; s/SL1051/UN0202/g; s/SL1052/UN0205/g' \
  -e 's/SL1053/UN0203/g; s/SL1054/UN0204/g; s/SL1055/UN0101/g; s/SL1056/UN0001/g'
```

ベースラインは作り直すのが簡単です。0.2.0 のときと同じ指摘を凍結したいなら、0.2.1 で `--write-baseline` を実行し直してください。

```bash
shaderlyn Assets --unity-project . --write-baseline .shaderlyn-baseline.json
```

ただし作り直すと、下の「新しく出る指摘」と「指摘が変わるところ」で増えた指摘も凍結されます。
前の指摘だけを残したい場合は、ベースラインのファイルの中の ID を上と同じように置き換えてください。

## 新しく出る指摘

0.2.1 で足したルールです。既存のシェーダーにも出ることがあります。

| ID | 重要度 | 内容 |
| --- | --- | --- |
| [HL0303](../rules/HL0303.md) | 警告 | cbuffer の中の関数をエントリポイントにしている (FXC でコンパイルされるとき) |
| [HL0304](../rules/HL0304.md) | エラー | cbuffer の中の関数をエントリポイントにしている (DXC でコンパイルされるとき) |
| [UN0002](../rules/UN0002.md) | 警告 | `.shader` の先頭に BOM が重なっている (0.2.0 では SL0001 のエラーだった) |
| [UN0102](../rules/UN0102.md) | 警告 | ヘッダの中の取り込みを、ヘッダではなくシェーダーからの相対で見つけている (0.2.0 では HL0321 のエラーだった) |
| [UE0001](../rules/UE0001.md) / [UE0002](../rules/UE0002.md) | 情報 | Unreal Engine: 生成ファイルが無いので宣言の検査を見送った (0.2.0 では SL0002) |

## 指摘が変わるところ

Unity の振る舞いに合わせて直したので、0.2.0 と指摘が変わることがあります。

- **共通コード片 (`HLSLINCLUDE` / `CGINCLUDE`)**: ファイルの中の同じ種類のものをすべてファイルの順につなぎ、どのコードブロックの前にも置きます
  (Pass より後に書いたものも、別の SubShader のものも)。`CGINCLUDE` は `HLSLPROGRAM` に、`HLSLINCLUDE` は `CGPROGRAM` に入れません。
  0.2.0 で出ていた「宣言されていない」(HL0310) の誤検出が消え、`CGINCLUDE` と `HLSLPROGRAM` を混ぜた誤りが新しく出ることがあります
- **同じヘッダを取り込む Pass**: キーワードを宣言する Pass と宣言しない Pass が同じヘッダを取り込むと、0.2.0 では HL0310 / HL0360 を誤って報告していました。出なくなります
- **ヘッダの中の `#include`**: ヘッダから見つからなければ、シェーダーからの相対で探し直します (UN0102 の警告付き)。0.2.0 の HL0321 が消えることがあります
- **`.shader` の先頭のノーブレークスペース (U+00A0)**: Unity は構文エラーにするので、SL0001 を出します (0.2.0 は見逃していました)
- **Unity 6.3.26f1 以降の Editor**: 同梱のヘッダ (`UnityCG.cginc` など) を `Editor/Data/Resources/CGIncludes` から引きます。
  0.2.0 で TOOL0004 になっていた CGPROGRAM のシェーダーが解析されるようになり、指摘が増えることがあります
- **ヘッダの中の指摘**: 文の下に `取り込み元:` の行が付きます。テキストの出力を読んでいるスクリプトは、行の数が変わることに気を付けてください
  (`--include-trace none` で出さないようにできます)

## キャッシュ

キャッシュ (`--cache`) の形式が変わりました。0.2.0 のキャッシュは使わずに全件を解析し直し、新しい形式で書き直します。手で消す必要はありません。
