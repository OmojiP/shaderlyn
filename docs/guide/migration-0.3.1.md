## 書き換えが要るか

以下の場所に、下の表の「0.3.0 の ID」が書かれている場合は、書き換えが必要です。**0.3.0 の ID は使えません。**

- 抑制コメント (`// shaderlyn-disable-next-line HL0310` など)
- 設定ファイルの `rules:`
- ベースライン
- 出力 (text / json / sarif / github) をルール ID で絞り込んでいる CI の設定やスクリプト
- 自作ルールのテストなど、組み込みのルールの ID を書いたコード

どれにも書いていなければ、書き換えは要りません。

書き換えないまま 0.3.1 で解析すると、次のようになります。

- 設定ファイルの `rules:`: その行に TOOL0003 (警告) が出ます。その設定は効いていません
- 抑制コメントとベースライン: 何も伝えずに効かなくなり、抑制していた指摘が出ます

## ルール ID の振り直し

HLSL にしか無いルール (HL0003、HL0210、HL0211、HL0303、HL0304、HL0345、HL0347、HL0348、HL0349、HL0354) は、HL のまま変わりません

## 書き換えの手順

置き換えは、スクリプト [tools/migrate/0.3.1.mjs](../../tools/migrate/0.3.1.mjs) でまとめて行えます (Node.js で動き、OS を選びません)。
上の表の置き換えを、設定ファイル (`.yaml` / `.yml`)・ベースライン (`.json`)・シェーダーのファイル (抑制コメント)・自作ルールのコード (`.cs`) に行います。

1. プロジェクトをコミットしておく (置き換えはファイルを直接書き換える)
2. スクリプトを流す。フォルダーの下を書き換え、書き換えたファイルを並べる (`bin` / `obj` / `.git` / `node_modules` / `Library` の下は見ない)

   ```sh
   node path/to/0.3.1.mjs <プロジェクトのフォルダー>
   ```

3. 0.3.1 で解析し、設定ファイルに TOOL0003 (知らない ID) が出ないことと、抑制していた指摘が出ていないことを確かめる

### スクリプトでは置き換えないもの

- **正規表現で書いた重要度** (`/HL03.*/: error` など)。どの ID に当たるかが変わるので、書き直してください。
  スクリプトは、`HL` を含む正規表現のキーを見つけると場所を伝えます。
  CF のルールは `/CF.*/`、HLSL にしか無いルールは `/HL.*/` で指定できます
- **CI の設定やスクリプトの中の ID** (出力を ID で絞り込んでいるものなど)。拡張子で見るファイルを決めているので、ほかの形式のファイルは書き換えません
