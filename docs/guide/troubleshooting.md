## 指摘の出方

### SL0002 が全ファイルに出る

`--unity-project` の指定先が正しくないか、一部のヘッダだけ引けていません（[CLI の使い方 5 章](cli-usage.md#5-プロジェクトの解析設定)）。
1 つも引けていない場合は `SL0002` と一緒に `TOOL0004` のエラーが出ます。
原因はそちらで、直し方もメッセージに書かれています。

同じオプションに `--env` を足して実行すると、解析はせずに、使う Unity Editor・パッケージの解決先・
解決できない `#include` を表示します（[CLI の使い方 8 章](cli-usage.md#8-解析の中身を見る)）。

### SL0002 が特定のファイルだけに出る

メッセージの 2 行目に `このファイルの HLSL を解析できませんでした` と出ている場合、
そのファイルに構文エラーがあります。同じファイルに `HL0001` / `HL0002` として該当行が
報告されているので、そちらを直すと対応検査も働きます。

### 指摘が出ない、または出る理由が分からない

`--inspect` で解析の中身を HTML に書き出して確認します（[CLI の使い方 8 章](cli-usage.md#8-解析の中身を見る)）。
型を根拠にするルールが何も報告しないときは、「式の型」のタブで型が空欄の式がないかを見てください。
ルールが見ている情報が足りない場合は、uniform や include のタブで分かります。

ヘッダが読めているかどうかは `--env` で確かめられます。

### 取り込んだヘッダの指摘が出る・出ない

利用者が書いて取り込んだヘッダ (共通の `.hlsl` など) は、取り込むシェーダーの文脈で検査し、指摘はヘッダの位置に出ます。
Unity と外部パッケージのヘッダは報告しません。プロジェクトの `Library` の下と、Unity Editor に同梱のものです。

自分で書いたヘッダの指摘が出ない場合は、そのヘッダが `Library` の下に置かれていないかを確かめてください。
`--unity-project` で指定したプロジェクトの `Library` の下は、すべて外部のヘッダとして扱います。

### SL1001 が大量に出る

カスタム `ShaderGUI` からプロパティを読んでシンボルを切り替えている場合、
シェーダー自身はその値を読まないため、この指摘が出ます。
その書き方をプロジェクト全体で使っているなら重要度を下げるか、
ベースラインで既存分を凍結してください（[CLI の使い方 6 章](cli-usage.md#6-ベースライン)）。

```yaml
rules:
  SL1001: info
```

### SL0003 が出る

「シンボルの経路をすべては調べていない」という報告で、シェーダーの誤りではありません。

`#pragma shader_feature` で宣言したシンボルはマテリアルからも C# からも切り替えられるため、
どの経路もいつか通るコードです。解析はそのシェーダー自身の条件が見ているシンボルを
1 つずつ有効にして調べますが、展開の件数には上限があります（既定 8）。

```bash
shaderlyn Assets/Shaders --unity-project . --max-symbol-variants 16
```

解析時間はシンボルの数に比例して伸びます。

宣言したシンボルを実際には使っていないなら、`HL0331` が該当の `#pragma` を指しています。
使わない宣言を消せば、展開すべき経路自体が減ります。
仕組みは [条件付きコンパイルの扱い](conditional-compilation.md) にあります。

## 実行と出力

### 終了コードが 2 になる

ツールの実行に失敗しています（引数の誤り、ファイルを読めない、ベースラインを読めない など）。
標準エラーに理由が出ています。終了コードの意味は [CLI の使い方 4 章](cli-usage.md#4-終了コード) にあります。

### SARIF をアップロードしても GitHub に何も表示されない

SARIF の中のパスが絶対パスのままだと、GitHub がリポジトリのファイルに対応づけられません。
`--base-path` にリポジトリのルートを渡してください（[CLI の使い方「出力形式」](cli-usage.md#出力形式)）。

### 解析が遅い

- `--cache` を付けると、前回から変わっていないファイルを解析しません（[CLI の使い方 7 章](cli-usage.md#7-キャッシュ)）
- `--timings` を付けると、構文解析・展開・ルールのどこに時間がかかっているかを標準エラーへ出します
- 解析対象を `Assets` 以下に絞ってください。プロジェクトのルートを渡すと Unity のパッケージまで解析します（[CLI の使い方 2 章](cli-usage.md#2-基本的な実行)）

## 設定ファイル

### 設定ファイルの内容が認識されない

`TOOL0003` の警告が出ていないか確認してください。キーのスペルミスはここで報告されます（[設定ファイル「設定の誤りの報告」](configuration.md#設定の誤りの報告)）。

設定ファイルが見つかっているかどうかは、`--env` を付けて実行すると表示されます。
`--config <パス>` で明示的に指定することもできます。

## CI

### CI でだけ TOOL0004 が出る

ランナーに `Library/PackageCache` が無いため、パッケージのヘッダを解決できていません。
`Library` のあるマシンをセルフホストランナーにする手順は [CI に組み込む](ci-setup.md) にあります。

### キャッシュが効かない

ログに `キャッシュを読み込めませんでした` / `キャッシュを書き出せませんでした` が出ていないか確認してください。
キャッシュファイルを作業フォルダーの中に置くと、`actions/checkout` が実行のたびに消します（[CI に組み込む 4 章](ci-setup.md#4-キャッシュで-2-回目以降を速くする)）。

## VS Code 拡張

### HLSL の指摘が、打っている間に消える

HLSL を見る検査は、ファイルを開いたときと保存したときに走ります。
打っている最中は ShaderLab 単体の検査だけが走るため、HLSL の指摘はいったん消え、保存すると戻ります。

### ホバーや補完が、ある場所でだけ出ない

出力パネルの **Shaderlyn** を開いてください。サーバー内部で処理が失敗した場合は「〜に失敗しました」と例外の内容が記録されています。
不具合の報告にはこの記録を添えてください。

### 自作ルール入りの言語サーバーを使うとき

サーバーの作り方は [自作ルールの作り方「エディタでも働かせる」](../custom-rules/tutorial.md#5-1-エディタでも働かせる)、
VS Code からの指し方は [VS Code 拡張の README「自作ルールを使う」](../../editors/vscode/README.md#自作ルールを使う) にあります。

| 症状 | 原因 |
| --- | --- |
| 設定を変えた・publish し直したのに、自作ルールの指摘が出ない | ウィンドウを再読み込みしていません。拡張は起動したときのサーバーを使い続けます |
| publish が「ファイルを上書きできない」「別のプロセスで使用中」で失敗する | VS Code が実行中のサーバーを使っています。ウィンドウを閉じてから publish するか、別のフォルダーへ出してください |
| 「言語サーバが見つかりません」と出る | `serverPath` のファイルが存在しません。パスが空の場合は同梱バイナリにフォールバックしますが、指定した場合はフォールバックしません |
| 指摘が 1 件も出ない / 途中で止まる | ルールが標準出力へ何か書いていないか確認してください。`shaderlyn.trace.server` を `"verbose"` にすると、出力パネルの **Shaderlyn** に通信内容が出ます |
| 組み込みルールまで消えた | 一覧に `.. BuiltInAnalyzers.All` を入れ忘れています |
| CI では落ちるのに編集中は出ない | CLI 側とサーバー側で渡している一覧が違います。どちらも同じ一覧を渡してください |

## 自作ルール

### 自作ルールの指摘が出ない

1. `SupportedDiagnostics` に入れましたか。入っていないルールはアナライザごと実行されないことがあります
2. `RegisterNodeAction` に HLSL のノード型を渡していませんか。ShaderLab の木しか歩きません。
   HLSL を見るときは `HlslRuleAnalyzer` を使います（[自作ルールの作り方 3 章](../custom-rules/tutorial.md#3-ルールを書く)）
3. セマンティックモデルが `null` ではありませんか。`--unity-project` を渡していないと構築されないことがあります
4. `--inspect` で構文木を見て、期待した型のノードがあるか確かめてください

### TOOL0005 が出る

`SupportedDiagnostics` への申告漏れです。[TOOL0005](../rules/TOOL0005.md) を読んでください。

### TOOL0006 が出る

メッセージの穴の数と引数の数が合っていません。[TOOL0006](../rules/TOOL0006.md) を読んでください。

### TOOL0001 が出る

ルールが例外を投げています。解析全体は止まりませんが、そのルールはその場で打ち切られています。
メッセージに例外の内容が入っているので、それを見て直してください。
`IsMissing` なトークンや `null` の子ノードを、確かめずに触っていることが多いです。
