# HL0332: どの構成でも成り立たない条件です

分類: Correctness / 既定の重要度: 情報

## 何を検出するか

`#if` / `#elif` の条件が、宣言されたシンボルをどう有効にしても成り立たない箇所です。

```hlsl
#pragma multi_compile _ _DETAIL

#if _DETAIL == 2        // 有効なシンボルの値は 1
    float _DetailScale; // このコードは決してコンパイルに含まれない
#endif
```

次の形も同じです。

```hlsl
#pragma multi_compile _ _X _Y          // _X と _Y は同時に有効にならない
#if defined(_X) && defined(_Y)
#endif

#pragma multi_compile MODE_A MODE_B    // どちらか 1 つが必ず有効
#if !defined(MODE_A) && !defined(MODE_B)
#endif
```

## なぜ問題か

Unity は、有効なシンボルを値 1 のマクロとして定義します。無効なシンボルは定義されず、条件の中では 0 になります。
そのため `#if _DETAIL == 2` は、`_DETAIL` を有効にしても無効にしても成り立ちません。

同じ `#pragma` 行に並べたシンボルは同時に有効になりません。
`_` の無い `multi_compile` の行は、どれか 1 つが必ず有効になります。
これらに反する組み合わせを求める条件も、実在する構成では成り立ちません。

Unity はこれをエラーにも警告にもしません。書いた分岐が丸ごとコンパイルに含まれないまま出荷されます。

## どう直すか

通したい構成に合わせて条件を書き直してください。

```hlsl
#if _DETAIL           // または #ifdef _DETAIL / #if defined(_DETAIL)
    float _DetailScale;
#endif
```

同時に有効にしたいシンボルは、別々の `#pragma` 行で宣言します。

意図して無効にしている分岐であれば、抑制して構いません。

## 判定できる範囲

**宣言されたシンボルと定数だけでできた条件を判定します。**
`SHADER_API_D3D11` のような環境のマクロや、別のマクロを含む条件は判定しません。
環境のマクロは 1 通りの値を仮に選んで解いているだけで、別のプラットフォームでは成り立つことがあるためです。

条件に現れるシンボルが 10 個を超える場合も判定しません。

**報告するのは、このファイルに書かれた条件だけです。**
取り込んだヘッダの中の条件は、そのヘッダの都合で書かれたものであり、利用者に直しようがありません。

このシンボルを有効にした構成を別に展開すること（[条件付きコンパイルの解析](../guide/conditional-compilation.md#5-構成ごとの展開方法-b)）もしません。
どの構成でも通らない分岐は、展開しても読めるものが増えないためです。

## 誤検出だと思ったら

`#pragma` が `#if` の中に書かれているなど、このツールが見ていない形でシンボルを宣言している場合、
宣言の行の読み方が実際と違うことがあります。その場合はこの指摘を抑制してください。

```hlsl
// shaderlyn-disable-next-line HL0332
#if _DETAIL == 2
```
