# SL1058: 取り込みをシェーダーからの相対で見つけています

分類: Correctness / 既定の重要度: 警告

Unity の環境だけで出ます。

## 何を検出するか

ヘッダ (`.hlsl` / `.cginc` など) の中の `#include "..."` が、そのヘッダからの相対では見つからず、
ヘッダを取り込んでいるシェーダー (`.shader`) からの相対で見つかったものです。報告はヘッダの `#include` の行に出します。

```
Assets/Shaders/Lib/Sub/H.hlsl(1:10): warning SL1058: '../B.hlsl' はこのファイルからは見つからず、取り込んでいるシェーダーからの相対で見つけています。
    Unity では通りますが、別のフォルダーのシェーダーから取り込むと見つからなくなります。このファイルからの相対の '../../B.hlsl' に直してください。
    取り込み元: Assets/Shaders/Deep/Pass.shader(10:22) → …
```

見つけたファイルは読み、解析はそのまま続けます。

## なぜ問題か

Unity は、ヘッダの中の `#include "..."` がそのヘッダから見つからないと、解析しているシェーダーからの相対で探し直します
(Unity 6.6 で確かめました)。

| 書き方 | Unity の結果 |
| --- | --- |
| ヘッダからの相対で正しい | 通る |
| ヘッダからは見つからず、シェーダーからの相対で見つかる | 通る (この指摘) |
| 両方で見つかる | ヘッダからの相対のほうを読む |
| 途中にある別のヘッダからの相対でだけ見つかる | 見つからない (`Couldn't open include file`) |
| `../` の数を間違えたなど、どちらからも見つからない | 見つからない ([HL0321](HL0321.md)) |

そのシェーダーではコンパイルできますが、パスがヘッダの場所ではなく、たまたま取り込んだシェーダーの場所に合っています。
別のフォルダーにあるシェーダーが同じヘッダを取り込むと、そのシェーダーはエラーになります。
`../` の数が 1 つ違うのに動く、という形で気づくことが多いです。

## どう直すか

メッセージにある、ヘッダからの相対パスに直してください。エディタ (VS Code) では、この指摘から直接置き換えられます。

```hlsl
// Assets/Shaders/Lib/Sub/H.hlsl
#include "../../B.hlsl"   // ヘッダからの相対
```

`Assets/` から始まるパス (`#include "Assets/Shaders/B.hlsl"`) にすると、どこから取り込んでも同じファイルを指します。

## 誤検出だと思ったら

特定のシェーダーからだけ取り込む前提のヘッダで、パスをシェーダーに合わせているなら、設定ファイルの `rules:` で `SL1058: none` にできます。
