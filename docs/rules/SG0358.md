# SG0358: ジェネリックの仮引数の書き方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のジェネリックの仮引数を、正しくない形で書いている状態です。slangc はコンパイルの誤り (E30624・E30625・E30401・E30117・E30855・E30408・E30441・E30522・E30122・E30402・E30404・E30413・E30416・E30852) にします。

```slang
void a<let N>() { }                        // 値の仮引数に型が存在しない
void b<let F : float>() { }                // 値の仮引数の型は整数・列挙型・bool
struct C<D : int> { }                      // 制約に int (値の仮引数の場合は let D : int)
struct Foo { }
void d<T : Foo>(T x) { }                   // 制約に構造体 (インターフェイスを書く)
interface IFloat { }
interface IFoo<T : IFloat> { }
void e<Foo : IFoo<T>, T : IFloat>() { }    // 制約が後ろの仮引数 T を指す
extension<T> int { }                       // T が拡張する型に出てこない
Buffer b0;                                 // 型引数が必要なジェネリックの型
struct Pair<T, U> { }
Pair<int> p;                               // 型引数の数が合わない
Buffer<> b1;                               // 要素の型が存在しない
struct Bad<each T, U> { }                  // 可変長の並びの後ろの仮引数
void g<A = B, B = int>() { }               // 既定の値が後ろの仮引数を指す
void h<T>() where int : IFloat { }         // where の左が仮引数でない
void k<T>() where T == IFloat { }          // == の右がインターフェイス (& でつないだものも)
struct P<each T> where nonempty(int) { }   // nonempty(…) にこの宣言の可変長の並びでないもの
extension<T> T : IFloat { }                // 制約が存在しない型の仮引数そのものの extension (extension<T : IBar> T と書く)
extension IFloat { }                       // インターフェイスの extension (extension<T : IFloat> T と書く)
```

型引数が必要なジェネリック型は、`Buffer`・`Tuple` と、既定の型引数が存在しない利用者のジェネリックの型です。
extension の型の仮引数は、拡張する型に出てくる仮引数の制約の中に出てくれば決まります (`extension<T, U : IBuf<T>> U`)。

## ジェネリックのエントリポイント

`[shader]` か `[numthreads]` を書いた関数にジェネリックの仮引数を書くと、型引数が決まらないので誤りです (E38014)。CUDA のコンパイル先 (`slang: target` の `cuda`・`ptx`) では、`[numthreads]` だけの関数はエントリポイントにならないので見ません (`cpp` ではなります)。

```slang
[shader("compute")]
[numthreads(1, 1, 1)]
void main<T : IFloat>(uint3 id : SV_DispatchThreadID) { }
```

slangc の `-specialize` か `-entry main<Foo>` か、アプリの側で Slang の API (`IEntryPoint` と `specialize`) を使用して型引数を決める場合は、設定ファイルの [`slang: generic-entry-points`](../guide/configuration.md#slang) を `true` にしてください。この報告をしなくなります。

ファイル全体で宣言したジェネリック仮引数 (`type_param T : IFoo;`・`__generic_value_param N : int;`) を、エントリポイントから直接または間接に呼び出される関数で使用する場合も報告します。指摘位置は仮引数の宣言です (E38207)。
この仮引数は、リフレクションと、API か `-specialize` で型引数を決めるためのものです。決める場合は、同じく `slang: generic-entry-points` を `true` にしてください。

```slang
interface IFoo { int get(); }
type_param T : IFoo;               // 報告する
RWStructuredBuffer<int> output;

[shader("compute")]
[numthreads(1, 1, 1)]
void main()
{
    T t;
    output[0] = t.get();
}
```

型引数の書き方の誤りも報告します。

- ジェネリックでない利用者の関数に型引数を書いた呼び出し (`nonGeneric<G>()`。E39999)
- `where` の制約の左の `__trimFirst(T)`・`__trimLast(T)` (E30402)
- 仮引数がどれも並び (`<let each A : int, let each B : int>`) の型の、並びの数で割り切れない数の型引数 (`TwoPacks<1, 2, 3, 4, 5>`。E30075)
- 既定の値が制約が存在しない型の仮引数のメンバー (`<T, let N : int = T.size>`) で、その既定の値を使用する型引数の並び (`Foo<int>`。E30075)

## なぜ問題か

slangc がコンパイルできません。

## どう直すか

値の仮引数は `let N : int` と書き、制約にはインターフェイスを書いてください。仮引数は、使用するものより前に宣言してください。
