# HL0346: 構造体に使用できない演算子です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

構造体の値に、使えない演算子を使っている式と、多重定義できない演算子の定義です。

```hlsl
struct Light { float3 color; float intensity; };

Light a, b;
Light c = a + b;               // 報告する。Light は operator+ を定義していない
Light d = k > 0 ? a : b;       // 報告する。条件演算子は構造体を選べない (演算子を定義していても)
a += b;                        // 報告する。複合代入は構造体に使えず、多重定義もできない
float e = 2 * a;               // 報告する。右辺だけが構造体の演算は、演算子を定義しても使えない
float f = 2 * a.intensity;     // 正しい。メンバーは数値型
a = b;                         // 正しい。ふつうの代入は使える
```

HLSL の演算子は数値型 (スカラー・ベクトル・行列) の値にしか使えません。

HLSL 2021 では、構造体の中で演算子を定義すると、その構造体を**左辺**にして使えます。

```hlsl
struct Rgb
{
    float3 value;
    Rgb operator+(Rgb other) { Rgb r; r.value = value + other.value; return r; }
    bool operator==(Rgb other) { return all(value == other.value); }
};

Rgb a, b;
Rgb c = a + b;     // 正しい
bool e = a == b;   // 正しい
bool n = a != b;   // 報告する。!= は == から導かれない
Rgb d = a * 2;     // 報告する。operator* が無い
float3 x = 2 * a;  // 報告する。右辺だけが構造体の演算は使えない
```

**右辺だけが構造体の演算 (`2 * a`) は、演算子を定義しても使えません。**
構造体の中で定義した演算子 (`Rgb operator*(float k)`) は、その構造体が左辺の式 (`a * 2`) にだけ使われます。
構造体の外の演算子 (`Rgb operator*(float k, Rgb a)`) は定義できません。DXC 1.8 は定義そのものをエラーにし
(`overloading non-member 'operator*' is not allowed`)、DXC 1.6 は定義だけ通して式には使いません。このルールは定義を報告します。
`a * 2` の順に書いてください。

次の演算子は多重定義できません。定義そのものを報告します。

| 演算子 | |
| --- | --- |
| `++` / `--` | 増減 |
| `+=` / `-=` / `*=` などの複合代入、`=` | 代入 |
| `<<` / `>>` | シフト |
| `->` | |

規則は DXC (`-HV 2021`) で確かめました。

## なぜ問題か

コンパイルに失敗します (DXC は `scalar, vector, or matrix expected` など)。

## どう直すか

メンバーごとに計算するか、HLSL 2021 なら構造体の中で演算子を定義してください。
条件演算子で選んでいるなら、`if` 文で書いてください。

```hlsl
Light c;
c.color = a.color + b.color;
c.intensity = a.intensity + b.intensity;

Light d = b;
if (k > 0)
{
    d = a;
}
```

## 環境による違い

演算子の定義 (`operator+`) は HLSL 2021 だけで書けます。
Unity の環境 (HLSL 2018) では定義を [HL0003](HL0003.md) で報告し、構造体への演算子はこのルールで報告します。

構造体の増減 (`a++` / `--a`) は、DXC でコンパイルされるときだけ報告します。DXC はどの版でも拒みます。
FXC (Unity の既定のコンパイラ) はエラーにせず、その演算を何もしないコードとして扱います。FXC だけでコンパイルされるなら [HL0348](HL0348.md) で警告します。

Unity では、パスがどの API でどちらのコンパイラでコンパイルされるかで決め、DXC の API を文に添えます
(`#pragma use_dxc` を書いたパスの `dx12 (DXC (HLSL 2018))` など。[設定](../guide/configuration.md#シェーダーのコンパイラ))。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 型が構造体だと分かっていない値 (template の型引数 `T` の値など)
- 単項の `+` / `-` / `!` / `~` で、構造体にその演算子の定義がある場合。
  DXC 1.6 / 1.8 は定義があっても使えませんでしたが、Unity が使う DXC 1.10 では確かめていないので報告しません
