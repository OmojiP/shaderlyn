# GL0301: この型には演算子を使えません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、演算子を使えない型の組に使っている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

void main()
{
    vec2 uv = vec2(0.5);
    vec3 n = vec3(1.0);
    bool lit = true;
    mat4 m = mat4(1.0);

    color.xyz = n + uv;          // 成分の数が違うベクトルは足せない
    color.w = 1.0 + lit;         // bool は数に変換されない
    color = m * n;               // mat4 には 4 成分のベクトルを掛ける
    if (uv < uv) { }             // < はスカラーにだけ使える。ベクトルは lessThan(uv, uv)
}
```

glslang と同じく、次の順に決めます。

1. 両辺の要素の型を、暗黙の変換でそろえます (`int + float` は `float`)。そろえられなければ使えません。ES の 3.10 より前とデスクトップの 1.10 には暗黙の変換がありません
2. 演算子ごとに要素の型を確かめます。`+ - * /` は `bool` に使えず、`% & | ^ << >>` は整数にだけ、`&& || ^^` は `bool` のスカラーにだけ、`< > <= >=` は `bool` でないスカラーにだけ使えます
3. 形 (スカラー・ベクトル・行列) の組を確かめます。ベクトルどうしは成分の数が同じでなければならず、行列とベクトルの `*` は列と行の数が合わなければなりません。
   代入の演算子 (`+=` など) は、結果が左の型のままでなければなりません (`float += vec3` は使えません)
4. 16 ビットと 8 ビットの型の演算には、拡張 (`GL_EXT_shader_explicit_arithmetic_types` など) が要ります

ほかに、次のものも報告します。

- 配列そのもの (添字を付けない配列の変数) に、`==`・`!=`・`=` 以外の演算子を使うこと
- `?:` の 2 つの枝の型が、暗黙の変換でもそろわないこと (`b ? vec4(1.0) : mat4(1.0)` など)

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

型をそろえてください。成分を選ぶ (`n.xy + uv`)、値を作る (`float(lit)`、`vec4(n, 1.0)`)、ベクトルの比較には `lessThan` などの関数を使う、のどれかです。

## 誤検出だと思ったら

型が分からない式 (構成によって型が変わる式を含む) には報告しません。構造体と配列の演算子は CF0406、代入 (`=`) は CF0410 が見ます。
