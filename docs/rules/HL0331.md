# HL0331: 宣言したシンボルが未使用です

分類: Usage / 既定の重要度: 情報

## 何を検出するか

`#pragma shader_feature` / `#pragma multi_compile` / `#pragma dynamic_branch` で
宣言したシンボルが、一度も参照されていない箇所です。

参照は `#ifdef` などの条件だけでなく、コードの中の識別子としての出現も数えます。
`#pragma dynamic_branch` で宣言したシンボルはバリアントを作らず、
`if (_HDR_OVERLAY)` のように実行時の分岐として書かれるためです。
条件だけを数えると、これらをすべて未使用と誤って報告することになります。

```hlsl
#pragma shader_feature _NEVER_USED   // どこでも見ていない
```

## なぜ問題か

シンボルは 1 つ増えるごとにバリアントの数を倍にします。

10 個のシンボルは 1024 通りの組み合わせになり、
`multi_compile` ならそのすべてがビルドに含まれます。
使っていない宣言は、ビルド時間とメモリと配布サイズを
何の役にも立たないまま消費します。

`shader_feature` は使われている組み合わせだけが含まれるため影響は小さいですが、
それでも読み手には「この機能はどこかで使われているはず」と誤解させます。

## どう直すか

使っていないなら宣言を消してください。
実装の途中であれば、そのままにして構いません。

## 判定できる範囲

**報告するのは、このファイルに書かれた宣言だけです。**
取り込んだヘッダが宣言したシンボルを使っていなくても、
それはこのシェーダーの都合ではありません。

**使われているかどうかは、取り込んだヘッダの中の条件も見て判断します。**
シェーダーが宣言し、切り替わるコードはヘッダ側にある、という書き方は普通です。
そのヘッダの `#ifdef` がシンボルを見ていれば、使われていることになります。

`multi_compile _ _FOO` の `_` は「シンボル無しの構成」を表す書き方であり、
シンボルとしては数えません。

## 誤検出だと思ったら

シンボルを条件ではなく別の形で使っている場合、この指摘は当たりません。
重要度が情報にとどめてあるのは、そのためです。
