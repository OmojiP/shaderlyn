# SL0002: 一部の検査を行っていません

分類: Usage / 既定の重要度: 情報

## 何を検出するか

プロパティと uniform の対応検査を実行できなかったファイルです。

具体的には次のいずれかが起きています。どちらであるかはメッセージに表示されます。

- 展開後の HLSL に構文エラーやプリプロセッサエラーがあった
- `#include` を解決できなかった

`#include` を解決できないこと自体は、この指摘ではなくエラーになります。
1 件も引けないなら [TOOL0004](TOOL0004.md)、
ほかは引けているのに 1 つだけ引けないなら [HL0321](HL0321.md) が、
その原因を直接指します。
この指摘は「その結果として検査を見送った」ことを伝える側です。

構文エラーやプリプロセッサエラーが解析対象のファイル自身にある場合、
それは [HL0001](HL0001.md) / [HL0002](HL0002.md) として該当行でも報告されます。
この指摘の位置はファイルの先頭です。原因は特定の行ではなく、
そのファイルの解析状況そのものにあるためです。

include 先のヘッダの中にあった場合は、そちらは報告されません。
どのファイルのどこであったかは、この指摘のメッセージに含まれます。

### Unity 以外の環境

汎用の HLSL と Unreal の環境には `Properties` が無いので、文は
「宣言が無いことを根拠にする検査 (HL0301 / HL0310 など) を行っていません。」になります。
見送るのは、宣言が見つからないことを根拠にするルール (HL0301 / HL0310 / HL0315 など) です。

Unreal では、欠けているのがビルドのときにエンジンが生成するファイル (`/Engine/Generated/…`) だけなら、
この指摘ではなく [UE0001](UE0001.md) (C++ から作れるもの) か [UE0002](UE0002.md) (マテリアルごとに作られるもの) が出ます。
ほかの取り込みも解決できていなければ、この指摘が出ます。

## なぜ問題か

これは「検査していない」ことを伝えるための指摘です。

依存関係が解決できていない状態では、uniform の一覧に抜けがあります。
その状態で「対応する uniform が無い」と報告すれば、
正しく書かれたシェーダーを誤りとして指摘することになります。
そのため以下のルールは自ら検査を見送ります。

- SL1001 (プロパティに対応する宣言が無い)
- SL1002 (定数バッファの uniform が公開されていない)
- SL1004 (使われていないプロパティ)
- URP0001 / URP0002 (SRP Batcher 互換性)

なお SL1003 (型の不一致) は、依存関係が不完全でも実行されます。
「見つかった uniform の型が食い違っている」という判断は、
ほかに何が見つかっていないかとは無関係に成り立つためです。

## どう直すか

Unity 以外の環境では、取り込みの探索パス (`include-paths`) と、Unreal なら `unreal:` の `engine` / `virtual-paths` を確かめてください。
`--env` で解決先を表示できます。以下は Unity の場合です。

Unity プロジェクトのルートを指定してください。

```
shaderlyn Assets/Shaders --unity-project .
```

これで `Library/PackageCache` と `Packages` からパッケージのヘッダが解決され、
Unity Editor のインストール先も `ProjectSettings/ProjectVersion.txt` から推定されます。

CI で `Library/` をキャッシュしておらず、ランナーに Unity も入っていない場合、
パッケージのヘッダは 1 つも解決できません。
その状態はこの指摘ではなく [TOOL0004](TOOL0004.md) のエラーとして報告され、解析は失敗します。

プロジェクトの外に置いたヘッダを取り込んでいる場合は `--include-path` を足してください。
プロジェクトの中のヘッダは、`#include "Assets/ShaderLibrary/Common.hlsl"` のように
`Assets/` から始まる形で書けば `--unity-project` だけで解決できます。

```
shaderlyn Assets/Shaders --unity-project . --include-path ../SharedShaderLibrary
```

## 誤検出だと思ったら

一部のヘッダだけ引けない環境では、この指摘が多くのファイルに出続けます
(1 つも引けない環境で出るのは、この指摘ではなく TOOL0004 のエラーです)。
その場合はルールを無効化して構いませんが、
対応検査が働いていないことは変わりません。
無効化するのは、その状態を承知したうえでの判断としてください。
