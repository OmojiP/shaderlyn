# HL0002: プリプロセッサ指令の誤り

分類: Syntax / 既定の重要度: エラー

## 何を検出するか

プリプロセッサ指令が正しく書かれていない箇所です。

- `#if` に対応する `#endif` が無い
- 対応する `#if` の無い `#else` / `#elif` / `#endif`
- 1 つの `#if` に `#else` が 2 つある
- `#define` / `#undef` にマクロ名が無い
- 条件式が整数式として解釈できない
- マクロの引数の個数が定義と合わない
- 同じマクロを中身を変えて定義し直している

最後のものは、別々の条件で定義している場合も見ます。

```hlsl
#pragma multi_compile _ _A
#pragma multi_compile _ _B

#ifdef _A
#define TINT half4(1, 0, 0, 1)
#endif
#ifdef _B
#define TINT half4(0, 0, 1, 1)   // _A と _B が同時に有効なときは再定義になる
#endif
#ifndef TINT
#define TINT half4(1, 1, 1, 1)    // 上のどちらも無いときだけ通るので、再定義ではない
#endif
```

単一の構成を展開するだけでは、通るのはどれか 1 つなので気づけません。
解析しているファイルの `#define` は、読み飛ばす分岐のものも条件付きで覚えて突き合わせます。

## なぜ問題か

条件分岐の対応が取れていない場合、
以降のコードが丸ごと有効化されるか、丸ごと無効化されます。
影響範囲が非常に大きい割に、見た目では気づきにくい種類の誤りです。

## どう直すか

`#if` と `#endif` の対応を確認してください。
入れ子が深い場合は `#endif // 条件名` のようにコメントを添えると追いやすくなります。

## 誤検出だと思ったら

`defined` はマクロ展開の前後の両方で解決しています。
Unity の `#define UNITY_SHOULD_SAMPLE_SH (defined(LIGHTPROBE_SH) && ...)` のような、
マクロ本体に `defined` を含む書き方にも対応しています。
条件ごとの再定義は、解析しているファイルに書かれたものだけを見ます。
取り込んだヘッダは、取り込む順序で中身を差し替える書き方を多用しているため対象外です。
`#undef` した名前は、それ以降は覚えません。

それでも誤検出が出る場合は不具合として報告してください。
