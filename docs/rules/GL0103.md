# GL0103: layout の値が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、`layout(…)` の値が正しくない状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = -1) out vec4 color;   // 負の数は書けない

layout(std140, binding = 0) uniform Params {
    layout(align = 12) vec4 tint;        // align は 2 のべき乗でなければならない
};

void main() { color = tint; }
```

今は次のものを検査します (どれも glslang と同じ)。

- 負の数、整数でない値、定数でない式、宣言されていない名前
- 上限を越える値 (`location` は 4094 まで、`set` は 62 まで、`binding` は 65534 まで、`component` は 3 まで、フラグメントシェーダーの出力の `location` は 31 まで、`max_vertices` は 256 まで、ワークグループの大きさ (`local_size_x` など) は glslang の既定の上限まで)
- 2 のべき乗でない `align` と `buffer_reference_align`、0 か 1 でない `index`、0 の `vertices` と `invocations`
- リテラルでない値 (`const` の変数や式) を書けない所に書いたもの。特殊化の定数 (`layout(constant_id = …) const`) は、リテラルとして扱われません
- 同じ `constant_id` を 2 度使うこと
- 入力・出力・uniform の `location` (と `component`) の重なり。型が使う location の数 (配列、行列、構造体、dvec3 など) は glslang と同じに数えます。
  同じ location を分け合う入力と出力は、型と補間の修飾子が同じでなければなりません。デスクトップの OpenGL 向けの頂点シェーダーの入力は重ねてもかまいません (glslang と同じ)
- シェーダー全体で 1 つの値 (入力と出力のプリミティブ、`vertices`、`invocations`、`local_size_x` など) を、前の宣言と違う値にすること
- 型と合わない値 (整数のイメージに浮動小数点数の形式 `rgba8` を付けるなど、成分が 4 つを越える `component`、アトミックカウンターの大きすぎる `binding`)

値の式は、リテラル、関数の外の `const` の変数、演算子を畳んで求めます。求められない値 (組み込みの定数など) は検査しません。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

文が示す範囲の値にしてください。上限は glslang の既定の資源の上限 (`gl_MaxDrawBuffers` が 32 など) で検査します。
