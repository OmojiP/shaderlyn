# CF0303: メッシュシェーダーのエントリポイントに必要なものが欠けています

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

メッシュシェーダーのエントリポイントに、必要な属性か出力が欠けている状態です。

```hlsl
struct V { float4 pos : SV_Position; };

[numthreads(1, 1, 1)]                             // 報告する。[outputtopology] が存在しない
void main(out vertices V verts,                   // 報告する。配列でない
          out indices uint3 tris[])               // 報告する。配列の大きさを書いていない
{
    SetMeshOutputCounts(0, 0);
}
```

| 欠けているもの | エラーにするコンパイラ |
| --- | --- |
| `[outputtopology("point" / "line" / "triangle")]` の属性 | DXC・slangc |
| `out vertices` / `out indices` / `out primitives` が、大きさを書いた配列でない | DXC・slangc |
| 頂点の出力 (`out vertices` / `OutputVertices<V, N>`) か、インデックスの出力 (`out indices` / `OutputIndices<uint3, N>`) が存在しない | slangc |

## なぜ問題か

コンパイルエラーになります (DXC は `mesh entry point must have a valid outputtopology attribute` や
`vertices output is not an constant-length array`、slangc は `E38047`・`E38048`・`E54002`・`E54003`)。
DXC 1.8 と slangc 2026.19 で確認しました。

## 修正方法

属性を加え、出力を大きさを書いた配列にしてください。

```hlsl
[outputtopology("triangle")]
[numthreads(1, 1, 1)]
void main(out vertices V verts[3], out indices uint3 tris[1])
{
    SetMeshOutputCounts(3, 1);
}
```

## 環境による違い

エントリポイントのステージは、[CF0302](CF0302.md) と同じく決めます (`[shader("mesh")]`、設定ファイルの `units:` の `target` が `ms_6_5` など、
`[outputtopology]` と `out vertices` などを持つ関数)。
FXC はメッシュシェーダーをコンパイルできないので、FXC でコンパイルするファイルには報告しません。

## 誤検出だと思ったら

配列の大きさを名前で書いた場合 (`verts[MAX_VERTICES]`) は、大きさを書いたものとして扱います。
