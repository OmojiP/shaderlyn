# GL0315: 整数のリテラルが正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、整数のリテラルが 32 ビットに収まらないか、8 進数のリテラルに 8 と 9 を書いている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

void main()
{
    int big = 5000000000;      // 32 ビット (4294967295) に収まらない
    int hex = 0x1FFFFFFFF;     // 16 進数でも同じ
    int oct = 08;              // 0 で始まるリテラルは 8 進数。8 と 9 は書けない
    color = vec4(float(big + hex + oct));
}
```

接尾辞の無い整数と `u` の付いた整数のリテラルを見ます (どれも glslang と同じ)。

- 10 進数・16 進数・8 進数のどれでも、値は 0xFFFFFFFF までです。`int` のリテラルの 0x80000000 から 0xFFFFFFFF は、負の数として読みます (誤りではありません)
- `0` で始まる整数のリテラル (`0` だけを除く) は 8 進数で、`8` と `9` は書けません

64 ビット (`l`、`ul`) と 16 ビット (`s`、`us`) の接尾辞のリテラルは見ません。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。
`08` は 10 進数の 8 のつもりで書かれることが多い書き誤りです。

## どう直すか

32 ビットに収まる値にするか、64 ビットの整数 (`GL_EXT_shader_explicit_arithmetic_types_int64` と `l` の接尾辞) を使ってください。
10 進数の数は、頭に `0` を付けずに書いてください。
