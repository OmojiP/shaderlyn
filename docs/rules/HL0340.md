# HL0340: 実引数を仮引数の型へ変換できません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

渡している値の成分が、仮引数の型より少ない呼び出しです。

```hlsl
#pragma multi_compile _ SHADER_DEBUG

#ifdef SHADER_DEBUG
half4 sampleTexture(float2 uv)  { ... }
#else
half4 sampleTexture(float3 uvw) { ... }
#endif

half4 frag(Varyings IN) : SV_Target
{
#ifdef SHADER_DEBUG
    return sampleTexture(IN.uv);   // float2 → float2。問題ない
#else
    return sampleTexture(IN.uv);   // float2 → float3。成分が足りない
#endif
}
```

候補はその構成に存在する宣言だけに絞ります。
条件を見ないと、`#else` の呼び出しに `float2` 版が候補として混ざり、
合わない呼び出しが合っているように見えます。

## なぜ問題か

HLSL は変換の向きで扱いが違います。

| 向き           | 例                  | 扱い              |
| -------------- | ------------------- | ----------------- |
| 成分を減らす   | `float3` → `float2` | 通る (警告 X3206) |
| スカラーを複製 | `float` → `float3`  | 通る              |
| 成分を増やす   | `float2` → `float3` | エラー            |

このルールが報告するのは最後の 1 行だけです。
上の 2 つは正しいコードなので、報告しません。

### `out` / `inout` では規則が違う

書き戻す仮引数では、成分を減らす向きも許されません。
書き戻す先が足りないためです。形が一致していなければなりません。

```hlsl
void split(float2 uv, out float3 rgb) { ... }

float2 small;
split(uv, small);   // float3 を float2 へは書き戻せない
```

### 行列とベクトルは互いに渡せない

```hlsl
half4 shade(float3x3 m) { ... }

float3 v;
shade(v);   // ベクトルを行列へは渡せない
```

スカラーはどちらへも複製されるので、これは許されます。

## どう直すか

足りない成分を明示してください。

```hlsl
return sampleTexture(float3(IN.uv, 0));
```

条件によって仮引数の型が変わる関数なら、
呼ぶ側にも同じ条件を付けるか、型を揃えてください。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 宣言が 1 つも見えていない関数。
  組み込み関数の形は持っていないので、表に無い名前は対象外です
- 受け付ける宣言が 1 つでもある場合。
  その構成に存在する候補のどれか 1 つが受け付ければ、その呼び出しは成り立ちます
- 実引数の型が分からない場合。
  型が分からないことは「合っていない」ことの証拠になりません
- 配列。要素の型と長さは [HL0344](HL0344.md) が見ます
- 成分の数が分からない型。構造体やテクスチャは対象外です

引数の個数が合わない呼び出しは [HL0341](HL0341.md) が報告します。
