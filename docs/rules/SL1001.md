# SL1001: プロパティに対応する HLSL の宣言がありません

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`Properties` に宣言されているのに、埋め込み HLSL のコードのどこにも
その名前が現れないプロパティです。

## なぜ問題か

マテリアルのインスペクタには表示され、値も保存されますが、描画には一切影響しません。

Unity はこれをエラーにも警告にもしません。
シェーダーは正常にコンパイルされ、マテリアルの UI にはスライダーやカラーピッカーが並び、
値を変えても何も起きない、という状態になります。

実際に多いのは次の 2 つです。

- プロパティ名のスペルミス (`_BaseColor` と `_BaseColour`)
- 機能を削除したときに `Properties` の側だけ消し忘れた

前者は「なぜか効かない」と悩む時間を生み、後者はマテリアルの UI を汚したまま残ります。

## どう直すか

```shaderlab
Properties {
    _BaseColor ("Base Color", Color) = (1,1,1,1)
}
SubShader {
    Pass {
        HLSLPROGRAM
        CBUFFER_START(UnityPerMaterial)
            half4 _BaseColor;   // 宣言を追加する
        CBUFFER_END
        ENDHLSL
    }
}
```

使わなくなったプロパティであれば `Properties` から削除してください。

## 誤検出だと思ったら

このルールは、判断できない可能性をすべて潰してから報告します。
次の場合は報告しません。

- 依存関係が解決できていない場合 (SL0002 が代わりに報告されます)
- `[HideInInspector]` が付いている場合
  (人が設定するものではないので「設定しても効果が無い」という指摘が当てはまりません)
- ShaderLab のレンダーステートから参照している場合 (`Cull [_Cull]` など)
- どの構成でも解析しない `#if` の領域 (`SHADER_API_*` など環境の条件の中や、取り込んだヘッダの非活性領域)や、呼び出されなかったマクロ定義の中にその名前が現れる場合
  (別の構成では宣言・使用されている可能性があるため断定できません)
- 宣言として認識できなくても、展開後のコードのどこかにその名前が現れる場合

したがって報告が出た場合、その名前は HLSL のコードに一度も出てきていません。

### 意図的にそう書いている場合

報告が正しくても、意図した設計であることがあります。

カスタム `ShaderGUI` が読むプロパティが代表例です。
マテリアルエディタが値を読んでシェーダーのシンボルを切り替える用途では、
シェーダー自身はその値を読みません。

```shaderlab
// URP の Lit.shader より
_WorkflowMode("WorkflowMode", Float) = 1.0    // ShaderGUI が読んでシンボルを決める
_Blend("__blend", Float) = 0.0
[ToggleUI] _AlphaClip("__clip", Float) = 0.0
```

C# のスクリプトが `material.GetFloat("_Foo")` でマテリアルを設定値の入れ物として
使っている場合も同様です。

この書き方をプロジェクト全体で使っているなら、
設定ファイルで重要度を下げるか、ベースラインで既存分を凍結してください。

> 実測: Unity 6000.3 同梱のシェーダー 209 件に対して 360 件の指摘が出ますが、
> その大半は URP / HDRP の基盤シェーダー約 20 件に集中しています。
> いずれも「HLSL に現れない」という判定自体は正しく、
> 上記の ShaderGUI 主導のプロパティにあたります。
