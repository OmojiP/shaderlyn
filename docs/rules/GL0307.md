# GL0307: 添字が範囲の外です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、定数の添字が範囲の外にある状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

void main()
{
    float weights[4] = float[](0.1, 0.2, 0.3, 0.4);
    vec3 normal = vec3(0.0, 1.0, 0.0);
    mat2x4 m = mat2x4(1.0);

    color = vec4(weights[4]);   // 大きさ 4 の配列の添字は 0 から 3
    color.x = normal[-1];       // 添字は 0 以上
    color = m[2];               // mat2x4 の列は 2 つ
}
```

範囲は次のとおりです (どれも glslang と同じ)。

- どれも、添字は 0 以上
- 配列: 大きさより小さい
- ベクトル: 成分の数より小さい
- 行列: 列の数より小さい (`mat2x4` は列が 2 つ)

添字は、リテラルと `const` の変数を使う式を畳んで求めます。特殊化の定数 (`layout(constant_id = …)`) を使う添字は、glslang と同じく検査しません。
配列の大きさを、整数のリテラルを初期値にした関数の外の `const` の変数の名前で書いたもの (`float a[N];`) も見ます。特殊化の定数の名前で書いた大きさは、glslang と同じく既定の値の大きさとします。
組み込みの整数の定数 (`gl_MaxSamples` など) は、glslang の既定の資源の値 (`glslang -c` が出す値) として畳みます。

大きすぎる添字は、宣言した変数 (とそれを添字で引いた `a[1][2]`、`m[1][3]`) で、配列の大きさが数で書かれているときだけ検査します。
構造体とブロックのメンバーと、大きさを書かない配列は検査しません。
ただし外側の大きさを省いて初期化した配列 (`const int a[] = int[](3, 2);`) は、初期化子の大きさで検査します。

組み込みの変数は、大きさの決まった配列だけを検査します。大きさは glslang の既定の資源の値です。

| 変数 | 大きさ |
| --- | --- |
| `gl_FragData` | 32 (`gl_MaxDrawBuffers`) |
| `gl_BoundingBox`・`gl_BoundingBoxEXT`・`gl_BoundingBoxOES` | 2 |
| `gl_SampleMask`・`gl_SampleMaskIn` | 1 (`gl_MaxSamples` の 4 から) |
| テッセレーションの制御シェーダーの `gl_out` | `layout(vertices = …) out;` の値 |

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。範囲の外を読み書きする意図は無いはずなので、多くは書き誤りです。

## どう直すか

範囲の中の添字にするか、配列を大きくしてください。
