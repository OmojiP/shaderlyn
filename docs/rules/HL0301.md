# HL0301: エントリポイントが見つかりません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

`#pragma vertex` や `#pragma fragment` に書かれた名前の関数が、
そのコードブロックから見える範囲に定義されていない状態です。

```hlsl
#pragma vertex vert
#pragma fragment fragmnet   // スペルミス

float4 vert(float4 p : POSITION) : SV_POSITION { return p; }
half4 frag() : SV_Target { return 0; }
```

対象にする `#pragma` は次のとおりです。
いずれも第 1 引数が関数名になります。

`vertex` / `fragment` / `geometry` / `hull` / `domain` / `surface` / `kernel`

## なぜ問題か

この Pass はコンパイルできず、シェーダー全体が使えなくなります。

Unity はシェーダーを必要になった時点でコンパイルするため、
該当のマテリアルを画面に出すまで気づけないことがあります。
ビルドは通り、エディタ上も正常に見え、
実行時にマゼンタのオブジェクトが現れて初めて分かる、という形になります。

原因のほとんどは次の 2 つです。

- 関数名のスペルミス
- 関数を定義している共通コード片 (`HLSLINCLUDE`) の取り込み漏れ

## どう直すか

関数名を合わせるか、関数を定義しているヘッダを `#include` してください。

共通コード片は、同じブロックの中にある Pass にしか差し込まれません。
別の `SubShader` に書いた `HLSLINCLUDE` は届きません。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 依存関係を解決できていない場合 (SL0002 が代わりに報告されます)。
  取り込めなかったヘッダに定義されている可能性がある以上、
  「見つからない」ことを根拠にはできません
- どの構成でも解析しない `#if` の領域 (`SHADER_API_*` など環境の条件の中や、取り込んだヘッダの非活性領域)に定義がある場合。
  単一構成での展開では、別の構成でのみ定義される関数が見えません

プロトタイプ宣言だけがある場合も「ある」とみなします。
定義がどこにあるかはリンクの問題であり、このルールが見る話ではありません。

## 一部の構成でだけ無い場合も報告する

```hlsl
#pragma fragment frag
#ifdef _B
half4 frag() : SV_Target { return 1; }
#endif
```

`!_B` の構成では入口の関数がありません。その構成を添えて報告します
(`#pragma fragment が指定する関数 'frag' が見つかりません。 (!_B のとき)`)。
どの構成の木も解析していない組み合わせについては何も言いません。
