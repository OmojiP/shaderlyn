# TOOL0006: メッセージの引数の数が合っていません

分類: Tool / 既定の重要度: 警告

## 何を検出するか

`DiagnosticDescriptor` のメッセージ書式が必要とする引数より、
`ReportDiagnostic` へ渡された引数が少ない状態です。

```
Assets/Shaders/Lit.shader(12:9): warning TOOL0006: ルール 'MY0001' のメッセージは
    引数を 2 個必要としますが、1 個渡されました。
```

シェーダーの誤りではなく、アナライザの実装の誤りです。

## なぜ問題か

引数が足りないと `string.Format` は失敗します。
そのとき利用者の画面に出るのは、穴が空いたままの書式です。

```
warning MY0001: 'positionOS' と '{1}' が食い違っています。
```

これは出力として成立してしまいます。
例外にもならず、赤くもならないので、テストが無ければ誰も気づきません。
気づかないまま、意味の通らないメッセージが利用者に届き続けます。

Roslyn も同じ壊れ方をします。ここでは必ず表に出します。

## 引数が多い分には報告しません

書式は埋まるので、害がありません。
余った引数は無視されます。

## どう直すか

書式の穴の数と、渡す引数の数を合わせてください。

```csharp
// 穴が 2 つある
messageFormat: "'{0}' と '{1}' が食い違っています。"

// 2 つ渡す
c.ReportDiagnostic(Rule, left.Name, right.Name);
```

穴の番号は飛んでいてもかまいませんが、
`{2}` だけを使う書式は引数を 3 個必要とします (`string.Format` と同じ規則)。

文字としての波括弧を書きたい場合は `{{` と `}}` にしてください。これは穴として数えません。
