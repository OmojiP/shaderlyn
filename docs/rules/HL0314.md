# HL0314: シンボル宣言の重複

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

同じ範囲に同じ名前の宣言が 2 つある状態です (FXC の X3003)。

```hlsl
float4 _Tint;
float4 _Tint;          // 二重宣言

struct Point { float x; };
struct Point { float y; };   // 二重宣言

float f(float a) { return a; }
float f(float b) { return b; }   // 同じ形の実装が 2 つ
```

## 条件で分けた宣言は誤りではない

`#ifdef` の両方の分岐に同じ名前を書くのは普通の書き方です。
この解析ツールは両方の分岐を 1 本の構文木に載せますが、
2 つの出現条件を掛け合わせて、同時に成り立つ構成があるときだけ報告します。

```hlsl
#ifdef _NORMALMAP
    float4 _Color;     // _NORMALMAP
#else
    float4 _Color;     // !_NORMALMAP    → 同時には成り立たない。報告しない
#endif

float4 _Other;         // 常に
#ifdef _NORMALMAP
    float4 _Other;     // _NORMALMAP     → 有効な構成では 2 つある。報告する
#endif
```

両方の条件を満たす構成を、シンボルを有効にして別に展開している場合は、その構成で決めます。
並べられない `#ifdef` の中の入れ子では、条件が「外側のシンボルが有効」までしか分からないことがあります。
そのときも、展開した構成に両方が現れなければ報告しません。

```hlsl
#ifdef _A              // 中でマクロを定義するので並べられない
#define USE_A 1
    #ifdef _B
        Texture2DArray _Src;   // _A と _B を同時に有効にした構成で見つかる
    #else
        Texture2D _Src;        // _A の構成で見つかる。_A と _B の構成には無い → 報告しない
    #endif
#endif
```

## 関数の中は、波括弧 1 つ分だけを見ます

同じ波括弧の直下に並ぶ宣言どうしだけを突き合わせます。

```hlsl
float ReturnFloat()
{
    #pragma multi_compile _A _B
    #pragma multi_compile _C _D

    #if defined(_A)
    float a = 1.0;
    #elif defined(_B)
    float3 a = float3(1.0, 2.0, 3.0);
    #endif

    #if defined(_C)
    a = 2;
    #elif defined(_D)
    float4 a = float4(1, 1, 1, 1);   // ← ここを報告する
    #endif
    return a.x;
}
```

`_A` と `_D` は別の `#pragma` の行なので同時に有効になります。
その構成では `a` が同じ波括弧の直下に 2 つあります。

内側の波括弧で同じ名前を宣言するのは覆い隠し (shadowing) であり、誤りではありません。
名前の範囲を外側へたどることはしないので、覆い隠しを二重宣言と取り違えることはありません。

```hlsl
float a = 1;
{
    float a = 2;    // 内側の波括弧。報告しない
}

if (x > 0) { float b = 1; }
else       { float b = 2; }   // 兄弟の波括弧。報告しない
```

`switch` の本体も 1 つの範囲です。別の `case` に同じ名前を宣言すると二重宣言になります (FXC の X3003)。
`case` ごとに波括弧で囲めば別の範囲になります。

```hlsl
switch (k)
{
case 0: float a = 1; break;
case 1: float a = 2; break;   // 同じ switch の本体。報告する
}
```

仮引数は、関数のいちばん外の波括弧と同じ範囲にあります (FXC の X3036)。

```hlsl
float f(float a)
{
    float a = 1;     // 仮引数と同じ範囲。報告する
    { float a = 2; } // 内側の波括弧。報告しない
    return a;
}
```

波括弧を書かない `if (x) float a;` は、それ自体が 1 つの範囲になるため集めません。

`for` の初期化の変数は、囲む波括弧の宣言として数えます。Unity (fxc) では囲む波括弧へ漏れるためです。

```hlsl
for (int i = 0; i < 2; i++) { }
float i = 1;                      // ループの i と同じ範囲。報告する (FXC の X3003)
```

初期化の変数のほうが後なら報告しません。前の宣言より優先されるだけで、FXC も警告 (X3078) に留めます。

```hlsl
float i = 1;
for (int i = 0; i < 2; i++) { }   // 報告しない
for (int i = 0; i < 3; i++) { }   // 報告しない
```

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 仮引数の型が違う関数。HLSL は多重定義を許します
- 実装を持たない宣言 (プロトタイプ)。先に宣言だけを書く形は正しい書き方です
- 別の `Pass` にある同じ名前。`Pass` ごとに別のコードとして組み立てられます
- 別の波括弧で宣言された名前 (前の節)
- Unity や外部パッケージのヘッダの中の宣言。このファイルと、利用者が書いて取り込んだヘッダの宣言だけを見ます
- 出現条件を追えなかった宣言。同時に存在するかを言えないので報告しません
