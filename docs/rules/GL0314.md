# GL0314: メモリのセマンティクスの組み合わせが正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、スコープとセマンティクスを取るアトミックとバリアの関数 (`GL_KHR_memory_scope_semantics`) に、
決まりに合わないセマンティクスを渡している状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
#extension GL_KHR_memory_scope_semantics : require
layout(local_size_x = 64) in;
layout(binding = 0) buffer B { uint x; } b;

void main()
{
    // ストアに gl_SemanticsAcquire は使えない
    atomicStore(b.x, 1u, gl_ScopeDevice, gl_StorageSemanticsBuffer, gl_SemanticsAcquire);
    // 記憶域のセマンティクスを書いたら、gl_SemanticsAcquire・Release・AcquireRelease のどれかが要る
    atomicAdd(b.x, 1u, gl_ScopeDevice, gl_StorageSemanticsBuffer, gl_SemanticsRelaxed);
}
```

対象の関数は `atomicAdd` などのアトミックの関数・`atomicLoad`・`atomicStore`・`atomicCompSwap`、イメージのアトミックの関数、
`controlBarrier`・`controlBarrierArrive`・`controlBarrierWait`・`memoryBarrier` の、スコープとセマンティクスを取る形です。次のものを報告します (どれも glslang と同じ)。

- セマンティクスと記憶域のセマンティクスに、定数に無い値が入っている
- `gl_SemanticsAcquire`・`gl_SemanticsRelease`・`gl_SemanticsAcquireRelease` を 2 つ以上入れている
- それらを使うのに記憶域のセマンティクスが 0、または記憶域のセマンティクスが 0 でないのにそれらが無い
- `gl_SemanticsMakeAvailable` に Release か AcquireRelease が無い、`gl_SemanticsMakeVisible` に Acquire か AcquireRelease が無い
- ストアの Acquire、ロードの Release、ロードとストアの AcquireRelease
- `memoryBarrier` に Acquire・Release・AcquireRelease が無い、バリアの `gl_SemanticsVolatile`
- `controlBarrierArrive` が Release (と MakeAvailable) でない、`controlBarrierWait` が Acquire (と MakeVisible) でない
- `atomicCompSwap` の等しくないときのセマンティクス (semUnequal) と記憶域のセマンティクス (semStorageUnequal) の決まり

スコープとセマンティクスの実引数が定数でないものは、[GL0303](GL0303.md) が報告します。値の分からない実引数があれば検査しません。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。
SPIR-V の決まりで、メモリの順序の指定は記憶域の指定と組で意味を持つためです。

## どう直すか

記憶域のセマンティクスとセマンティクスを組で書いてください。順序が要らないなら、両方を 0 (`gl_StorageSemanticsNone`、`gl_SemanticsRelaxed`) にします。

```glsl
atomicStore(b.x, 1u, gl_ScopeDevice, gl_StorageSemanticsBuffer, gl_SemanticsRelease);
atomicAdd(b.x, 1u, gl_ScopeDevice, gl_StorageSemanticsNone, gl_SemanticsRelaxed);
```
