# SL0004: 条件を追えなかった箇所があります

分類: Usage / 既定の重要度: 情報

## 何を検出するか

同じ場所が構成によって**別の種類の文**になるため、
その箇所の出現条件が分からなかった状態です。

```hlsl
#ifdef SHADER_DEBUG
#define BODY { v = 1; }
#else
#define BODY v = 2;
#endif

if (v > 0)
    BODY
```

`if` の本体が、一方ではブロック、もう一方では式文になります。
構成ごとに組み立てた構文木を突き合わせるとき、
この位置には対応を取れる相手がいません。

## 何は検出しないか

**`#if` が構文の単位をまたいでいること自体は、この規則の対象ではありません。**

```hlsl
#ifdef SHADER_DEBUG
half4 frag(Varyings IN) : SV_Target
{
    return IN.debugColor;
#else
half4 frag(Varyings IN) : SV_Target
{
    return 0;
#endif
}
```

この形は 1 本のトークン列には並べられませんが、
構成ごとに組み立てて突き合わせる経路へ回り、そこで対応が取れます。
どちらの分岐の中も検査されます。

**同じ文の中身が構成によって入れ替わるだけの形も、対象ではありません。**

```hlsl
#ifndef USE_SECOND_CLOUD_LAYER
    #define LAYER       0
#else
    #define LAYER       dispatchThreadId.z
#endif

uv.x -= _Rotation(LAYER);
```

`LAYER` はリテラルにもメンバー参照にもなりますが、
この文は構成ごとの形を**両方とも残して**あります（下記）。

## なぜ追えないのか

この解析器は、構成ごとに構文木を組み立ててから突き合わせます。
対応付けの鍵は「ノードの種類」と「元のソースでの位置」です。

同じ位置に違う種類のノードが立ったときは、対応を取る代わりに、
**両方をその構成でだけ立つ選択肢として残します**。
既定の構成の側にはシンボルの否定を、バリアントの側にはシンボルを付け、
ルールは両方を歩いてそれぞれの条件で判断します。
SuperC (Gazzillo &amp; Grimm, PLDI 2012) が条件付きの選択肢 (static choice) を
構文木に残すのと同じ考え方です。
SuperC は構文解析そのものを条件で分岐させ（fork）、同じ状態へ戻ったところで併合します（merge）。
この解析器は、構文解析には手を入れず、文・宣言の単位で同じことを行います。

残るのは、**分ける単位が見つからない**場合です。
分けてよいのは文と宣言で、しかもその単位自身のトークンが構成で変わっているときだけです。
上の `if` の例では、変わっているのは本体の文の種類で、
`if` 文自身のトークン (`if ( v > 0 )`) は構成によらず同じです。
`if` 文ごと分けてしまうと、どの構成にもあるコードまで条件付きになってしまうため、そうはしません。

## なぜ問題か

この箇所では、条件を根拠にするルールが何も報告しません。

[HL0311](HL0311.md) / [HL0313](HL0313.md) / [HL0340](HL0340.md) は、
「使う条件」と「ある条件」を突き合わせて判断します。
条件が分からない箇所では、どちらも成り立たないため何も言えません。

報告しないのは正しい振る舞いです。
分からないものを根拠に指摘を出せば、正しいコードを誤りとして指摘することになります。

しかし、報告を見送ったことを、伝えないままにしてはいけません。
利用者から見ると「問題が無かった」のと区別が付きません。

## どう直すか

やり方は 2 つあります。どちらでも条件が追えるようになります。

**1. 分岐を文の側へ移す。** マクロではなく、使う場所を条件で分けます。

```hlsl
if (v > 0)
{
#ifdef SHADER_DEBUG
    v = 1;
#else
    v = 2;
#endif
}
```

**2. 定義の種類をそろえる。** 中身が変わっても、文の種類が同じなら対応が取れます。

```hlsl
#ifdef SHADER_DEBUG
#define BODY v = 1;
#else
#define BODY v = 2;
#endif
```

## どれくらい起きるか

Unity 同梱のシェーダー 401 件（Unity 6000.0.60f1）では 0 件でした。
`BakeCloudTexture.compute` と `OpaqueAtmosphericScattering.shader` の 2 件は、
選択肢として残すようにしたことで報告されなくなっています。
