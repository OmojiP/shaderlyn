# GL0303: この実引数は定数でなければなりません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、組み込み関数の、定数でなければならない実引数に、変数や仮引数を使う式を渡している状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;
layout(binding = 0) uniform sampler2D tex;
layout(location = 0) in vec2 uv;
layout(location = 1) flat in ivec2 shift;

void main()
{
    color = textureOffset(tex, uv, shift);   // テクセルのオフセットは定数でなければならない
}
```

今は次の実引数を検査します (どれも glslang と同じ)。

- テクセルのオフセット (`textureOffset`、`texelFetchOffset`、`textureLodOffset`、`textureGradOffset` などの `offset`)。
  拡張 `GL_EXT_texture_offset_non_const` か `GL_NV_gpu_shader5` を有効にしていれば、定数でなくてかまいません
- `textureGather` / `textureGatherOffset` / `textureGatherOffsets` の成分の番号 (`comp`) と、`textureGatherOffsets` のオフセットの配列
- サブグループのクラスターの大きさ (`subgroupClusteredAdd` などの `clusterSize`)
- SPIR-V 1.5 より前に向けたときの `subgroupBroadcast` / `subgroupQuadBroadcast` の `id`
- `rayQueryGetIntersection*EXT` の `committed`

`const` でない変数・仮引数を使っていると言い切れる式だけを報告します。分からない式 (ユーザーの関数の呼び出しなど) は報告しません。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

リテラルか `const` の変数にしてください (`textureOffset(tex, uv, ivec2(1, 0))`)。値を実行時に変えたいなら、オフセットを座標に足してください。
