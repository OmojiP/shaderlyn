# GL0001: このバージョンと拡張では使えません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、`#version` で決まる言語のバージョンとプロファイル、`#extension` で有効にした拡張、
作る SPIR-V のバージョンでは使えない機能を使っている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
#extension GL_KHR_shader_subgroup_basic : enable

layout(local_size_x = 64) in;
layout(binding = 0) buffer Data { float values[]; };

void main()
{
    // subgroupAdd は GL_KHR_shader_subgroup_arithmetic の関数。basic だけでは使えない
    values[gl_LocalInvocationIndex] = subgroupAdd(values[gl_LocalInvocationIndex]);
}
```

今は次のものを検査します。

- 拡張で足される組み込みの関数と変数 (`subgroupAdd`、`gl_SubgroupSize` など)。どの組み込みにどの拡張が要るかは、glslang 16.6.0 の組み込みの表に従います。
  ES のジオメトリとテッセレーションのシェーダーの `gl_PointSize` (`gl_in[i].gl_PointSize` を含む) には `GL_EXT_geometry_point_size` / `GL_EXT_tessellation_point_size` が要ります
- `samplerExternalOES` (ES の 3.00 より前は `GL_OES_EGL_image_external`、それ以降は `GL_OES_EGL_image_external_essl3`)
- OpenGL 向けの `texture2D(…)` などの組み込み関数を、それが無い版とプロファイル (ES の 3.00 以降など) で呼ぶこと。
  Vulkan 向けでは `texture2D` は型の名前なので、[`glsl: target`](../guide/configuration.md#glsl) が OpenGL のときだけ検査します
- サブグループの関数に 8・16・64 ビットの値を渡すこと (`GL_EXT_shader_subgroup_extended_types_*` が要ります)
- 実引数の型で要る拡張が変わる組み込み関数。float のアトミック (`atomicAdd` に `float` を渡すと `GL_EXT_shader_atomic_float`)、
  64 ビットの整数のアトミック、メモリのスコープを取るアトミック (`GL_KHR_memory_scope_semantics`)、整数と `bool` の `mix`、
  サンプラーを伴わないテクスチャの `textureSize` / `texelFetch` (`GL_EXT_samplerless_texture_functions`)、影のサンプラーの配列とキューブの `texture` / `textureLod` (`GL_EXT_texture_shadow_lod`)、
  `textureGather` / `textureGatherOffset` / `textureGatherOffsets` (デスクトップの 4.00・ES の 3.10 か `GL_ARB_texture_gather` / `GL_ARB_gpu_shader5` から。サンプラーと実引数の数で変わる)、
  `textureSamples` / `imageSamples` (4.50 か `GL_ARB_shader_texture_image_samples` から)
- サブグループの関数を SPIR-V 1.3 より前に向けて使うこと ([`glsl: target`](../guide/configuration.md#glsl) か `glsl: spirv` で SPIR-V のバージョンが分かるときだけ)
- 型 (`double`、`uint`、`int16_t`、`f16vec3`、`coopmat` など) と修飾子 (`flat`、`centroid`、`precise`、`devicecoherent` など) を、使えるバージョンより前か、拡張を有効にせずに使うこと
- 16 ビット・8 ビットの型 (`float16_t`、`i16vec2`、`uint8_t` など) を、保存用の拡張 (`GL_EXT_shader_16bit_storage` など) だけで、
  uniform と buffer のブロックの外 (変数・仮引数・組み込み関数の実引数と戻り値・`[`・成分の選び出し・値の作成・構造体と配列の代入と `return`) で使うこと。
  算術の拡張 (`GL_EXT_shader_explicit_arithmetic_types` など) が要ります
- ステージの入力と出力の変数の宣言。`in` / `out` (デスクトップの 1.30・ES の 3.00 から)、整数と `double` の入力と出力 (デスクトップの 1.30・ES の 3.00 から)、
  頂点シェーダーの入力の配列 (デスクトップの 1.50 から。ES は不可)、頂点シェーダーの `double` の入力 (4.10 か `GL_ARB_vertex_attrib_64bit` から)、
  フラグメントシェーダーの構造体の入力と頂点シェーダーの構造体の出力 (デスクトップの 1.50・ES の 3.00 から。ES では構造体と配列を含むものは不可)、
  ES の入力と出力の配列の配列と構造体の配列
- 定数でない添字で引く配列。サンプラーとイメージの配列 (デスクトップの 4.00・ES の 3.20 か `GL_ARB_gpu_shader5` / `GL_EXT_gpu_shader5` から)、
  uniform のブロックの配列 (コアプロファイルの 4.00・ES の 3.20 から)、buffer のブロックの配列と、フラグメントシェーダーの出力の配列 (ES は不可)
- 整数の演算子 (`%`、`<<`、`&` など) と `uint` のリテラル (`1u`) を、デスクトップの 1.30・ES の 3.00 より前に使うこと
- 配列の比較と代入を、デスクトップの 1.20・ES の 3.00 より前に使うこと
- 配列の配列 (`float a[2][3]`) を、デスクトップの 4.30・ES の 3.10 より前に使うこと
- 行の継続 (行末の `\`) を、デスクトップの 4.20 (か `GL_ARB_shading_language_420pack`)・ES の 3.00 より前に使うこと
- 接尾辞の付いたリテラル (`1.0lf`、`1l`、`1s`、`1.0hf`) に要るバージョンと拡張
- そのプロファイルで取り除かれたもの (コアプロファイルの 4.20 以降と ES の 3.00 以降の `attribute` / `varying`)

`#extension` は、書いた位置より後ろのコードにだけ効きます。使う位置より前に書いてください。
1 つの拡張を有効にすると、一緒に有効になる拡張があります (`GL_KHR_shader_subgroup_arithmetic` は `GL_KHR_shader_subgroup_basic` も)。glslang と同じに扱います。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。
ドライバーの GLSL コンパイラ (OpenGL) は拡張を書かなくても通すことがありますが、別のドライバーでは通りません。

## どう直すか

文に書いた拡張を、使う位置より前で有効にしてください。

```glsl
#extension GL_KHR_shader_subgroup_arithmetic : enable
```

SPIR-V のバージョンが足りないときは、コンパイルする Vulkan のバージョン (glslang の `--target-env`) を上げ、
設定ファイルの `glsl: target` も合わせてください。

## 誤検出だと思ったら

設定ファイルの [`glsl: target`](../guide/configuration.md#glsl) が、実際にコンパイルする向け (Vulkan か OpenGL、Vulkan のバージョン) と合っているか確かめてください。
組み込みの関数と変数は、向けによって要る拡張が変わります。

利用者が同じ名前の関数を宣言していれば、組み込みとは見なしません。
組み込みの変数を宣言し直していれば (`GL_EXT_spirv_intrinsics` で宣言した `gl_BaryCoordSmoothAMD` など)、その宣言を使います。

取り込まれる断片 (`.glsl`) は、バージョンが取り込む側で決まるので検査しません。
