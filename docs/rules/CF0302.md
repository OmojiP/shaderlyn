# CF0302: システム値のセマンティクスをそのステージで使用できません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

`SV_` で始まるセマンティクス (システム値) を、そのステージで使用できない向き (入力か出力か) に付けている箇所です。
エントリポイントの仮引数・戻り値と、そこで受け渡す構造体のフィールド (入れ子の構造体と基底の構造体を含む) を検査します。

```hlsl
#pragma vertex vert
#pragma fragment frag

struct v2f
{
    float4 pos : SV_POSITION;
    float depth : SV_Depth;     // 報告する。SV_Depth はピクセルシェーダーの出力にだけ使用できる
};

v2f vert(float4 p : POSITION) { ... }
```

```slang
[shader("compute")]
[numthreads(1, 1, 1)]
void main(out uint3 id : SV_DispatchThreadID)   // 報告する。SV_DispatchThreadID は入力にだけ使用できる
{
    id = 0;
}
```

ジオメトリ・ハル・ドメイン・メッシュシェーダーは、値の受け渡しの形ごとに検査します。

| ステージ | 受け渡しの形 |
| --- | --- |
| ジオメトリシェーダー | 仮引数、頂点の配列 (`point S input[1]`) のフィールド、ストリーム (`inout PointStream<S>`) のフィールド |
| ハルシェーダー | 仮引数、`InputPatch` のフィールド、戻り値 (制御点) のフィールド、`[patchconstantfunc]` で指定した関数の戻り値のフィールド |
| ドメインシェーダー | 仮引数、`OutputPatch` のフィールド、パッチ定数の構造体のフィールド |
| メッシュシェーダー | 仮引数、`out vertices` / `out primitives` / `out indices` のフィールド |

メッシュシェーダーでプリミティブごとの値 (`SV_PrimitiveID`・`SV_CullPrimitive` など) を `out vertices` や `out indices` の構造体に置いた場合は、
`out primitives` の構造体に置くように伝えます。

セマンティクスを受け取れない型の値に付けた箇所も報告します (`uint2 id : SV_VertexID`、`float id : SV_ViewID` など。slangc の E30701、DXC の「SV_VertexID must be uint.」、FXC の X4555 など)。
受け取れる型は、コンパイラごとに型を変えてコンパイルした表で決めます。表に存在しない型 (`half`・`min16uint`・構造体など) と配列の値は見ません。

ピクセルシェーダーの深度の出力 (`SV_Depth`・`SV_DepthGreaterEqual`・`SV_DepthLessEqual`) は 1 つだけです。
仮引数・戻り値・構造体のフィールドをまたいで 2 つ目を報告します (DXC と slangc。FXC は誤りにしません)。

```hlsl
void main(out float a : SV_DepthGreaterEqual, out float b : SV_Depth)   // b を報告する
```

## なぜ問題か

コンパイルエラーになります (FXC は `X4502: invalid vs_5_0 output semantic 'SV_Depth'`、
DXC は `invalid semantic 'SV_Depth' for vs 6.8`、slangc は `E30702` / `E30703`)。

Unity はシェーダーを必要になった時点でコンパイルするため、
該当のマテリアルを画面に出すまで気づけないことがあります。

## 修正方法

ステージに合うセマンティクスにするか、値を別のステージで受け渡してください。

- 深度を書き込む場合は、ピクセルシェーダーの出力 (`out float depth : SV_Depth`) にします
- 頂点シェーダーから値を渡す場合は、`TEXCOORD0` などのセマンティクスにします
- `SV_DispatchThreadID` などのスレッドの番号は入力にだけ使用できます。結果は `RWStructuredBuffer` などに書き込みます

## 環境による違い

使用できるかは、FXC (シェーダーモデル 5.0)・DXC (シェーダーモデル 6.8)・slangc に、すべての組み合わせをコンパイルさせて作った表で決めます。
表は `tools/semantics/system-values.mjs` が作ります。コンパイラによって表が違うので、そのファイルをコンパイルするコンパイラの表を使用します。

- Unity: コンパイル先のコンパイラ (既定は FXC、`#pragma use_dxc` などで DXC)。どれかのコンパイラがエラーにする場合に報告し、そのコンパイラを示します
- 汎用の HLSL・Unreal: 設定 (`hlsl: compiler`) やプラットフォームで決まるコンパイラ
- Slang: slangc

主な違いは次のとおりです。

- slangc は、頂点シェーダーの入力に `SV_Position` を使用できません。FXC と DXC は使用できます
- slangc は `SV_Target` をどこでも受け付けます。FXC と DXC はピクセルシェーダーの出力にだけ使用できます
- FXC は、シェーダーモデル 6 で加わったもの (`SV_ViewID`・`SV_Barycentrics`・`SV_ShadingRate` など) をどこでも使用できません

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- エントリポイントのステージが不明な場合。ステージは `[shader("vertex")]` の属性、Unity の `#pragma vertex` などの指定、
  設定ファイルの `units:` の `target` (`vs_6_0` など)、メッシュシェーダーの `[outputtopology]` と `out vertices` から決めます。
  slangc の `-stage` のように、コマンドラインだけで指定したステージは参照できません
- 表に存在しない組み合わせ (コンパイラが別の理由でエラーにしたため、判断できなかったもの) と、表に存在しないセマンティクス
- `SV_` で始まらないセマンティクス (`POSITION`・`COLOR`・`VPOS` など)
