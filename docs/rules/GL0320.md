# GL0320: どの多重定義を呼ぶか決まりません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、利用者の関数の呼び出しに、型がすべて同じ宣言が無く、暗黙の変換で合う宣言が 2 つ以上あって 1 つに決まらない状態です。
glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

void scale(float a, double b) { }
void scale(double a, float b) { }

void main()
{
    float f = 1.0;
    scale(f, f);   // (float, double) と (double, float) のどちらも合い、決まらない
    color = vec4(f);
}
```

決め方は glslang と同じです。

- 型がすべて同じ宣言があれば、それを呼びます
- デスクトップの 1.20 から 4.00 より前 (`GL_ARB_gpu_shader5` などが無いとき) と、ES の `GL_EXT_shader_implicit_conversions` では、
  暗黙の変換で合う宣言が 2 つ以上あれば決まりません
- 4.00 からは、実引数ごとに変換の良さを比べます。変換しないものがいちばん良く、次に `float` から `double`、次に `double` より `float` への変換が良いです。
  どの実引数でもほかより悪くなく、どれかで良い宣言が 1 つだけあれば、それを呼びます
- 明示的な幅の算術型の拡張 (`GL_EXT_shader_explicit_arithmetic_types` など) を有効にしたときは、変換しないもの、昇格 (`int16_t` から `int`、`float` から `double` など)、
  それ以外の変換の順に良いとして比べます

関数は呼ぶ位置より前に宣言しなければならないので、呼び出しより前の宣言だけを候補にします。
仮引数と実引数がどれも数値の型 (配列でない) の呼び出しだけを見ます。同じ名前の組み込み関数がある名前は見ません。

## なぜ問題か

どの関数を呼ぶかが決まらないので、glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

実引数を、呼びたい宣言の仮引数の型に合わせてください (`scale(f, double(f))`)。
多重定義の仮引数の型が近すぎるなら、関数の名前を分けることも考えてください。
