# CF0410: 値を代入先の型へ変換できません

分類: Correctness / 既定の重要度: エラー / 0.3.1 より前の ID: HL0350

## 何を検出するか

代入または初期化で、渡している値の成分が代入先より少ない状態です。

```hlsl
float2 uv;

float3 a = uv;          // 成分が足りない
float2 b = float3(1, 2, 3); // 正しい (切り捨て。警告は出る)
float3 c = 1;           // 正しい (スカラーは全成分へ複製される)

float3 d;
d = uv;                 // 成分が足りない
d.xy = uv;              // 正しい

float3x3 m = uv;        // ベクトルは行列へ渡せない
```

判定は引数の受け渡し ([CF0401](CF0401.md)) と同じ規則です。

| 向き           | 例                    | 扱い              |
| -------------- | --------------------- | ----------------- |
| 成分を減らす   | `float3` → `float2`   | 通る (警告 X3206) |
| スカラーを複製 | `float` → `float3`    | 通る              |
| 成分を増やす   | `float2` → `float3`   | エラー            |
| ベクトルと行列 | `float3` → `float3x3` | エラー            |

複合代入 (`+=` など) も、右辺を左辺の型へ変換してから演算するので同じ判定です。

## なぜ問題か

コンパイルに失敗します。

変数の型を後から広げたときや、
`float3` を返すつもりの式が実は `float2` だったときに現れます。

## どう直すか

足りない成分を明示してください。

```hlsl
float3 a = float3(uv, 0);
```

## 構成によって型が変わる場合

同じ名前を条件ごとに違う型で宣言している場合も、構成ごとに型を求めて判定します。

```hlsl
#if defined(_A)
float3 a = float3(1, 2, 3);
#elif defined(_B)
float2 a = float2(1, 2);
#endif

float3 result;
result = a;   // !_A && _B のとき float2 を float3 へ渡している
```

この場合、どの構成で起きるかを添えて報告します。

```
float2 を float3 に変換できません。構成：!_A && _B のとき、この式は float2 です。
```

成分が落ちるだけで渡せはする場合は、このルールではなく
[CF0413](CF0413.md) が警告として報告します。

## 構造体 (HLSL 2021)

HLSL 2021 では、構造体が関わる暗黙の変換も見ます (DXC で確かめた規則です)。

```hlsl
struct P { float x; };
struct Q { float x; };
struct D : P { float z; };

P p = q;        // 報告する。別の構造体 (メンバーが同じでも)
P p = d;        // 正しい。派生した構造体は基底へ入る
P p = 0;        // 報告する。数は構造体へ暗黙に変換されない
P p = (P)0;     // 正しい
float f = p;    // 報告する。構造体は数へ暗黙に変換されない
```

template の構造体 (`Box<float4>`) は、型引数が違えば別の型ですが、名前だけでは区別できないので見ません。
Unity の環境 (HLSL 2018) では、FXC の規則を確かめていないので見ません。

## GLSL の関数の外の変数

GLSL では、関数の外の変数の初期値も検査します (`int a = true;`、`int b = 0xFFFFFFFFu;` など)。glslang は関数の中と同じく誤りにします。

## GLSL の配列

GLSL の配列は、大きさまで同じでなければ代入も初期化もできません (glslang と同じ)。
大きさを書かない配列 (`float u[];`) へも、それからも代入できません。
初期化では、宣言の外側の大きさを省けば値の大きさになります。

```glsl
float a4[4];
float a5[5] = a4;                 // 報告する。大きさが違う
int b[3] = int[](3, 2);           // 報告する。値の大きさは 2
float c[2] = { 1.0, 2.0, 3.0 };   // 報告する。要素が 3 個
float d[] = float[](1.0, 2.0);    // 正しい。d の大きさは 2
```

大きさが数で書かれていない次元 (定数の名前、特殊化定数) は比べません。

配列の値の作成 (`float[4][7](a, b, c, d)`) の実引数は、内側の次元と同じ形の配列でなければなりません (`float[](a[0], …)` に配列を渡すもの、`float[4][7][4](…)` に `float[7]` を渡すものを報告します)。
内側の次元の大きさを書かない配列 (`vec4 v[3][];`) の初期化子の要素は、どれも同じ大きさの配列でなければなりません。
buffer のブロックの最後のメンバーのような、大きさの決まっていない配列には代入できません (`name[1].v = a;`)。

ES の `GL_EXT_shader_implicit_conversions` による暗黙の変換 (`int` から `uint` など) は、その位置で拡張が有効なときだけ通します。
`#extension GL_EXT_shader_implicit_conversions : disable` の後ろの変換は報告します。
見るのは、名前 (変数と仮引数)・配列の値の作成 (`float[3](…)`)・波括弧の初期化子 (外側の要素の数だけ) です。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- どちらかの型が分からない場合。
  型が分からないことは「合っていない」ことの証拠になりません。
  構成を決めても分からない場合を含みます
- 調べる構成が多すぎる場合。1 つの式につき 16 通りまでを見ます
- 配列に単一の値を与える形。規則が違うので踏み込みません
- 波括弧による初期化。要素の個数は [CF0412](CF0412.md) が見ます
- 構造体やテクスチャなど、成分の数で比べられない型
