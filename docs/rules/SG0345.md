# SG0345: throw と try の書き方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、誤りを投げる `throw` と、投げる関数を呼ぶ `try` を、受ける先が存在しない場所に書いている状態です。
slangc はコンパイルの誤り (E30093・E30113・E30114・E30115・E30116) にします。

```slang
enum MyError { Fail }
enum OtherError { Fail }

int g() throws MyError { throw MyError.Fail; }

void f()
{
    let n = try g();               // throws が存在しない関数の、catch で受けない try
    throw MyError.Fail;            // throws が存在しない関数の、catch で受けない throw
}

void h() throws MyError
{
    defer
    {
        throw MyError.Fail;        // defer の中の、catch で受けない throw
    }
}

int k() throws MyError
{
    throw OtherError.Fail;         // throws の型と違う列挙型
}
```

`do { … } catch` で受けたものは通ります。ラムダ式の本体は見ません。

エントリポイント (`[shader]` か `[numthreads]` を書いた関数) には `throws` を書けません (E38053)。誤りを返す先が存在しないので、関数の中で受けてください。

## なぜ問題か

`throws` を書いていない関数からは、誤りを外へ投げられません。`defer` から投げると、ほかの `defer` が動かなくなります。

## どう直すか

関数に `throws` を書くか、`do { … } catch (e : MyError) { … }` で受けてください。`defer` の中では、その中で受けてください。
投げる値は、関数の `throws` の型にそろえてください。
