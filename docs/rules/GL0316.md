# GL0316: 整数のスカラーでなければなりません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、配列・ベクトル・行列の添字、`switch` の条件、`case` のラベルに、整数のスカラーでない値を書いている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;
layout(binding = 0) uniform U { float f; int a[2]; };

void main()
{
    vec4 v[4];
    color = v[1.0];         // 添字が float
    switch (f) { }          // switch の条件が float
    switch (a) { }          // switch の条件が配列
    switch (a[0]) {
        case 2.0: break;    // case のラベルが float
    }
}
```

- 添字と `case` のラベルは、`int` と `uint` のほか、拡張の整数の型 (`int16_t`、`int64_t` など) のスカラーを使えます
- `switch` の条件は、`int` か `uint` のスカラーでなければなりません
- `atomic_uint` やサンプラーのような不透明な型も誤りです

型が分からない式と、構成 (`#if` の分かれ) によって型が変わる式は見ません。

## なぜ問題か

GLSL は、浮動小数点数やベクトルを暗黙に整数へ変換しません。glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

`int(...)` で整数に変換するか、整数の変数を使ってください。
