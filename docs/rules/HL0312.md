# HL0312: 存在しないメンバー

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

存在しないメンバーの参照です。2 つの形があります。

### 構造体のメンバー名のスペルミス

```hlsl
struct Varyings
{
    float4 positionHCS : SV_POSITION;
    float2 uv : TEXCOORD0;
};

float w = IN.postionHCS.x;   // positionHCS のスペルミス
```

メッセージには、その構造体にあるメンバーの一覧が付きます。

### 行列の成分の書き方が誤っている

```hlsl
float3x3 m;

float a = m._m00;    // 正しい (0 始まり)
float b = m._11;     // 正しい (1 始まり)
float c = m._m44;    // 3x3 に 4 行 4 列は無い
float d = m._m00_11; // 0 始まりと 1 始まりは混ぜられない
float e = m.x;       // 行列にスウィズルは無い
```

### 成分の数を超えたスウィズル

```hlsl
float2 uv;

float z = uv.z;      // float2 に z は無い
float m = uv.xg;     // 位置 (xyzw) と色 (rgba) は混ぜられない
float4 t = uv.xyzwx; // 一度に取り出せるのは 4 成分まで
```

スカラーとベクトルには、スウィズル以外のメンバーがありません。
だからここでは「成り立たないものはすべて誤り」と言い切れます。

## なぜ問題か

コンパイルに失敗します。

スペルミスは目で追っても見つけにくく、
構造体のメンバーを増減したときに置き去りになった参照も同じ形で現れます。

## どう直すか

正しい名前に直すか、必要な成分を持つ型に変えてください。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 利用者が書いた構造体でない場合 (Unity や外部パッケージのヘッダの構造体)。
  指摘しても直しようがありません。利用者が書いて取り込んだヘッダの構造体は対象です
- 参照している式の型が分からない場合
  （同じ名前を条件ごとに違う型で宣言している場合は、構成ごとに型を求めて検査します。
  その場合はメッセージに「`_A && _B` のとき、この式は `float3` です。」のように構成を添えます。
  両方の分岐を 1 本の木に並べられない書き方では、今までどおり型が分からないものとして報告しません）
- メソッド呼び出し。`texture.Sample(...)` はメンバー参照とは形が違います
- 条件付きのメンバーが、条件の外から参照されている場合。
  メンバー自体は存在するので、[HL0313](HL0313.md) の担当です
