# SG0364: GetAttributeAtVertex に頂点の入力でない値を渡しています

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

フラグメントシェーダーのエントリポイントで、`GetAttributeAtVertex` の 1 つ目の実引数に、エントリポイントの入力を直接渡していない箇所です。

```slang
struct VertexOutput
{
    float color;
    nointerpolation float id;
}

static float g;

[shader("fragment")]
float4 fsmain(VertexOutput vout, nointerpolation float4 n : NORMAL) : SV_Target
{
    float l = vout.id;
    return GetAttributeAtVertex(vout.color, 0)   // 報告する。nointerpolation がないスカラー
         + GetAttributeAtVertex(vout.id, 0)      // 報告しない
         + GetAttributeAtVertex(l, 0)            // 報告する。局所変数
         + GetAttributeAtVertex(g, 0)            // 報告する。グローバル変数
         + GetAttributeAtVertex(n.x, 0);         // 報告する。ベクトルの成分
}
```

報告するのは次のものです。

- `nointerpolation` も `pervertex` もないスカラーの入力 (仮引数と構造体のフィールド)
- 局所変数 (入力を入れたものを含む) とグローバル変数
- 入力のベクトルの成分 (`n.x`)

## なぜ問題か

slangc がコンパイルの誤り (`E39027: 'GetAttributeAtVertex' must reference vertex input`) にします。

## 修正方法

エントリポイントの入力に `nointerpolation` か `pervertex` を付けて、その入力を直接渡してください。

```slang
struct VertexOutput
{
    nointerpolation float color;
}
```

## 環境による違い

slangc 2026.19 で確認した条件です。ベクトルの入力は、`nointerpolation` を付けていなくても slangc は通します。このルールも報告しません。

HLSL では [HL0355](HL0355.md) になります。DXC は条件が違います (`nointerpolation` を付けていないベクトルの入力も誤りにし、入力を入れた局所変数は通します)。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- エントリポイントの本体でない関数の中の呼び出し (ほかの関数の仮引数を渡すと slangc が内部エラー E99997 で止まるため、見ません)
- `[shader("fragment")]` を付けていないエントリポイント
