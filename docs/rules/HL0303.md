# HL0303: cbuffer の中の関数をエントリポイントにしています

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

エントリポイント (`#pragma vertex` / `#pragma fragment` など、または設定ファイルの `units` の `entry`) の関数が、
cbuffer (`CBUFFER_START` / `CBUFFER_END`) の中に書かれていて、そのコードが FXC でだけコンパイルされるものです。

```hlsl
CBUFFER_START(UnityPerMaterial)
#include "MyPass.hlsl"   // uniform と一緒に Main_PS も書いてある
CBUFFER_END
```

```
Lit.shader(11:30): warning HL0303: #pragma fragment が指定する関数 'Main_PS' は cbuffer 'UnityPerMaterial' の中にあります。
    dx11 (FXC) ではコンパイルできますが、DXC ではエントリポイントにできません。関数を cbuffer の外へ出してください。
```

cbuffer の中に `#include` を書き、取り込んだファイルに uniform 以外のもの (関数) があると、こうなります。

## なぜ問題か

Unity 6.6 と、スタンドアロンの FXC / DXC 1.8 で確かめた結果です。

| cbuffer の中に書いたもの | FXC | DXC |
| --- | --- | --- |
| uniform、`#define`、構造体、`static const` | 通る | 通る |
| 関数 (呼ぶだけ) | 通る | 通る |
| 関数をエントリポイントにする | 通る | 通らない ([HL0304](HL0304.md)) |

FXC では動きますが、DX12 などで DXC に切り替えると、このシェーダーはコンパイルできなくなります。
Unity では、エラーの行も出ずに「Lost connection with shader compiler process. Suspected crash in DXC.」になり、原因を探しにくくなります。

## どう直すか

関数を cbuffer の外へ出してください。cbuffer の中で取り込んでいるファイルなら、uniform だけのファイルと関数のファイルに分けます。

```hlsl
CBUFFER_START(UnityPerMaterial)
#include "MyPassProperties.hlsl"   // uniform だけ
CBUFFER_END
#include "MyPass.hlsl"             // Main_PS
```

## 誤検出だと思ったら

DXC でコンパイルされることが無いと分かっているなら、設定ファイルの `rules:` で `HL0303: none` にしてください。
