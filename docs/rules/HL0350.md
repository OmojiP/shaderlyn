# HL0350: 値を代入先の型へ変換できません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

代入または初期化で、渡している値の成分が代入先より少ない状態です。

```hlsl
float2 uv;

float3 a = uv;          // 成分が足りない
float2 b = float3(1, 2, 3); // 正しい (切り捨て。警告は出る)
float3 c = 1;           // 正しい (スカラーは全成分へ複製される)

float3 d;
d = uv;                 // 成分が足りない
d.xy = uv;              // 正しい

float3x3 m = uv;        // ベクトルは行列へ渡せない
```

判定は引数の受け渡し ([HL0340](HL0340.md)) と同じ規則です。

| 向き           | 例                    | 扱い              |
| -------------- | --------------------- | ----------------- |
| 成分を減らす   | `float3` → `float2`   | 通る (警告 X3206) |
| スカラーを複製 | `float` → `float3`    | 通る              |
| 成分を増やす   | `float2` → `float3`   | エラー            |
| ベクトルと行列 | `float3` → `float3x3` | エラー            |

複合代入 (`+=` など) も、右辺を左辺の型へ変換してから演算するので同じ判定です。

## なぜ問題か

コンパイルに失敗します。

変数の型を後から広げたときや、
`float3` を返すつもりの式が実は `float2` だったときに現れます。

## どう直すか

足りない成分を明示してください。

```hlsl
float3 a = float3(uv, 0);
```

## 構成によって型が変わる場合

同じ名前を条件ごとに違う型で宣言している場合も、構成ごとに型を求めて判定します。

```hlsl
#if defined(_A)
float3 a = float3(1, 2, 3);
#elif defined(_B)
float2 a = float2(1, 2);
#endif

float3 result;
result = a;   // !_A && _B のとき float2 を float3 へ渡している
```

この場合、どの構成で起きるかを添えて報告します。

```
float3 に float2 は入りません。!_A && _B のとき、この式は float2 です。
```

成分が落ちるだけで渡せはする場合は、このルールではなく
[HL0353](HL0353.md) が警告として報告します。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- どちらかの型が分からない場合。
  型が分からないことは「合っていない」ことの証拠になりません。
  構成を決めても分からない場合を含みます
- 調べる構成が多すぎる場合。1 つの式につき 16 通りまでを見ます
- 配列に単一の値を与える形。規則が違うので踏み込みません
- 波括弧による初期化。要素の個数は [HL0352](HL0352.md) が見ます
- 構造体やテクスチャなど、成分の数で比べられない型

## 関連

- [HL0340](HL0340.md) — 実引数を仮引数の型へ変換できない
- [HL0351](HL0351.md) — `return` の値が戻り値の型と合わない
- [HL0353](HL0353.md) — 構成によっては成分が切り捨てられる

先の 3 つは同じ変換規則を使っています (`HlslConversion`)。
上の表で「通る (警告 X3206)」となっている切り捨てのうち、
条件ごとに型を書き分けた場合だけを HL0353 が見ます。
