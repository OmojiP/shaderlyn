# HL0315: 変数の宣言がその構成にありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

使っている変数の宣言が、その構成には存在しない状態です。

```hlsl
#pragma multi_compile _ _TINT

#ifdef _TINT
float4 _TintColor;                  // _TINT が有効のときだけ宣言
#endif

half4 frag() : SV_Target
{
    return _TintColor;              // いつも使う → _TINT が無効のときに宣言が無い
}
```

使う条件は「常に」、宣言がある条件は `_TINT` です。
`_TINT` が無効の構成では、`_TintColor` はどこにも宣言されていません。

宣言がどこかの構成にはあるので、[HL0310](HL0310.md)（宣言されていない識別子）にはなりません。
食い違いは「使う側の条件」と「宣言がある条件」の組み合わせにしか現れないため、このルールが受け持ちます。
関数についての同じ検査は [HL0311](HL0311.md) です。

## なぜ問題か

その構成ではコンパイルに失敗し、シェーダーが使えなくなります。

Unity はシェーダーを必要になった時点でコンパイルするので、
そのシンボルの組み合わせが実際に使われるまで表面化しません。
別のシンボルを有効にした（または無効にした）瞬間に壊れる、という形で現れます。

## どう直すか

条件を揃えてください。次のどちらかです。

- 宣言側の条件を、使う側を覆うように広げる（`#ifdef` を外す）
- 使う側を、宣言がある条件の中へ入れる

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- その位置で関数の中の変数か仮引数を指している名前。
  別の関数に同じ名前の局所変数があっても、ここでグローバル変数を指しているなら対象にします。
  局所変数が一部の構成でしか宣言されていなくても、局所変数を指しうるなら対象にしません
- その位置で名前が何を指すか決められない場合。
  波括弧の無い `if (x) float a;` のような宣言があるときなどです
- 依存関係を解決できていない場合（[SL0002](SL0002.md) を参照）
- どの構成でも解析しない領域（`SHADER_API_*` など環境の条件の中）に、その名前が現れる場合。
  そこで宣言されているかもしれません
- 宣言や使う側の出現条件を追えなかった場合（[SL0004](SL0004.md) を参照）

同じ行の `#pragma` に並べたシンボルが同時に有効にならないことと、
`_` の無い `multi_compile` の行はどれか 1 つが必ず有効なことは考えに入れます。
