# TOOL0004: 取り込むヘッダを 1 つも解決できません

分類: Tool / 既定の重要度: エラー

## 何を検出するか

そのシェーダーが書いている `#include` を、1 つも解決できなかった状態です。

```
Assets/Shaders/Lit.shader(9:9): error TOOL0004: 取り込むヘッダを 1 つも解決できません
    (最初に引けなかったのは 'Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl')。
    --unity-project にプロジェクトのルートを渡してください。
    CI では Library/PackageCache がキャッシュされているかを確かめてください。
```

`Packages/...` を引けない場合の多くは、シェーダーの誤りではなく解析の前提が揃っていない状態です。
自前のヘッダを引けない場合は、パスの書き方か探索パスの設定に原因があります。

## なぜ問題か

Unity のヘッダは、あるものとして扱います。

ヘッダを引けないと、そこで定義されるマクロも型も宣言も分かりません。
その状態で出した指摘は根拠を欠いており、
出なかった指摘も「問題が無い」ことを意味しません。

以前はこの状態でも警告のまま解析を続けていました。
しかし「精度が落ちたことが分からない結果」は、利用者からは正常な結果と区別が付きません。
「見送ったことを必ず伝える」という原則を、止まるところまで進めたのがこの規則です。

## どう直すか

メッセージの直し方は、最初に引けなかったパスの形で変わります。

| 引けなかったパス | 直し方 |
| --- | --- |
| `Packages/...` | Unity プロジェクトのルートを指定する（CLI は `--unity-project`、VS Code はプロジェクトのルートを開く）。CI では `Library/` をキャッシュする |
| `Assets/...` | Unity プロジェクトのルートを指定する |
| `UnityCG.cginc` のようなファイル名だけ | Unity 同梱のヘッダなら Unity Editor が見つかる必要がある（CLI は `--unity-editor`）。自前のヘッダなら探索パスに加える |
| それ以外 (`Shaders/Common.hlsl` など) | パスの書き方と、取り込み元からの相対位置を確かめる。別の場所に置いたなら探索パスに加える（CLI は `--include-path`、設定ファイルは `include-paths`） |

GitHub Actions では `unity-project: .` を指定し、`actions/cache` の `path: Library` で `Library/` を持ち越します。

Unity 同梱のヘッダと、Editor に同梱された URP / HDRP のパッケージは、
インストール済みの Editor から引きます
(`--unity-project` があればその `ProjectVersion.txt` のバージョンを、
無ければ最も新しいものを使います)。
このエラーは、プロジェクトの `Library/PackageCache` からも Editor からも
引けなかったことを意味します。
Unity をインストールしない CI では、`Library/` をキャッシュするか、
Unity の入ったランナーを使ってください
([CI に組み込む](../guide/ci-setup.md#2-セルフホストランナーを用意する))。
