# URP0003: このレンダーパイプラインで推奨されない API を使用しています

分類: Usage / 既定の重要度: 警告

## 何を検出するか

SRP のシェーダーで、Built-in レンダーパイプライン向けの API を使っている箇所です。

| 使っている API                                   | 代替                                               |
| ------------------------------------------------ | -------------------------------------------------- |
| `UnityObjectToClipPos`                           | `TransformObjectToHClip`                           |
| `UnityObjectToWorldNormal`                       | `TransformObjectToWorldNormal`                     |
| `UnityObjectToWorldDir`                          | `TransformObjectToWorldDir`                        |
| `UnityWorldSpaceViewDir` / `WorldSpaceViewDir`   | `GetWorldSpaceViewDir`                             |
| `UNITY_MATRIX_MVP`                               | `UNITY_MATRIX_VP` と `UNITY_MATRIX_M` の組み合わせ |
| `tex2D` / `tex2Dlod` / `tex2Dbias` / `tex2Dgrad` | `SAMPLE_TEXTURE2D` 系                              |
| `tex3D` / `texCUBE` / `texCUBElod`               | `SAMPLE_TEXTURE3D` / `SAMPLE_TEXTURECUBE` 系       |

## なぜ問題か

多くは互換のために残されているだけで、
SRP Batcher やインスタンシングと組み合わせたときに正しく動かないことがあります。

`UNITY_MATRIX_MVP` は代表的で、
SRP ではモデル行列が定数バッファ経由で渡されるため、
この行列を使うと SRP Batcher の前提が崩れます。

`tex2D` 系はテクスチャとサンプラが 1 つに融合した Cg 時代の記法です。
SRP ではテクスチャとサンプラを分けて宣言するため、
`TEXTURE2D` / `SAMPLER` で宣言した組み合わせに対しては使えません。

## どう直すか

```hlsl
// Built-in の書き方
o.pos = UnityObjectToClipPos(v.vertex);
half4 c = tex2D(_MainTex, i.uv);

// URP の書き方
o.positionCS = TransformObjectToHClip(v.positionOS.xyz);
half4 c = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, i.uv);
```

## 誤検出だと思ったら

このルールは、対象のシェーダーが実際に SRP のヘッダを取り込んでいる場合にのみ適用されます。

`--profile urp` を指定していても、
`UnityCG.cginc` しか使っていない Built-in 向けのシェーダーには発火しません。
そちらでは `UnityObjectToClipPos` が正規の書き方であり、
指摘するのは端的に誤りだからです。

検査はマクロ展開前のコードに対して行います。
`UNITY_MATRIX_MVP` のようにマクロ自体を対象にする以上、
展開後のトークン列では検出できないためです。
その副作用として、`#if` の非活性領域に書かれた使用箇所も報告されます。
バージョン分岐で意図的に残している場合は抑制してください。
