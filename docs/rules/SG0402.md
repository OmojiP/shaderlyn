# SG0402: 可視性の書き方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、可視性 (`public`・`internal`・`private`) を次のように書いている状態です。slangc はコンパイルの誤りにします。

- 関数の外の宣言 (関数・構造体・変数) を `private` にしている (E30603)。`private` は型のメンバーにだけ書けます
- public でない構造体のメンバーを `public` にしている (E30601)。メンバーの公開範囲は親より広くできません
- public の宣言 (関数・変数・`typealias`・public の構造体の public のメンバー) が、public でない型を使用している (E30604)

```slang
private struct Hidden { }              // 報告する。関数の外の private

struct Inner { public int x; }         // 報告する。Inner は public ではない (書かなければ internal)

struct IS { int a; }
public IS make() { return {}; }        // 報告する。public の関数が IS を返す
public struct P { public IS s; }       // 報告する (s の型と、P の名前)
public struct Q { IS s; }              // 正しい。internal のフィールドは IS を使用できる
```

## なぜ問題か

public の宣言は別のモジュールから使用できます。そのとき、使用する側から参照できない型が現れると、値を受け取ることも渡すこともできません。

## どう直すか

使用する型も `public` にするか、宣言を `public` でなくしてください。関数の外の宣言で隠したいものは、`private` ではなく `internal` (書かなければ internal) にしてください。

## 見ないもの

このファイルで宣言した型だけを見ます。`property` と、構造体の中の構造体の可視性はまだ見ません。
