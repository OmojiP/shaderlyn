# SL1050: コンパイラの指定が API や Unity のバージョンと一致しません

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`#pragma use_dxc` / `never_use_dxc` / `require` のうち、対象の API や Unity のバージョンでは意図どおりに効かないものです。

| 書いたもの | 報告する条件 | 何が起きるか |
| --- | --- | --- |
| `use_dxc d3d12` | いつでも | どのバージョンでも無視される (FXC のまま) |
| `use_dxc dx12` | Unity 6.5 以前 | 無視される (FXC のまま)。`dx12` が効くのは 6.6 から |
| `use_dxc` (API なし) / `use_dxc d3d11` | Unity 6.5 以前で、対象の API に DX11 がある | DX11 も DXC でコンパイルされ、DX11 では使えなくなる |
| DXC が要る `require` (`int64` / `native16bit` / ウェーブの命令など) | 対象の API に DX11 がある | DX11 では使えない (コンパイルされないか、作られても使われない) |
| `require inlineraytracing` | Unity 2022.3 | 知らない値として無視される (FXC のまま) |
| `never_use_dxc` と DXC が要る `require` | いつでも | 6.5 以前は FXC、6.6 からは DXC。バージョンで結果が逆になる |
| include ファイルの中の `use_dxc` / `require` | Unity 2023.2 以降 | 無視される (FXC のまま)。コードブロックの開始の語に報告する |

```hlsl
#pragma use_dxc d3d12      // 報告する。d3d12 は API 名として無視される
#pragma require int64      // 対象に DX11 があれば報告する
```

規則は Unity 2022.3〜6.6 (DX11 / DX12 / Vulkan) で確かめました。

## どう直すか

- DX12 だけを DXC にするなら、6.6 以降は `use_dxc dx12` と書きます。6.5 以前は `d3d11` と書きますが、DX11 も DXC になります
- DX11 でも使うシェーダーで DXC が要る機能を使うなら、キーワードで分けます (`#pragma require int64 : _USE_INT64`)
- `never_use_dxc` と `require` はどちらか一方にします
- include ファイルに書いた指定は、コードブロックか `HLSLINCLUDE` に移します

## 環境による違い

Unity の環境だけで動きます。バージョンで変わるものは、Unity のバージョンが分かるとき
(`--unity-project` のプロジェクトの `ProjectVersion.txt`、または設定の `unity: version`) だけ報告します。
対象の API は `unity: graphics-apis`、無ければプロジェクトの設定、それも無ければ DX11 と DX12 です
([設定](../guide/configuration.md#シェーダーのコンパイラ))。
