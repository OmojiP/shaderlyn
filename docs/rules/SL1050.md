# SL1050: コンパイラの指定が無視されます

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`#pragma use_dxc` / `require` のうち、Unity が認識しない、または効かない場所に書いたために無視されるものです。
この指定では DXC に切り替わらず、ほかに DXC の指定が無ければ FXC でコンパイルされます。

| 書いたもの | 報告する条件 | 直し方 |
| --- | --- | --- |
| `use_dxc d3d12` | いつでも | DX12 を DXC にするなら、Unity 6.6 以降は `dx12`、6.5 以前は `d3d11` を書く (6.5 以前の `d3d11` は DX11 にも効く) |
| `use_dxc dx12` | Unity 6.5 以前 | 6.5 以前で DX12 を DXC にするなら `d3d11` を書く (DX11 にも効くので、DX11 では使えなくなる) |
| include ファイルの中の `use_dxc` / `require` | Unity 2023.2 以降 | コードブロックか `HLSLINCLUDE` に移す。報告はコードブロックの開始の語に出す |
| `require inlineraytracing` | Unity 2022.3 | 要るなら Unity 6.4 以降を使い、要らなければ消す |

```
Assets/Shaders/A.shader(14:29): warning SL1050: use_dxc の API 名 d3d12 は、どのバージョンの Unity でも認識されません。
    この指定では DXC に切り替わらず、ほかに DXC の指定が無ければ FXC でコンパイルされます。
    DX12 を DXC にするには、Unity 6.6 以降は dx12、6.5 以前は d3d11 を書いてください (6.5 以前の d3d11 は DX11 にも効きます)。
```

文は「何が起きているか」「何でコンパイルされるか」「どう直すか」の 3 文です。規則は Unity 2022.3〜6.6 (DX11 / DX12 / Vulkan) で確かめました。

## なぜ問題か

DXC でしか使えない機能 (64 ビットの整数、ウェーブの命令など) を使うつもりで DXC を指定しても、FXC でコンパイルされます。
FXC はその機能を知らないので、コンパイルエラーになるか、意図しない書き方で通ります。
Unity はこの指定を無視したことを伝えません (`inlineraytracing` の 2022.3 だけは「unknown feature」の警告を出します)。

## 環境による違い

Unity の環境だけで動きます。バージョンで変わるものは、Unity のバージョンが分かるとき
(`--unity-project` のプロジェクトの `ProjectVersion.txt`、または設定の `unity: version`) だけ報告します
([設定](../guide/configuration.md#シェーダーのコンパイラ))。

## 関連

コンパイラの指定の誤りは、直し方の種類で ID を分けています。DX12 だけを対象にするプロジェクトは SL1053 だけを無効にできます。

- [SL1053](SL1053.md) — DX11 で使えなくなる指定
- [SL1054](SL1054.md) — Unity のバージョンでコンパイラが変わる指定
- [SL1051](SL1051.md) — コンパイラの指定についての注意
- [HL0003](HL0003.md) — この環境では使えない構文
