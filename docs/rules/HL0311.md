# HL0311: 関数の定義が見つかりません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

呼んでいる関数の定義が、その構成には存在しない状態です。

```hlsl
#pragma multi_compile _ SHADER_DEBUG

half4 sampleTexture(float2 uv);      // 宣言だけ

half4 frag(Varyings IN) : SV_Target
{
#ifdef SHADER_DEBUG
    return IN.debugColor;
#else
    return sampleTexture(IN.uv);     // SHADER_DEBUG が無効のときに呼ぶ
#endif
}

#ifdef SHADER_DEBUG
half4 sampleTexture(float2 uv) { ... }   // SHADER_DEBUG が有効のときだけ定義
#endif
```

呼ぶ条件は `!SHADER_DEBUG`、定義がある条件は `SHADER_DEBUG` です。
この 2 つは同時に成り立たないため、呼ぶときには必ず定義がありません。

定義がどこにも無い場合も同じ規則で報告します。
宣言は取り込んだヘッダの中にあってもかまいません。
宣言が見えていて実装がどこにも無いなら、その構成ではリンクできません。
宣言をどのファイルに書いたかは、その判断と関係がないからです。

シンボルを宣言した `#pragma` も、取り込んだヘッダの中にあってかまいません。
共通の関数を `Common.hlsl` に切り出し、そこに宣言と `#ifdef` の両方を置く書き方でも、
`#ifdef` の外れた側でしか定義されていない関数の呼び出しを報告します
([条件付きコンパイル](../guide/conditional-compilation.md#ヘッダに置いた-pragma))。

## なぜ問題か

その構成ではリンクに失敗し、シェーダーが使えなくなります。

宣言だけを見ると揃っているように見えるため、
コードを読んでも気づけません。
`#ifdef` の条件を書き換えたときや、
デバッグ用のコードを条件で囲ったときに紛れ込みます。

Unity はシェーダーを必要になった時点でコンパイルするので、
そのシンボルの組み合わせが実際に使われるまで表面化しません。
別のシンボルを有効にした瞬間に壊れる、という形で現れます。

## どう直すか

条件を揃えてください。次のどちらかです。

- 定義側の条件を、呼ぶ側を覆うように広げる (`#ifdef` を外す)
- 呼ぶ側を、定義がある条件の中へ入れる

条件が複雑で追いきれない場合は、
`--inspect` で構文木を開いてください。
ノードごとに `#if <条件>` のラベルが付いています。

## 別の Pass の定義は数えない

Pass (コンピュートシェーダーならカーネル) ごとに別のコードとして組み立てられるので、別の Pass にある定義はそのコードからは見えません。
別の Pass にだけ定義がある関数を呼んでいれば報告します。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 組み込み関数。どこにも宣言が無いので、そもそも対象になりません。
  対象にすると、あらゆる呼び出しが「定義が無い」になります
- Unity や外部パッケージのヘッダの中に書かれた呼び出し。
  利用者が直せない場所を指しても仕方がないので、
  報告するのはこのファイルと、利用者が書いて取り込んだヘッダに書かれた呼び出しだけです
  (宣言と実装は、どのヘッダの中にあるものも数えます)
- 出現条件が分からない場合。
  `#if` が構文の単位をまたいでいると条件を追えません。
  分からないものを根拠に「定義が無い」とは言いません
