# GL0402: 配列の大きさが要ります

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、配列の大きさを書かなければならない所で、`[]` と大きさを省いている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

struct Weights
{
    float values[];          // 構造体のメンバーには大きさが要る
};

float first(float values[])  // 仮引数にも大きさが要る
{
    return values[0];
}
```

大きさが要る所は次のとおりです (どれも glslang と同じ)。

- 関数の戻り値と仮引数の配列
- 構造体のメンバーの配列
- 配列の配列の、一番外側でない次元 (`float a[][]` の 2 つ目)。初期化子があれば要りません
- ES では、初期化子の無い変数とブロック (メンバーとインスタンスの名前) の配列。次のものは例外です
  - ジオメトリシェーダーの入力、テッセレーションのシェーダーの入力と出力 (`patch` を除く)、メッシュシェーダーの出力の配列 (ES の 3.20 か、その拡張から)
  - buffer のブロックの最後のメンバー
  - `GL_EXT_uniform_buffer_unsized_array` を有効にしたときの、uniform のブロックの最後のメンバー

デスクトップでは、関数の外と中の変数の一番外側の次元を省けます。大きさは、定数の添字で引いた一番大きな添字か、大きさを付けた宣言し直しで決まります。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

大きさを書くか、初期化子で大きさを決めてください。

```glsl
float values[4];
float okay[] = float[](1.0, 2.0, 3.0);
```
