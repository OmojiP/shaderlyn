# HL0330: 未宣言のシンボルが使用されています

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`#ifdef` などで参照しているシンボルが、
`#pragma shader_feature` / `#pragma multi_compile` / `#pragma dynamic_branch` の
どれでも宣言されていない箇所です。

```hlsl
#pragma multi_compile _ _SHADOWS_SOFT

#ifdef _SHADOWS_SOFTT   // 綴りが違う
    // このコードは決してコンパイルに含まれない
#endif
```

## なぜ問題か

シンボルは、そのシェーダーが宣言して初めて切り替えられます。

宣言していないシンボルは常に未定義のままなので、その分岐は
マテリアルからもスクリプト (`Shader.EnableKeyword`) からも有効にできません。

Unity はこれをエラーにも警告にもしません。
綴りを 1 文字誤っただけで、書いた機能が丸ごと入らないまま出荷されます。
「実装したのに効かない」という形でしか現れず、
シェーダーを読み直しても宣言と使用が離れているため気づきにくい部分です。

## どう直すか

綴りを確認し、必要なら宣言を足してください。

```hlsl
#pragma multi_compile _ _SHADOWS_SOFT

#ifdef _SHADOWS_SOFT
```

シンボルには 3 つの種類があり、選び方で変わるものがあります。

| 宣言                   | 何が変わるか                                 |
| ---------------------- | -------------------------------------------- |
| `shader_feature`       | 使われている組み合わせだけがビルドに含まれる |
| `shader_feature_local` | 同じだが、マテリアル単位のシンボルになる   |
| `multi_compile`        | すべての組み合わせが常にビルドに含まれる     |
| `dynamic_branch`       | バリアントを作らず、実行時に分岐する               |

スクリプトから `Shader.EnableKeyword` で切り替えるものは
`multi_compile` にしないと、ビルドから外れることがあります。

## 判定できる範囲

**報告するのは、このファイルに書かれた条件だけです。**
取り込んだヘッダの中の条件は、そのヘッダの都合で書かれたものであり、
利用者に直しようがありません。

**宣言されているかどうかは、取り込んだヘッダの `#pragma` も見て判断します。**
共通の関数を `Common.hlsl` に切り出し、`#pragma multi_compile` もそこに置く書き方があります。
その場合、シェーダー側にそのシンボルの宣言は 1 つも書かれていませんが、
Unity はヘッダの `#pragma` も宣言として扱うので、この指摘は出ません
([条件付きコンパイル](../guide/conditional-compilation.md#ヘッダに置いた-pragma))。

マテリアルのシンボルの形をした名前だけを報告します。
条件にはプラットフォームの判定 (`SHADER_API_D3D11`) や
コンパイラが定義する名前も現れ、それらは宣言されていなくて当然です。
アンダースコアで始まり小文字を含まない名前に限っています。

`#define` で定義されている名前も報告しません。

取り込まれる前提の断片 (`.hlsl` / `.cginc` / `.hlslinc`) を単体で解析したときも報告しません。
シンボルは取り込む側の `.shader` が宣言するためです。
`.compute` は 1 ファイルで完結するので報告します。

## 誤検出だと思ったら

このツールが見ていない場所で宣言されている場合、この指摘は無視して構いません。
`#pragma` が `#if` の中に書かれている場合などが該当します。

```hlsl
// shaderlyn-disable-next-line HL0330
#ifdef _DEFINED_ELSEWHERE
```
