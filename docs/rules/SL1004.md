# SL1004: プロパティが宣言されているだけで使われていません

分類: Usage / 既定の重要度: 情報

## 何を検出するか

`Properties` にあり、HLSL 側にも uniform として宣言されているが、
その値をどこからも読んでいないプロパティです。

SL1001 とは検出する状態が違います。

|        | HLSL の宣言 | コードからの参照 |
| ------ | ----------- | ---------------- |
| SL1001 | 無い        | 無い             |
| SL1004 | ある        | 無い             |

## なぜ問題か

機能を削除したときの消し残しであることがほとんどです。

- マテリアルのインスペクタに、効果の無い項目が並び続ける
- 定数バッファの容量を無駄に占有する
  (SRP Batcher が扱えるサイズには上限があります)
- 後から読む人が「この値はどこで使われているのか」を探す時間を生む

## どう直すか

`Properties` と HLSL の宣言の両方から削除します。

## 誤検出だと思ったら

既定の重要度を情報にしているのは、正当な用途があるためです。

- C# のスクリプトから `material.GetFloat("_Foo")` で読んでいる場合
- 別のシェーダーが `UsePass` でこの Pass を取り込み、そちらで使っている場合
- 実装途中で、これから使う予定がある場合

いずれも抑制して構いません。

なお、次の場合は報告しません。

- 依存関係を解決できていない場合 (SL0002 を参照)
- どの構成でも解析しない `#if` の領域 (`SHADER_API_*` など環境の条件の中や、取り込んだヘッダの非活性領域)にその名前が現れる場合
  (別の構成では使われている可能性があるため断定できません)
- 呼び出されなかったマクロ定義の中にその名前が現れる場合。
  URP はテクスチャの参照をマクロ定義の中だけに書くことがあります。

  ```hlsl
  // URP の LitInput.hlsl より
  #ifdef _METALLICSPECGLOSSMAP
  #define SAMPLE_METALLICSPECULAR(uv) SAMPLE_TEXTURE2D(_MetallicGlossMap, sampler_MetallicGlossMap, uv)
  #endif
  ```

  `_MetallicGlossMap` はこの定義の中でしか読まれません。
  マクロ定義の中を見ないと、正しく使われているテクスチャを
  「使われていない」と報告することになります
- ShaderLab のレンダーステートから参照している場合 (`Cull [_Cull]` など)

判定は「宣言の個数」と「コード中の出現回数」を比べて行います。
共通コード片 (`HLSLINCLUDE`) が複数の Pass へ差し込まれると
宣言も出現も Pass の数だけ増えるため、単純に出現回数だけでは判定できないためです。
