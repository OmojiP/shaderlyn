# UE0003: このプラットフォームではコンパイルされないシェーダーのため、解析していません

分類: Usage / 既定の重要度: 情報

Unreal Engine の環境 (`environment: unreal`) で、`unreal: generated` に `--unreal-generate` の結果を書いたときだけ出ます。

## 何を検出するか

C++ でシェーダーを登録したクラスが、どれも PC の Direct3D 12 (SM6) ではコンパイルされないファイルです。
モバイルだけのシェーダー (`ShouldCompilePermutation` が `IsMobilePlatform(Parameters.Platform)` を返す) や、
コンソールだけの機能を使うシェーダー (`RHISupportsRenderTargetWriteMask` など) が当たります。

```
OcclusionFeedbackShaders.usf(1:1): info UE0003: このファイルを解析していません。登録した C++ のクラス (FOcclusionFeedbackPS, FOcclusionFeedbackVS) は、どのパーミュテーションも ShouldCompilePermutation が PC の Direct3D 12 (SM6) では除きます。
```

## なぜ問題か

これは「検査していない」ことを伝えるための指摘です。

`--unreal-generate` は、クラスの `ShouldCompilePermutation` をパーミュテーションの組ごとに読み、
プラットフォームを問う関数には PC の Direct3D 12 (SM6) の設定 (`DataDrivenPlatformInfo.ini`) で答えます。
どの組でも `false` と分かったクラスは、エンジンも PC ではコンパイルしません。

そうしたファイルを既定の構成で読むと、実際にはコンパイルされる構成 (モバイル) とは違うマクロで読むことになり、
実在しない誤りを報告します (`OcclusionFeedbackShaders.usf` は、モバイルでない構成では `DummyBuffer` が宣言されていません)。
そのため、このファイルは解析しません。

登録したクラスのうち 1 つでも PC でコンパイルされるなら、そのクラスの登録だけで解析し、この指摘は出ません。

## どう直すか

直す必要はありません。知らせが要らなければ、設定ファイルでこのルールを無効にしてください。

```yaml
rules:
  UE0003: none
```

## 誤検出だと思ったら

PC でもコンパイルされるはずのシェーダーで出るなら、`ShouldCompilePermutation` の読み方が実際と違っています。
生成した `ShaderlynShaderClasses.tsv` で、そのクラスの行に `never` があるかを確かめ、クラスの名前と
`ShouldCompilePermutation` の中身を添えて報告してください。
