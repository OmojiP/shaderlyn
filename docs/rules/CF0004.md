# CF0004: マクロを中身を変えて定義し直しています

分類: Correctness / 既定の重要度: 警告 / 0.3.1 より前の ID: HL0008

## 何を検出するか

定義済みのマクロを、`#undef` せずに中身を変えて `#define` している箇所です。

```hlsl
#define TILE_SIZE 8
#define TILE_SIZE 16   // CF0004
```

別々の条件で定義している場合も、両方が同時に通る構成があれば報告します。

```hlsl
#pragma multi_compile _ _A
#pragma multi_compile _ _B

#ifdef _A
#define TINT half4(1, 0, 0, 1)
#endif
#ifdef _B
#define TINT half4(0, 0, 1, 1)   // _A と _B が同時に有効なときは定義し直しになる
#endif
#ifndef TINT
#define TINT half4(1, 1, 1, 1)    // 上のどちらも無いときだけ通るので、定義し直しではない
#endif
```

単一の構成を展開するだけでは、通るのはどれか 1 つなので気づけません。
解析しているファイルの `#define` は、読み飛ばす分岐のものも条件付きで覚えて突き合わせます。

## なぜ問題か

コンパイラはこれを警告にするだけで (DXC の `-Wmacro-redefined`、FXC の X1519)、後の定義を使ってコンパイルを続けます。
コンパイルは続きますが、取り込む順序や構成によって使われる定義が変わるため、コードを読む人には分かりにくくなります。
意図せず同じ名前を別の意味で使っている可能性もあります。

0.3.0 より前は、プリプロセッサ指令の誤り ([CF0002](CF0002.md)、エラー) として報告していました。

## どう直すか

定義し直すことが意図どおりなら、前の定義を `#undef` してから定義してください。

```hlsl
#define TILE_SIZE 8
#undef TILE_SIZE
#define TILE_SIZE 16
```

意図していないなら、名前を分けてください。

## 報告しないもの

- 同じ中身で定義し直しているもの (書き手の意図どおりなので)
- `#ifndef X` の中の `#define X` (既定の値を与える書き方)
- 取り込んだヘッダの中どうしの定義し直し (Unity のヘッダは、取り込む順序で中身を差し替える書き方を多用しているため)

## 誤検出だと思ったら

条件ごとの定義し直しは、解析しているファイルに書かれたものだけを見ます。
`#undef` した名前は、それ以降は覚えません。
それでも誤検出が出る場合は不具合として報告してください。
