# HL0371: 整数のリテラルが 32 ビットに収まりません

分類: Correctness / 既定の重要度: 警告

対応する HLSL のコード: 1002 / 1003 / 1004
(`ERR_HEXTRUNCATED` / `ERR_OCTTRUNCATED` / `ERR_DECTRUNCATED`)

## 何を検出するか

整数のリテラルが 32 ビットで表せる範囲を超えている状態です。
上位の桁が捨てられ、書いた値とは違う値になります。

```hlsl
static const uint h = 0xFFFFFFFFFFFFFFFFF;   // 16 進
static const int  o = 077777777777777777777; // 8 進
static const int  d = 999999999999999999999; // 10 進
```

収まっているものは報告しません。

```hlsl
static const uint a = 0xFFFFFFFF;   // 32 ビットぴったり
static const uint b = 4294967295;
static const int  c = 2147483647;
static const int  d = 0777;
```

## 誤検出だと思ったら

浮動小数のリテラルは対象にしません。
桁が多くても精度が落ちるだけで、上位の桁が捨てられるわけではありません。

16 進の判定は浮動小数の判定より先に行います。
`0xFFFFFFFF` は `F` で終わりますが、これは浮動小数の接尾辞ではありません。
実装の最初のバージョンはこの順序が逆で、16 進の桁あふれを 1 件も報告できていませんでした。

## なぜ字句解析ツールで見ないか

字句解析ツールは「リテラルとして読めること」だけを保証し、
値の妥当性は後段に委ねる作りになっています。
桁数の判定は意味の検査であり、こちら側の仕事です。
