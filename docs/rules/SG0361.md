# SG0361: 微分の型の書き方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、`IDifferentiable` の型の微分の型 (`typealias Differential = …;`) と、フィールドの `[DerivativeMember]` を正しくない形で書いている状態です。slangc はコンパイルの誤り (E30121・E31130・E30310・E31132・E30096・E30125) にします。

- 微分の型が自分でないのに、微分するフィールド (float・half・double とそのベクトル・行列と、その配列) に `[DerivativeMember]` も `no_diff` も書いていない。微分の型に同じ名前のフィールドがあっても、当てはまりません
- `[DerivativeMember(D.m)]` の m が、微分の型 D のフィールドでない
- 微分しない型 (int・bool など) のフィールドに `[DerivativeMember]` を書いた
- 関数の外の変数に `[DerivativeMember]` を書いた (型のフィールドにだけ書ける)

```slang
struct MyDiff : IDifferentiable
{
    typealias Differential = MyDiff;
    float dx;
}

struct MyType : IDifferentiable
{
    typealias Differential = MyDiff;
    float x;                           // [DerivativeMember(MyDiff.dx)] が必要
    [DerivativeMember(MyDiff.dy)]      // MyDiff に dy は存在しない
    float y;
    [DerivativeMember(MyDiff.dx)]      // int は微分しない
    int count;
}
```

`extension` で `IDifferentiable` に適合させた型も見ます (E30125)。型の定義の側では微分しない型の仮引数 (`struct V<T : __BuiltinArithmeticType>` の `T`) を使用するフィールドは、
`extension<T : __BuiltinFloatingPointType> V<T> : IDifferentiable` の制約で微分するようになっても、slangc が合成する `dzero`・`dadd` に入りません。
`extension` に `dzero` と `dadd` の両方を書いていない場合は、そのフィールドに報告します。型の定義に `where` の制約がある場合は見ません。

微分の型の微分は、その型自身でなければなりません (E30096)。`MyType` の微分の型 `D` に `typealias Differential = E;` (`E` は `D` でない) と書いた場合は、`MyType` の基底の `IDifferentiable` に報告します。

微分の型が自分 (`typealias Differential = MyType;`) の場合は、フィールドは自分のフィールドに当たるので、`[DerivativeMember]` は必要ありません。
微分するかどうかが型の名前で決まらないフィールド (構造体の型など) と、ファイルの外やジェネリックの微分の型は見ません。

## なぜ問題か

slangc は、型の微分を、フィールドごとに微分の型のフィールドへ当てて作ります。当てる先が決まらなければ、微分の型を作れません。

## 修正方法

微分するフィールドに `[DerivativeMember(D.m)]` で微分の型のフィールドを書くか、微分しない場合は `no_diff` を付けてください。
`extension` で適合させた型では、`extension` に `dzero` と `dadd` を書いてください。
