# HL0356: そのステージでは使用できない機能を使用しています

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

エントリポイントから直接または間接に呼び出される関数で、そのステージでは使用できない機能を使用している箇所です。

| 機能 | 使用できないステージ |
| --- | --- |
| `discard`・`clip` | ピクセルシェーダー以外のすべて |
| 微分 (`ddx`・`ddy`・`ddx_coarse`・`ddx_fine`・`ddy_coarse`・`ddy_fine`・`fwidth`) | 頂点・ジオメトリ・ハル・ドメインのシェーダー。FXC はコンピュートシェーダーも |
| LOD を指定しないサンプリング (テクスチャの `Sample`・`SampleBias`・`SampleCmp`・`CalculateLevelOfDetail`、DX9 の `tex2D(s, uv)`・`tex2Dbias`・`tex2Dproj` など) | 微分と同じ |

```hlsl
#pragma vertex vert
#pragma fragment frag

sampler2D _HeightMap;

float4 vert(float4 pos : POSITION, float2 uv : TEXCOORD0) : SV_POSITION
{
    pos.y += tex2D(_HeightMap, uv).r;      // 報告する。頂点シェーダーでは LOD を決められない
    return UnityObjectToClipPos(pos);
}
```

LOD を指定しないサンプリングは、隣のピクセルとの差 (微分) から LOD を決めます。ピクセルシェーダー以外には隣のピクセルがないので使用できません。

## なぜ問題か

コンパイルエラーになります。

- FXC: `X4532: cannot map expression to vs_5_0 instruction set`
- DXC: `Opcode Sample not valid in shader model vs_6_0.`、`Opcode Discard not valid in shader model cs_6_0.` など

## どう直すか

- サンプリングは、LOD を指定する形にします (`tex2D` → `tex2Dlod`、`Sample` → `SampleLevel`、`SampleCmp` → `SampleCmpLevelZero`)

  ```hlsl
  pos.y += tex2Dlod(_HeightMap, float4(uv, 0, 0)).r;
  ```

- `discard` と `clip` は、ピクセルシェーダーで呼び出してください
- 複数のステージで使用する関数の中にある場合は、ステージごとに関数を分けてください

## 環境による違い

コンピュートシェーダーの微分とサンプリングは、DXC ではシェーダーモデル 6.6 から使用できます (`[numthreads]` の大きさの条件があります)。
このルールは、コンピュートシェーダーでは FXC でコンパイルされる場合だけ報告します。メッシュと増幅のシェーダーの微分とサンプリングは見ません。

Slang では [SG0365](SG0365.md) になります。slangc は LOD を指定しないサンプリングをどのステージでも通すので、条件が違います。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- エントリポイントのステージが分からない場合 (ステージの決め方は [CF0302](CF0302.md) と同じです)
- エントリポイントから届かない関数の中の使用

結果を使用しない微分やサンプリングは、コンパイラが取り除くため誤りにならないことがあります。このルールはそれを区別しません。
