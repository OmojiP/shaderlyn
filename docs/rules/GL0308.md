# GL0308: 大きさの決まっていない配列です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、大きさを書かずに宣言した配列を、定数でない添字で引くか、`length()` で長さを求めている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(local_size_x = 64) in;

layout(binding = 0) buffer Data
{
    float values[];   // 最後のメンバーでないので、大きさが決まらない
    uint count;
};

void main()
{
    count = uint(values.length());   // length() を使えない
}
```

大きさを書かずに宣言した配列 (`float a[];`) は、定数の添字で引くと、使った一番大きな添字で大きさが決まります (glslang と同じ)。
定数でない添字で引くことと `length()` は、大きさが決まらないので使えません。

次のものは使えます。

- buffer のブロックの最後のメンバー (実行時に大きさが決まる配列)。定数でない添字も `length()` も使えます
  ただし、バッファの参照 (`buffer_reference`) の型の変数とメンバーの先のブロックの配列には `length()` を使えません
- uniform のブロックの最後のメンバーは、`GL_EXT_uniform_buffer_unsized_array` を有効にすれば定数でない添字で引けます
- サンプラー・イメージなどの配列と、uniform と buffer のブロックの配列は、`GL_EXT_nonuniform_qualifier` を有効にすれば定数でない添字で引けます。
  有効にしていなければ [GL0001](GL0001.md) で報告します

関数の外の変数、関数の中の変数、ブロックのメンバーを検査します。

ステージの layout で大きさが決まる入出力の配列も検査します。ジオメトリシェーダーの入力の配列 (`gl_in` と、大きさを書かない `in` の配列) は
`layout(triangles) in;` などで、テッセレーションの制御シェーダーの出力の配列 (`gl_out` と、大きさを書かない `out` の配列) は `layout(vertices = N) out;` で
大きさが決まります。それより前では、`length()` と定数でない添字を使えません (配列の大きさに書いた `gl_out.length()` も)。
同じ名前を大きさを付けて宣言し直していれば、使う位置より前の、最後の宣言で判断します。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

配列の大きさを書くか、実行時に大きさを決めたい配列を buffer のブロックの最後のメンバーにしてください。

```glsl
layout(binding = 0) buffer Data
{
    uint count;
    float values[];   // 最後のメンバー
};
```
