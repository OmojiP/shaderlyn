# HL0355: GetAttributeAtVertex に nointerpolation の入力でない値を渡しています

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

ピクセルシェーダーのエントリポイントで、`GetAttributeAtVertex` の 1 つ目の実引数に、`nointerpolation` を付けた入力でない値を渡している箇所です。
DXC でコンパイルされるコードだけを見ます (FXC はこの関数を持ちません)。

```hlsl
struct PSInput
{
    nointerpolation float4 color : COLOR;
    float4 uv : TEXCOORD0;
};

static float4 g;

float4 main(PSInput input, float4 normal : NORMAL) : SV_Target
{
    return GetAttributeAtVertex(input.color, 0)   // 報告しない
         + GetAttributeAtVertex(input.uv, 1)      // 報告する。nointerpolation がない
         + GetAttributeAtVertex(normal, 2)        // 報告する。nointerpolation がない
         + GetAttributeAtVertex(g, 0);            // 報告する。入力でない
}
```

報告するのは次のものです。

- `nointerpolation` を付けていない仮引数と、構造体のフィールド (構造体の仮引数に付けた場合は、そのフィールドのすべてに付けたものとして扱います)
- グローバル変数

## なぜ問題か

`GetAttributeAtVertex` は、三角形の頂点ごとの値を補間せずに読み取る関数です。補間する入力の値は読み取れないので、DXC がコンパイルの誤りにします。

- `nointerpolation` を付けていない入力: `Attribute COLOR must have nointerpolation mode in order to use GetAttributeAtVertex function.`
- グローバル変数: `attribute evaluation can only be done on values taken directly from inputs.`

## 修正方法

入力の宣言に `nointerpolation` を付けてください。

```hlsl
struct PSInput
{
    nointerpolation float4 uv : TEXCOORD0;
};
```

## 環境による違い

Slang では [SG0364](SG0364.md) になります。slangc は条件が違います (ベクトルの入力は `nointerpolation` を付けていなくても通し、入力を入れた局所変数は誤りにします)。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- エントリポイントの本体でない関数の中の呼び出し (DXC は関数を展開してから判断するため)
- 入力を入れた局所変数を渡す呼び出し (DXC は通します)
- エントリポイントのステージを特定できない場合 (ステージの決め方は [CF0302](CF0302.md) と同じです)

シェーダーモデル 6.0 以前では、`GetAttributeAtVertex` そのものを使用できません。このルールはシェーダーモデルを見ません。
