# GL0101: この修飾子はここに書けません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、修飾子を書けない場所に書いている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;

void main()
{
    in vec4 v;     // 記憶域の修飾子 (in / out / uniform など) は、関数の中の変数に付けられない
    color = v;
}
```

今は次のものを検査します (どれも glslang と同じ)。

- 関数の外の宣言にだけ付けられる修飾子 (`in`、`out`、`uniform`、`buffer`、`shared`、補間の `flat` / `smooth` / `noperspective`、`invariant` など) を、
  関数の中の宣言に付けたもの (glslang の「not allowed in nested scope」)
- 型の無い宣言 (`layout(triangles) in;`) にだけ書ける layout (`triangles`、`local_size_x`、`max_vertices`、`early_fragment_tests` など) を、変数やブロックに書いたもの
- 記憶域と合わない layout (`uniform` か `buffer` でない宣言の `offset` / `align` / `std140` / `binding`、出力でない宣言の `index` / `stream` / `xfb_*`、
  `in` でない宣言の `local_size_x`、`buffer` でない宣言の `buffer_reference` など)
- 型と合わない layout (変数の `std140` と `align`、ブロックの `offset`、イメージでない型のイメージの形式、ブロックでない型の `push_constant`、
  サブパスの入力でない型の `input_attachment_index`、`const` のスカラーでない宣言の `constant_id` など)
- ブロックのメンバーのパッキング (`std140` など)、in / out でないブロックのメンバーの `location`、パッキングが std140 / std430 / scalar でないブロックの `offset` / `align`
- 入力と出力の `bool`
- フラグメントシェーダーの出力の補助・補間の修飾子 (`flat out`、`sample out` など) と、行列・構造体・`double` の出力
- `flat` の無い、整数と `double` のフラグメントシェーダーの入力 (と ES の 3.00 の頂点シェーダーの出力)
- 修飾子の組み合わせ。補助の修飾子 (`centroid`・`patch`・`sample`) と補間の修飾子 (`flat`・`smooth`・`noperspective`) は 1 つずつしか書けず、
  `patch` と補間の修飾子は一緒に書けません。頂点シェーダーの入力には、補助・補間・メモリの修飾子と `invariant` を書けません
- 修飾子の順。デスクトップの 4.20 と ES の 3.10 より前は (`GL_ARB_shading_language_420pack` を有効にしない限り)、
  `precise`・`invariant`・補間・補助・記憶域・精度の順に書かなければなりません。仮引数の `const` は `in` / `out` より前です

```glsl
#version 330
out flat vec4 a;         // 補間の修飾子は記憶域 (out) より前に書く: flat out vec4 a;
smooth flat out vec4 b;  // 補間の修飾子は 1 つだけ
```

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

修飾子を外すか、宣言を関数の外へ出してください。関数の中の変数には、`const` と精度の修飾子 (`highp` など) を付けられます。
