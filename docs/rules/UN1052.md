# UN1052: 16 ビットの型を有効にしたパスの定数バッファに half があります

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

16 ビットの型を有効にした DXC でコンパイルされるコードで、定数バッファのメンバーを `half` / `min16float` / `min16int` / `min16uint` で宣言している箇所です。

```hlsl
#pragma require native16bit

CBUFFER_START(UnityPerMaterial)
    half4 _BaseColor;      // 報告する
    float4 _Tint;          // 正しい
CBUFFER_END
```

16 ビットの型が有効になるのは、`#pragma require native16bit` のパスと、
`multi_compile _ UNITY_DEVICE_SUPPORTS_NATIVE_16BIT` のキーワードが有効な構成です (DX11 以外)。

## なぜ問題か

DXC は `-enable-16bit-types` でコンパイルし、`half` を 2 バイトの `float16_t` にします。
定数バッファの `half4` は 8 バイトに詰められますが、Unity はマテリアルの値を 32 ビットの float で書き込みます。
シェーダーは別の値を読みます。

Unity 2022.3〜6.6 で、マテリアルの色を白 (1, 1, 1, 1) にして確かめた値です。

| | DX12 | Vulkan |
| --- | --- | --- |
| `half4` で宣言 | (0, 1.875, 0, 1.875) | (0, 0, 0, 0) |
| `float4` で宣言 | (1, 1, 1, 1) | (1, 1, 1, 1) |

DX12 の値は、`1.0f` (`0x3F800000`) の上下 16 ビットを half として読んだものです。

## どう直すか

定数バッファのメンバーは 32 ビットの型 (`float4` など) で宣言し、使うところで `half` に変換してください。

```hlsl
CBUFFER_START(UnityPerMaterial)
    float4 _BaseColor;
CBUFFER_END

half4 color = (half4)_BaseColor;
```

## 環境による違い

Unity の環境だけで動きます。どの構成が 16 ビットの型を使うかは、[シェーダーのコンパイラ](../guide/configuration.md#シェーダーのコンパイラ)の判定によります。
