# HL0004: #ifdef / #ifndef の後ろの記述は無視されます

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`#ifdef` / `#ifndef` の名前の後ろに、さらに記述がある行です。

```hlsl
#pragma multi_compile A0 A1 A2

#ifdef A0 || A1        // ← ここを報告する
    return albedo;
#else
    return half3(0, 0, 0);
#endif
```

## なぜ問題か

`#ifdef` と `#ifndef` が見るのは、直後の名前 1 つだけです。
後ろの記述は捨てられるので、上の例は `#ifdef A0` と同じ意味になります。
`A1` を有効にした構成では、この分岐は外れます。

コンパイルは通るので、書いた本人は「A0 か A1 のとき」のつもりのまま気づけません。

捨てられた `A1` は条件で参照されていないので、
[HL0331](HL0331.md) が「宣言されていますが、条件のどこにも現れません」と報告します。
ただしそちらは `#pragma` の宣言を指すため、原因の行が分かりません。
この指摘は書いた行そのものを指します。

## どう直すか

複数の名前を条件にするときは、`#if` と `defined()` を使います。

```hlsl
#if defined(A0) || defined(A1)
```

名前を `||` / `&&` だけでつないだ `#ifdef` には、この形へ置き換える直しを添えます
(VS Code では電球のメニューから適用できます)。

`#ifndef` には直しを添えません。
`#ifndef A0 || A1` が「どちらも定義されていない」のか「どちらかが定義されていない」のかは、
書かれた行から読み取れないためです。意図に合わせて書き直してください。

```hlsl
#if !defined(A0) && !defined(A1)   // どちらも定義されていない
#if !defined(A0) || !defined(A1)   // どちらかが定義されていない
```
