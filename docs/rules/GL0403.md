# GL0403: その宣言には使えない型です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、その宣言には使えない型を使っている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(binding = 0) uniform sampler2D albedo;
layout(location = 0) in vec2 uv;
layout(location = 0) out vec4 color;

void main()
{
    sampler2D s = albedo;   // サンプラーの局所変数は作れない
    color = texture(s, uv);
}
```

次のものを報告します (どれも glslang と同じ)。

- サンプラー・イメージ・テクスチャの型 (`sampler2D`、`image2D`、`texture2D` など) の、uniform でない変数 (関数の外と中)。
  これらの型は uniform の変数と仮引数にしか使えません。`GL_ARB_bindless_texture` を有効にしていれば報告しません。`atomic_uint` も同じです
- サンプラーかイメージをメンバーに持つ構造体の、uniform でない変数
- `void` の変数と、名前を付けた `void` の仮引数 (`int f(void v)`。`int f(void)` は良い)
- 配列でない、ジオメトリシェーダーの入力・テッセレーションの制御シェーダーの `patch` でない入力と出力・評価シェーダーの `patch` でない入力 (変数とブロック)。
  これらは頂点ごとの配列 (`in vec2 uv[];`) でなければなりません。`layout(passthrough)` は除きます
- 構造体とブロックの中の構造体の定義 (`struct S { struct T { int a; } t; };`)
- ブロックのメンバーのサンプラー・イメージ・`atomic_uint` と、それを含む構造体 (`GL_ARB_bindless_texture` のサンプラーを除く)
- 精度の文 (`precision mediump float;`) の型。書けるのは `float`・`int`・サンプラーとイメージの型・`atomic_uint` だけで、
  `uint`・`bool`・ベクトル・行列・構造体・配列 (`precision highp float[2];`) は書けません。`atomic_uint` の精度は `highp` だけです
- `out` / `inout` の、サンプラー・イメージ・`atomic_uint` の仮引数 (`void f(out sampler2D s)`)
- ES の、精度の修飾子を付けた `bool` と `bvec2` ～ `bvec4` の変数 (`mediump bool b;`)
- shared の変数とブロックのメンバーの協調行列 (`coopmat`、`fcoopmatNV` など)
- uniform でない (関数の中の変数を含む) 加速構造 (`accelerationStructureEXT`) とテンソル (`tensorARM`) の変数
- 大きさが 0 以下の配列 (`float f[-2];`)
- 特殊化の定数で大きさを決めた配列の初期値 (代入と比較は [GL0301](GL0301.md) が報告します)
- 大きさを書かない配列の変数の、大きさの決まっていない配列や空の初期化子 (`{ }`) での初期化
- メッシュシェーダーの `perviewNV` の出力で、ビューの次元 (ブロックのメンバーは一番外、ほかは外から 2 番目の次元) が無いものと、その大きさが `gl_MaxMeshViewCountNV` でないもの

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

サンプラーは uniform の変数のまま使うか、仮引数で関数に渡してください。

```glsl
vec4 sampleAlbedo(sampler2D s, vec2 uv)
{
    return texture(s, uv);
}

void main()
{
    color = sampleAlbedo(albedo, uv);
}
```
