# GL0003: GLSL のプリプロセッサの指令の誤りです

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、glslang が誤りにするプリプロセッサの指令の書き方です。

今は次のものを検査します (glslang 16.6.0 のプリプロセッサと同じ)。

- ES (`#version 100`、`#version 300 es` など) で、`#if` / `#elif` の式に定義されていないマクロを書いたもの

```glsl
#version 300 es
precision mediump float;
out vec4 o;

#if USE_FOG          // USE_FOG はどこでも定義されていない
#endif

void main() { o = vec4(1.0); }
```

`&&` の左が 0 のときと、`||` の左が 0 でないときの右の項は評価しないので、報告しません。
`#if defined(USE_FOG) && USE_FOG` は書けます。

## なぜ問題か

C と、ES でない GLSL では、`#if` の式の定義されていない名前は 0 として読みます。
ES ではそれが誤りで、glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

マクロを定義するか、`defined(…)` で定義されているかを先に確かめてください。

```glsl
#if defined(USE_FOG) && USE_FOG
#endif
```

## 誤検出だと思ったら

コンパイラに渡すマクロ (glslang の `-D` など) は、`--define 名前=値` (設定ファイルは `defines`) で渡してください。渡さないと、定義されていないマクロとして読みます。
