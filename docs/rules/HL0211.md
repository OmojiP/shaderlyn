# HL0211: レジスタが重複しています

分類: Correctness / 既定の重要度: エラー

対応する HLSL のコード: 3115 (`ERR_CONFLICTING_REGISTER_SEMANTICS`)

## 何を検出するか

同じレジスタを 2 つ以上の宣言が指定している状態です。

```hlsl
Texture2D _A : register(t0);
Texture2D _B : register(t0);   // t0 は _A が使っている
```

レジスタの種類ごとに別の空間です。`b0` と `t0` は衝突しません。

```hlsl
Texture2D    _A : register(t0);
SamplerState _S : register(s0);   // 種類が違うので問題ない
Texture2D    _B : register(t1);
```

## なぜ問題か

どちらが使われるかは保証されず、コンパイルに失敗します。
リソースを増やしたときに番号を振り忘れると起きます。

## 誤検出だと思ったら

空間の指定を伴う形 (`register(t0, space1)`) は対象にしません。
同じ番号でも空間が違えば衝突しないためです。

同じ名前の宣言が複数の Pass に現れる場合は衝突として扱いません。
同じ 1 行が各 Pass に差し込まれているだけです。

Pass (コードブロック) ごとに判定し、その Pass のコードが使っているリソースどうしだけを比べます。
コンパイラは使われていないリソースを取り除いてから割り当てるので、一方が使われていなければ衝突しません。
HDRP の CopyStencilBuffer.shader は、共通コード片で `_HTile` と `_StencilBufferCopy` をどちらも `register(u1)` に宣言し、
Pass ごとにどちらか一方だけを使っています。別の Pass で同じ番号を使うのも、別々にコンパイルされるので衝突しません。

同時には存在しない宣言どうしも衝突しません。

```hlsl
#ifdef _B
Texture2D _T1 : register(t0);
#else
Texture2D _T2 : register(t0);   // 報告しない。1 つの構成には 1 つしか無い
#endif
```
