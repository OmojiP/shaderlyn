# HL0321: include を解決できません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

そのファイルに書かれた `#include` のうち、
ほかの `#include` は解決できているのに指定されたパスだけ見つからなかったものです。

指摘はそのパスが書かれた行に出ます。

```hlsl
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"  // 解決できた
#include "Assets/ShaderLibrary/Commmon.hlsl"                                      // ← ここを報告する
```

## なぜこの 2 つの条件が付くのか

1 件も解決できていないときは報告しません。

Unity をインストールしていない環境や、`--unity-project` を指定していない場合、
パッケージ配下のヘッダは軒並み解決できません。
それらを全件報告すると出力が埋まり、ほかの指摘が読めなくなります。
これは「パスの書き方が誤っている」のではなく「環境が揃っていない」ことであり、
その事実は [SL0002](SL0002.md) が伝えます。

逆に、ほかの include は解決できているのに 1 つだけ解決できないなら、
原因は環境ではなくそのパスにある可能性が高いので報告します。

取り込んだヘッダの中の `#include` は報告しません。
Unity のヘッダが別のパッケージを参照していて、
そのパッケージがプロジェクトに入っていないことはよくあります。
利用者に直しようがない指摘は出しません。

> Unity 同梱の 209 件で測ったところ、この 2 つの条件によって指摘は 0 件になりました。
> 解決できない include はありましたが、いずれも Unity のヘッダの中に書かれたものでした。

## なぜ問題か

解決できない include があると、その中で定義されるマクロや型が未知のままになります。
その結果、正しく書かれたコードに対して構文エラー ([HL0001](HL0001.md)) が大量に出たり、
uniform の一覧が不完全になって対応検査が丸ごと見送られたり ([SL0002](SL0002.md)) します。

## どう直すか

まずパスの書き方を確認してください。
ほかの include が解決できている以上、探索の仕組み自体は働いています。

プロジェクトの中のヘッダは、`Assets/` から始まる形で書けば解決できます。

```hlsl
#include "Assets/ShaderLibrary/Common.hlsl"
```

`../` を含む相対パスでも引けます。

```hlsl
#include "../ShaderLibrary/Common.hlsl"
```

相対パスの基準は、取り込み元のシェーダーではなく、**その `#include` が書かれているファイルの位置**です。
ヘッダの中に書いた `#include` は、そのヘッダのある場所から数えます。

ファイル名だけで書けるのは、`#include` を書いたファイルと同じフォルダーにある場合だけです。
Unity にはプロジェクト全体の探索パスという設定が無いため、別のフォルダーにあるヘッダを
ファイル名だけで書くと、Unity 自身もコンパイルに失敗します。

プロジェクトの外に置いたヘッダを取り込んでいる場合は `--include-path` を足してください。

```
shaderlyn Assets/Shaders --unity-project . --include-path ../SharedShaderLibrary
```

Unity のシェーダーは次の形式でパッケージを参照します。

```hlsl
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
```

この `Packages/` は実在するフォルダーではなく、Unity がパッケージの実体へ読み替える接頭辞です。
`--unity-project` を指定すると、`Library/PackageCache` と `Packages` から実体を探します。

## エディタでの扱い

VS Code 拡張では、`#include` のパスの上で F12 (定義へ移動) または Ctrl + クリックすると、
実際に読み込まれたファイルが開きます。
書かれたパスではなく解決後のパスへ飛ぶため、`Packages/...` の形でも開けます。

解決できていない場合は何も開きません。飛べない先を開こうとすると、
「ファイルが見つからなかったため、エディターを開くことができませんでした」というタブが出るだけです。
