# GL0002: このステージでは使用できません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、ファイルの拡張子で決まるステージでは使用できない機能を使用している状態です。glslang はコンパイルの誤りにします。

```glsl
// a.vert (頂点シェーダー)
#version 450
shared float cache[64];   // shared はコンピュートシェーダー・メッシュシェーダー・タスクシェーダーのもの

void main() { gl_Position = vec4(cache[0]); }
```

今は次のものを検査します (どれも glslang 16.6.0 の文法の規則と同じ)。

- ステージの限られた修飾子 (`shared`、`patch`、`attribute`、レイトレーシングの `rayPayloadEXT` / `hitAttributeEXT` など、メッシュシェーダーの `perprimitiveEXT` など)
- フラグメントシェーダーにしか存在しない型 (`subpassInput` など)
- 頂点シェーダーとコンピュートシェーダーの入力のブロック (`in Block { … };`)、フラグメントシェーダーとコンピュートシェーダーの出力のブロック。
  コンピュートシェーダーの関数の外の `in` / `out` の変数 (`layout(local_size_x = 64) in;` は書けます)
- そのステージに存在しない組み込みの関数と変数 (テッセレーションの評価シェーダーの `barrier()`、頂点シェーダーの `dFdx()`、フラグメントシェーダーの `gl_VertexIndex` など)。
  同じバージョンの別のステージにあるものだけを、このルールで報告します。どのステージにも存在しないものは [GL0001](GL0001.md) です

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## 修正方法

その機能を使用できるステージのファイルへ移すか、使用しない書き方にしてください。

## 誤検出だと思ったら

ステージはファイルの拡張子で決めます (glslang と同じ)。`.glsl` の前にステージの拡張子があれば (`shadow.vert.glsl`)、そのステージです。
拡張子と中身のステージが合っているか確認してください。
