# CF0401: 実引数を仮引数の型へ変換できません

分類: Correctness / 既定の重要度: エラー / 0.3.1 より前の ID: HL0340

## 何を検出するか

渡している値の成分が、仮引数の型より少ない呼び出しです。

```hlsl
#pragma multi_compile _ SHADER_DEBUG

#ifdef SHADER_DEBUG
half4 sampleTexture(float2 uv)  { ... }
#else
half4 sampleTexture(float3 uvw) { ... }
#endif

half4 frag(Varyings IN) : SV_Target
{
#ifdef SHADER_DEBUG
    return sampleTexture(IN.uv);   // float2 → float2。問題ない
#else
    return sampleTexture(IN.uv);   // float2 → float3。成分が不足している
#endif
}
```

候補はその構成に存在する宣言だけに絞ります。
条件を見ないと、`#else` の呼び出しに `float2` の多重定義が候補として混ざり、
合わない呼び出しが合っているように見えます。

## なぜ問題か

HLSL は変換の向きで扱いが違います。

| 向き           | 例                  | 扱い              |
| -------------- | ------------------- | ----------------- |
| 成分を減らす   | `float3` → `float2` | コンパイルできる (警告 X3206) |
| スカラーを複製 | `float` → `float3`  | コンパイルできる |
| 成分を増やす   | `float2` → `float3` | エラー            |

このルールが報告するのは最後の 1 行だけです。
上の 2 つは正しいコードなので、報告しません。

### `out` / `inout` では規則が違う

書き戻す仮引数では、成分を減らす向きも許されません。
書き戻す先が不足するためです。形が一致していなければなりません。

```hlsl
void split(float2 uv, out float3 rgb) { ... }

float2 small;
split(uv, small);   // float3 を float2 へは書き戻せない
```

### 行列とベクトルは互いに渡せない

```hlsl
half4 shade(float3x3 m) { ... }

float3 v;
shade(v);   // ベクトルを行列へは渡せない
```

スカラーはどちらへも複製されるので、これは許されます。

## どう直すか

不足している成分を明示してください。

```hlsl
return sampleTexture(float3(IN.uv, 0));
```

条件によって仮引数の型が変わる関数の場合は、
呼ぶ側にも同じ条件を付けるか、型を揃えてください。

## 構造体 (HLSL 2021)

HLSL 2021 では、構造体が関わる暗黙の変換も見ます (DXC で確認した規則です)。

```hlsl
struct P { float x; };
struct Q { float x; };
struct D : P { float z; };

P p = q;        // 報告する。別の構造体 (メンバーが同じでも)
P p = d;        // 正しい。派生した構造体は基底へ入る
P p = 0;        // 報告する。数は構造体へ暗黙に変換されない
P p = (P)0;     // 正しい
float f = p;    // 報告する。構造体は数へ暗黙に変換されない
```

template の構造体 (`Box<float4>`) は、型引数が違えば別の型ですが、名前だけでは区別できないので見ません。
Unity の環境 (HLSL 2018) では、FXC の規則を確認していないので見ません。

要素の構造体が違うバッファーも別の型です。関数の実引数に、要素の構造体が違うバッファーの変数を渡すと報告します (Slang も同じです)。

```hlsl
float Sum(StructuredBuffer<P> items) { ... }

StructuredBuffer<Q> q;
StructuredBuffer<D> d;
float a = Sum(q);   // 報告する。要素の構造体が違う
float b = Sum(d);   // 報告する。派生した構造体でも、バッファーは基底のバッファーへ入らない
```

## 構造体 (GLSL)

GLSL の暗黙の変換は数値の型にしかありません。構造体の仮引数には同じ構造体の値しか渡せず、数値の仮引数に構造体の値は渡せません。
テンソル (`tensorARM`) の仮引数も同じです。型の引数を書かない `tensorARM` はどのテンソルも受け取りますが、要素の型を書いたもの (`tensorARM<int>`。階数を書かなければ 1) は、同じ要素の型と階数のテンソルしか受け取りません。

```glsl
struct S { float a; };
float f(S s) { return s.a; }

float c = f(1.0);   // 報告する。float は S へ変換されない
```

## Slang

Slang では、成分を減らす暗黙の変換も誤りです ([CF0410](CF0410.md) の「Slang の成分を減らす変換」と同じ)。
`out` / `inout` の仮引数には、要素の型も同じ値を渡さなければなりません。暗黙の変換が必要な値を渡すと、slangc は「argument must be l-value」(E30047) にします。
同じ大きさの符号付きと符号無しの整数 (`int` と `uint`) は通ります。

```slang
void a(out float x) { x = 0; }
void b(double d, int i, float f)
{
    a(d);   // 報告する。double を out float に渡せない
    a(i);   // 報告する
    a(f);   // 正しい
}
```

多重定義した関数は、どの宣言も実引数を受け取れないときに報告します (E39999)。ジェネリックの宣言は、型の仮引数を実引数から決め、制約 (`<T : IA>`・`where T : IA`・`where T == int`) を確認します。決められないことのある宣言 (型が不明な実引数、基底の構造体を持つ構造体など) は、受け取るものとします。

```slang
interface IA {}
interface IB {}
struct W { int v; }
T h<T : IA>(T x) { return x; }
T h<T : IB>(T x) { return x; }
void use(W w) { h(w); }   // 報告する。W は IA にも IB にも適合しない
```

ジェネリックの型の、型引数で決まる適合 (`extension<T : IScalar> Shape<T> : IShaped`) は、実引数の型の型引数 (`Shape<T> left` の T) で確認します。
T が外の関数の型の仮引数の場合は、その制約から届くインターフェイスにだけ適合します。
ジェネリックのメソッド (`d.doThing(W())`) も、どの宣言の型の仮引数の制約にも、適合するものの決まった構造体が適合しないときに報告します。

インターフェイスの型の `out`・`inout` の仮引数 (`inout IThing x`) に、具体的な型の値を渡すものも報告します (E30077)。
インターフェイスの型の値を渡すか、仮引数をジェネリック (`T x` と `where T : IThing`) にしてください。

```slang
interface IThing { void g(); }
struct MyThing : IThing { void g() {} }
void f(inout IThing x) { x.g(); }
void use(MyThing concrete) { f(concrete); }   // 報告する
```

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 宣言を 1 つも参照できない関数。
  組み込み関数の形は持っていないので、表に無い名前は対象外です
- 受け付ける宣言が 1 つでもある場合。
  その構成に存在する候補のどれか 1 つが受け付ければ、その呼び出しは成り立ちます
- 実引数の型が不明な場合。
  型が不明なことは「合っていない」ことの証拠になりません
- 配列。要素の型と長さは [CF0405](CF0405.md) が見ます
- 成分の数が不明な型。構造体やテクスチャは対象外です

引数の個数が合わない呼び出しは [CF0402](CF0402.md) が報告します。
