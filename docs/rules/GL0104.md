# GL0104: layout に要る指定がありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、宣言に要る `layout(…)` の指定を書いていない状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
in vec4 color;                    // SPIR-V を作るとき、入力と出力には location が要る
layout(location = 0) out vec4 result;

uniform Params { vec4 tint; };    // SPIR-V を作るとき、uniform と buffer のブロックには binding が要る

void main() { result = color * tint; }
```

今は次のものを検査します。

- SPIR-V を作るとき ([`glsl: target`](../guide/configuration.md#glsl) が Vulkan か、`spirv` を書いたとき) の、利用者の入力と出力の `location`
- SPIR-V を作るときの、uniform と buffer のブロックの `binding` (`push_constant` などのブロックを除く)
- Vulkan 向けの、サンプラー・テクスチャ・イメージの `binding`
- アトミックカウンター (`atomic_uint`) の `binding`
- サブパスの入力 (`subpassInput`) の `input_attachment_index`
- ES の、`r32f` / `r32i` / `r32ui` 以外の形式を付けたイメージの `readonly` か `writeonly`
- `tileImageEXT` の変数の `location`
- `GL_EXT_post_depth_coverage` の `layout(post_depth_coverage) in;` に要る `layout(early_fragment_tests) in;` (main の位置で報告します)
- `GL_KHR_compute_shader_derivatives` を有効にした計算・タスク・メッシュのシェーダーの、`derivative_group_quadsKHR` か `derivative_group_linearKHR` (ファイルの終わりで報告します。微分の関数 `dFdx` などより前に要ります)
- `derivative_group_quads*` の、2 の倍数でない `local_size_x` / `local_size_y` と、`derivative_group_linear*` の、4 の倍数でないワークグループの大きさ

計算シェーダーで、ワークグループの大きさ (`layout(local_size_x = …) in;`。`local_size_x_id` などの特殊化の定数も) を宣言する前に `gl_WorkGroupSize` を読んだものも報告します。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

文が示す指定を書いてください。

```glsl
layout(location = 0) in vec4 color;
layout(binding = 0) uniform Params { vec4 tint; };
```

## 誤検出だと思ったら

`location` と `binding` をコンパイラに決めさせているなら (glslang の `--auto-map-locations` / `--auto-map-bindings`、glslc の `-fauto-map-locations` / `-fauto-bind-uniforms`)、
設定ファイルに書いてください。

```yaml
glsl:
  target: vulkan1.3
  auto-map-locations: true
  auto-map-bindings: true
```
