# SG0365: エントリポイントから、そのステージでは使用できない機能に届きます

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

エントリポイントから直接または間接に呼び出される関数で、そのステージでは使用できない機能を使用しているものです。
slangc と同じく、エントリポイントの名前の位置に報告し、使用した箇所をメッセージに書きます。

| 機能 | 使用できないステージ |
| --- | --- |
| `discard`・`clip` | フラグメントシェーダー以外のすべて (レイトレーシングのステージを含む) |
| 微分 (`ddx`・`ddy`・`ddx_coarse`・`ddx_fine`・`ddy_coarse`・`ddy_fine`・`fwidth`) | 頂点・ジオメトリ・ハル・ドメインのシェーダー |
| ステージを 1 つだけ書いた `[require(fragment)]` などの関数 | 書いたステージ以外のすべて (`[require]` を 2 つ書いた関数は見ない) |

```slang
void test()
{
    discard;
}

[shader("compute")]
[numthreads(1, 1, 1)]
void main()   // 報告する。コンピュートシェーダーから discard に届く
{
    test();
}
```

## なぜ問題か

slangc がコンパイルの誤り (`E36107: unavailable features in entry point`、`E36100: conflicting capability requirement` など) にします。
`[require(…)]` は、関数を使用できる環境 (能力) を指定する属性です。ステージの名前を書くと、そのステージでしか使用できません。

## 修正方法

- `discard` と `clip` は、フラグメントシェーダーで呼び出してください
- 複数のステージで使用する関数の中にある場合は、ステージごとに関数を分けてください

## 環境による違い

slangc 2026.19 で確認した条件です。

- LOD を指定しないサンプリング (`Sample` など) は、slangc はどのステージでも通します。HLSL の [HL0356](HL0356.md) とは違い、報告しません
- 微分は、レイトレーシングとメッシュのステージでは slangc が通します。コンピュートシェーダーは `[numthreads]` の大きさで決まるため、見ません

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- エントリポイントのステージを特定できない場合 (`-stage` のように、コマンドラインだけで指定したステージは参照できません)
- エントリポイントから届かない関数の中の使用
- ステージでない能力 (`[require(hlsl)]`・`[require(spvRayTracingKHR)]` など) の `[require(…)]` による誤り (コンパイル先で決まるため)
