# GL0313: 実引数の修飾子が仮引数と合いません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、サンプラーかイメージの変数を、修飾子の合わない仮引数に渡している状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(local_size_x = 1) in;
layout(binding = 0, rgba8) uniform coherent writeonly image2D target;

void store(writeonly image2D image, ivec2 p) { imageStore(image, p, vec4(1.0)); }

void main()
{
    store(target, ivec2(0));                // coherent を外して渡している
    vec4 v = imageLoad(target, ivec2(0));   // writeonly のイメージは imageLoad に渡せない
}
```

次のものを報告します (どれも glslang と同じ)。

- メモリの修飾子 (`coherent`・`devicecoherent` などの `coherent` 系・`volatile`・`readonly`・`writeonly`・`nontemporal`) を持つ変数を、
  その修飾子を持たない仮引数に渡すこと。`coherent` 系は、より広い範囲の修飾子を持つ仮引数には渡せます (`workgroupcoherent` の変数を `coherent` の仮引数へ)。
  `restrict` は外して渡せます
- 組み込みのイメージの関数では、`imageLoad` に `writeonly` の、`imageStore` に `readonly` の、アトミックの関数 (`imageAtomicAdd` など) にどちらかのイメージを渡すこと
- 利用者の関数に、イメージの形式 (`layout(rgba8)` など) が仮引数と違うイメージを渡すこと。`writeonly` の仮引数には、どちらかが形式を書いていなければ渡せます

実引数は、変数と仮引数の名前 (とそれを添字で引いたもの) だけを見ます。利用者の関数は、実引数の数の合う宣言が 1 つだけのときに見ます。

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。
修飾子を外して渡すと、関数の中でその性質 (メモリの見え方、読み書きの向き) が守られなくなるためです。

## どう直すか

仮引数にも同じ修飾子と形式を付けてください。

```glsl
void store(layout(rgba8) coherent writeonly image2D image, ivec2 p) { imageStore(image, p, vec4(1.0)); }
```
