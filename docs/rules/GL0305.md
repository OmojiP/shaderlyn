# GL0305: ここでは呼べない組み込み関数です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、呼べる場所の決まった組み込み関数を、その場所の外で呼んでいる状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(vertices = 4) out;

void main()
{
    if (gl_InvocationID == 0)
        barrier();      // if の中では呼べない

    barrier();          // これは良い
}
```

今は次の関数を検査します (どれも glslang と同じ)。

- テッセレーションの制御シェーダーの `barrier()`
- `beginInvocationInterlockARB()` と `endInvocationInterlockARB()` (`GL_ARB_fragment_shader_interlock`)

### barrier と interlock の呼び出し場所

これらの関数は、次の場所に書かなければなりません。

- `main` の中 (ほかの関数の中は不可)
- 流れを分ける文の外。if の枝、while・do・for (条件を含む)、switch の本体、`?:` の枝の中は不可。
  if と switch の条件、`?:` の条件は流れを分ける文に含みません
- `main` の `return;` より後ろでない所

`beginInvocationInterlockARB()` と `endInvocationInterlockARB()` は、ファイルの中でそれぞれ 1 回だけ、begin を end より前に呼びます。

### Vulkan のサンプラー構築式

Vulkan の GLSL で、テクスチャとサンプラーから作るサンプラーの値 (`sampler2D(t, s)`) も、使う場所 (組み込み関数の実引数など) に直接書かなければなりません。
利用者の関数の実引数、`?:` の枝、カンマの演算子の項には書けません。

```glsl
vec4 sampleIt(sampler2D s2, vec2 uv) { return texture(s2, uv); }

void main()
{
    color = texture(sampler2D(t, s), uv);    // 良い
    color = sampleIt(sampler2D(t, s), uv);   // 利用者の関数には渡せない
}
```

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。
テッセレーションの制御シェーダーの `barrier()` は、すべての呼び出しが同じ所で待ち合わせるため、一部の呼び出しだけが通る場所には書けません。

## どう直すか

`main` の一番外の文の並びに移してください。条件によって処理を分けたいときは、`barrier()` の前後で分けます。

```glsl
void main()
{
    if (gl_InvocationID == 0)
        gl_TessLevelOuter[0] = 4.0;

    barrier();
}
```
