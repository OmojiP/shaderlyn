# HL0313: その構成に存在しない構造体メンバー

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

参照している構造体のメンバーが、その構成には宣言されていない状態です。

```hlsl
#pragma multi_compile _ SHADER_DEBUG

struct Varyings
{
    float4 positionHCS : SV_POSITION;
    float2 uv : TEXCOORD0;
#ifdef SHADER_DEBUG
    float4 debugColor : COLOR;      // SHADER_DEBUG のときだけある
#endif
};

half4 frag(Varyings IN) : SV_Target
{
#ifdef SHADER_DEBUG
    return IN.debugColor;           // 問題ない
#else
    return IN.debugColor;           // ここには無い
#endif
}
```

メンバーがある条件は `SHADER_DEBUG`、参照する条件は `!SHADER_DEBUG` です。
この 2 つは同時に成り立たないため、参照するときにはメンバーがありません。

## なぜ問題か

その構成ではコンパイルに失敗し、シェーダーが使えなくなります。

`#ifdef` で囲んだメンバーを参照する側にも同じ条件を付ける、
という対応が崩れたときに起きます。
条件を後から書き換えたり、参照する行を別の分岐へ動かしたりすると紛れ込みます。

Unity はシェーダーを必要になった時点でコンパイルするので、
そのシンボルの組み合わせが実際に使われるまで表面化しません。

## どう直すか

条件を揃えてください。次のどちらかです。

- 参照する側を、メンバーがある条件の中へ入れる
- メンバー側の条件を、参照する側を覆うように広げる

条件が複雑で追いきれない場合は、
`--inspect` で構文木を開いてください。
ノードごとに `#if <条件>` のラベルが付いています。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 利用者が書いた構造体でない場合 (Unity や外部パッケージのヘッダの構造体)。
  指摘しても直しようがありません。利用者が書いて取り込んだヘッダの構造体は対象です
- 参照している式の型が分からない場合。
  型が分からないことは「メンバーが無い」ことの証拠になりません
- 条件が付いていないメンバー。
  無条件のメンバーはどの構成にもあります。
  そもそも存在しないメンバーの参照は [HL0312](HL0312.md) が報告します
- 出現条件が分からない場合。
  `#if` が構文の単位をまたいでいると条件を追えません
