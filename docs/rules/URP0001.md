# URP0001: プロパティがマテリアル定数バッファに含まれていません

分類: Performance / 既定の重要度: 警告

## 何を検出するか

`Properties` に対応する uniform が HLSL 側で宣言されているのに、
その宣言が `CBUFFER_START(UnityPerMaterial)` … `CBUFFER_END` の外にある状態です。

検査するのは「uniform の宣言がどこにあるか」であって、
「`Properties` の項目が定数バッファに列挙されているか」ではありません。
`Properties` にあっても HLSL で uniform を宣言していない項目は、
バインドされる値を持たないので互換性に関係しません。

テクスチャとサンプラは定数バッファに入れられないため対象外です。
`[PerRendererData]` が付いたプロパティも対象外です。

Pass ごとに判定します。1 つの Pass でもバッファの外に宣言していれば報告します。

## なぜ問題か

SRP Batcher が無効になります。エラーにはならず、ただ遅くなります。

SRP Batcher は「マテリアルごとの値がすべて 1 つの定数バッファに収まっている」ことを
前提に、描画呼び出しをまとめます。
1 つでも外れていると、そのシェーダーはバッチの対象から丸ごと外れます。

コンパイルは通り、描画結果も変わりません。
フレームデバッガを開いて `SRP Batch` ではなく `Draw Mesh` が並んでいるのを見るまで、
気づく機会がありません。

## どう直すか

```hlsl
// 誤り: _Smoothness がバッファの外にある
half _Smoothness;

CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
    half4 _BaseColor;
CBUFFER_END

// 正しい
CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
    half4 _BaseColor;
    half _Smoothness;
CBUFFER_END
```

すべての Pass で中身と順序を一致させてください。
Pass ごとに定数バッファの構成が違う場合も SRP Batcher は無効になります。
共通コード片 (`HLSLINCLUDE`) にまとめて書くのが確実です。

テクスチャそのものはバッファの外に置き、
スケールとオフセット (`_ST`) だけをバッファへ入れます。

```hlsl
TEXTURE2D(_BaseMap);
SAMPLER(sampler_BaseMap);

CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
CBUFFER_END
```

## 誤検出だと思ったら

このルールは、次の場合に発火しません。

- シェーダーが URP / SRP Core のヘッダを取り込んでいない場合。
  Built-in パイプライン向けのシェーダーに SRP の規約を当てはめるのは誤りなので、
  `--profile urp` を指定していても、シェーダー自身の `#include` を確認してから適用します。
  HDRP のヘッダを取り込んでいるシェーダーも、URP プロファイルの対象外になります
- マテリアル定数バッファが 1 つも存在しない場合。
  SRP Batcher に対応させるかどうかはシェーダーの設計判断であり、
  全プロパティを列挙して指摘しても直し方の指示になりません
- 依存関係を解決できていない場合 (SL0002 を参照)
- その Pass の、どの構成でも解析しない `#if` の領域 (`SHADER_API_*` など環境の条件の中や、取り込んだヘッダの非活性領域)やマクロ定義の中にその名前が現れる場合
  (別の構成ではバッファに入っている可能性があります)。別の Pass の領域は見ません

意図的に別の定数バッファへ分けている設計 (Unity のテレイン用シェーダーは
`_Terrain` という独自のバッファを使います) では、この指摘は該当しません。
その場合は抑制してください。
