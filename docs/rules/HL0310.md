# HL0310: 宣言されていない識別子です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

値として使っている名前が、どこにも宣言されていない状態です。

```hlsl
half4 frag() : SV_Target
{
    return undeclaredName;   // どこにも宣言が無い
}
```

スペルミスか、宣言しているヘッダの取り込み漏れです。

## この検査が働く条件

取り込めなかったヘッダが 1 つでもあると、この検査は行いません。

そこにある宣言が見えないまま「宣言されていない」と言うことになるためです。
その場合は [SL0002](SL0002.md) が出ます。

Unity 6000.0.60f1 に同梱の `.shader` 209 本では、201 本で依存が揃い、
10,057 個の識別子を調べて 1 件も報告しませんでした (`UnityCorpusTests` で測定)。

## 呼び出しの対象も見る

```hlsl
float a = saturat(uv.x);   // saturate のスペルミス
```

組み込み関数の名前は
[Intrinsic Functions](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-intrinsic-functions)
の一覧を持っています。
シェーダーモデル 6 以降の波動関数と量子化の関数は、あの表に載っていないので足してあります。

表に無い名前が出たら、それは表の不足です。報告しないのではなく表へ足してください。

## 宣言として数えるもの

- 変数・仮引数・関数・構造体・定数バッファの宣言。このファイルに書いた宣言も、取り込んだヘッダの宣言も、
  同じ Pass (コンピュートシェーダーなら同じカーネル) のものだけを数えます。
  別の Pass が取り込んだヘッダの宣言は、取り込んでいない Pass からは見えません
- レイトレーシング (DXR) の組み込み関数と、定義済みの定数 (`HIT_KIND_*`、`RAY_FLAG_*`)
- `#define` で定義されたマクロ。ただし、マクロの名前が展開されずに識別子のまま残っている位置では、
  その構成ではそのマクロは定義されていないものとします (定義されていれば展開されているはずです)
- `#pragma shader_feature` / `multi_compile` / `dynamic_branch` で宣言されたシンボル
- `#if` の非活性領域のうち、**どの構成でも解析されない領域**に現れた名前。
  `SHADER_API_*` のような環境の条件は 1 通りにしか解かないため、その裏側で宣言される名前は見えません。
  シンボルの `#ifdef` の中は、そのシンボルを有効にした構成で解析されるので、ここには含めません。
  既定の構成で使っている名前は、別の構成で読み飛ばされていても報告します。
  取り込んだヘッダの非活性領域に現れた名前は、区別せずに含めます
- `true` / `false`。構文の上では識別子と同じ形をしています

## 関数の中の変数は、その位置で見えるかを確かめる

関数の中の変数と仮引数は、宣言した関数の中でしか見えません。
関数の中の変数としてしか宣言されていない名前は、使っている位置から見えるかを確かめます。

```hlsl
float helper(float x) { float scale = 2; return x * scale; }
half4 frag() : SV_Target { return helper(1) * scale; }   // helper の scale は見えない。報告する
```

関数の外の変数・関数・構造体・マクロとしてどこかに宣言がある名前は、位置を問わず「宣言されている」として扱います。

## 一部の構成でだけ宣言が無い名前も報告する

`#ifdef` の中でだけ宣言した名前を常に使えば、その `#ifdef` が外れた構成で壊れます。

```hlsl
#ifdef _B
#define EXTRA 1
#endif
half4 frag() : SV_Target { return EXTRA; }   // 報告する ('EXTRA' は !_B のとき宣言されていません)
```

マクロでも、関数の中の変数でも同じです。

`#if` で分けたコードは、同じ位置がいくつかの構成の木に現れます。
宣言が見えなかった木の構成から、見えた木の構成を除いて、残る構成があれば、その構成を添えて報告します。
「どれか 1 つの木で見えれば報告しない」とすると、`_B` の木で見えるだけで `!_B` の誤りが隠れます。

どの木も解析していない組み合わせ (バリアントの上限を超えた組み合わせなど) については何も言いません。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 組み込み関数の名前 (前の「呼び出しの対象も見る」)
- 取り込めなかったヘッダがある場合
- 関数の中の変数の名前で、その位置で何を指すか決められない場合。
  波括弧の無い `if (x) float a;` のような宣言があるときなどです

`for` の初期化の変数は、囲む波括弧の中ではループの後でも見えるものとして扱います。
`for (int i = 0; ...) { } return i;` は Unity で通るので報告しません。
