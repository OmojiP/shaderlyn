# GL0406: 組み込みの変数とブロックの宣言し直しが正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、組み込みの変数 (`gl_FragCoord`・`gl_FragDepth`・`gl_ClipDistance` など) やブロック (`gl_PerVertex`) を、
glslang が受け付けない形で宣言し直している状態です。

```glsl
#version 420 core
layout(depth_any) out float gl_FragDepth;
layout(depth_greater) out float gl_FragDepth;   // 前の宣言し直しと depth が違う

out gl_PerVertex {
    vec4 gl_Position;
};

void main()
{
    gl_PointSize = 1.0;   // 宣言し直した gl_PerVertex に含めなかったメンバー
}
```

今は次のものを検査します (glslang 16.6.0 の `redeclareBuiltinVariable` と `redeclareBuiltinBlock` と同じ)。

- 変数
  - 型を変えたもの (`flat in vec3 gl_Color;`)
  - `gl_FrontColor` などの色で、layout を書いたものと、記憶域・メモリ・補助の修飾子を変えたもの
  - `gl_TexCoord`・`gl_ClipDistance`・`gl_CullDistance` で修飾子を変えたものと、前と違う大きさにしたもの
  - `gl_FragCoord` の最初の宣言し直しを使った後に書いたものと、前の宣言し直しと違う layout (`origin_upper_left`・`pixel_center_integer`) にしたもの
  - `gl_FragDepth` の depth の layout を使った後に書いたものと、前と違う depth にしたもの
  - 1.40 以前で `GL_ARB_separate_shader_objects` を有効にした `gl_Position` などを、使った後に書いたものと、記憶域や補間を変えたもの
- ブロック
  - `gl_PerVertex` などの決まった名前でないもの、インスタンスの名前を組み込みのもの (`gl_in` など) にしていないもの
  - その版とステージに無いブロックを宣言し直したもの
  - 2 度以上宣言し直したものと、ジオメトリシェーダーで `gl_in` を使った後に宣言し直したもの
  - 組み込みのブロックに無いメンバーを足したもの、メンバーの型や配列かどうかを変えたもの
  - 名前の無い出力のブロックを宣言し直した後に、含めなかったメンバーを使ったもの

## なぜ問題か

glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

組み込みの変数とブロックは、型と記憶域を変えずに、変えてよい修飾子だけを変えて宣言し直してください。
宣言し直しは、その変数やブロックを使う前に、1 度だけ (`gl_FragCoord` と `gl_FragDepth` は同じ layout で) 書いてください。
`gl_PerVertex` を宣言し直すときは、使うメンバーをすべて含めてください。

## 誤検出だと思ったら

組み込みの変数とブロックの形は、ファイルの拡張子で決まるステージと `#version` で決まります。拡張子と `#version` が意図どおりか確かめてください。
