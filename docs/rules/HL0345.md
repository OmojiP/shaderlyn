# HL0345: template の型引数を実引数から決められません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

HLSL 2021 の `template` の関数を、型引数を書かずに呼んだときに、型引数を 1 つに決められない呼び出しです。

```hlsl
template<typename T>
T MaxOf(T a, T b) { return max(a, b); }

float k;
half h;
float3 v;

MaxOf(k, k);     // 正しい。T は float
MaxOf(k, h);     // 報告する。第 1 引数からは float、第 2 引数からは half
MaxOf(v, k);     // 報告する。float3 と float
MaxOf(1.0, k);   // 報告する。接尾辞の無い 1.0 は float とは別の型
MaxOf(1.0f, k);  // 正しい
MaxOf(1.0, 2.0); // 正しい。どちらも接尾辞の無い数
```

型引数を書かずに呼ぶと、型引数は実引数の型から決まります (推論)。
同じ型引数に当たる実引数の型は**完全に一致**しなければなりません。
ふつうの関数の呼び出しと違い、`half` から `float` のような変換は行われません。

接尾辞の無い数 (`1.0` / `1`) は、`float` / `int` とは別の型として推論されます。
括弧や符号を付けても (`(1.0)` / `-1.0`) 同じです。`1.0f` / `1u` はふつうの型です。

仮引数が `vector<T, N>` なら、実引数のベクトルの基本型が `T`、成分の数が `N` になります。

```hlsl
template<typename T, int N> T Dot(vector<T, N> a, vector<T, N> b) { return dot(a, b); }
template<typename T> T Sum3(vector<T, 3> v) { return v.x + v.y + v.z; }

Dot(f3, f3);   // 正しい。T は float、N は 3
Dot(f3, f4);   // 報告する。N が 3 と 4
Sum3(f4);      // 報告する。float4 は vector<T, 3> に合わない
Sum3(k);       // 報告する。スカラーは vector<T, 3> に合わない
```

typedef で同じ型になる名前 (`dword` と `uint`、`float32_t` と `float`、`vector<float, 3>` と `float3`) は一致します。
どれも DXC (`-HV 2021`) で確かめた規則です。

引数の個数が合わない template の関数の呼び出しは [CF0402](CF0402.md) が報告します。

## なぜ問題か

コンパイルに失敗します (DXC は `no matching function for call to 'MaxOf'`)。

## どう直すか

型引数を書けば推論はされず、実引数は書いた型へ変換されます。

```hlsl
MaxOf<float>(1.0, k);   // 正しい
MaxOf<float>(k, h);     // 正しい
```

または、実引数の型を揃えてください (`1.0f`、`(float)h`)。

## 環境による違い

HLSL 2021 (汎用の HLSL の既定) だけの構文です。
Unity の環境 (HLSL 2018) では `template` そのものを [HL0003](HL0003.md) で報告します。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 型引数を書いた呼び出し (`MaxOf<float>(...)`)
- 同じ名前の関数が 2 つ以上ある場合 (template でない関数も含む)。
  どれが選ばれるかは実引数の型の変換で決まり、その規則は扱いません。
  DXC 1.8 は同じ名前の template を 2 つ書くことも、template とふつうの関数の多重定義も受け付けます (1.6 は拒みます)
- 実引数の型が分からない場合
- 型を比べてよいと確かめていない型。構造体、16 ビットの型の別名 (`float16_t` など) は比べません
- 仮引数の型が型引数そのものでも `vector<T, N>` でもない場合 (`matrix<T, R, C>`、配列、構造体)。そこからは推論しません
- 宣言か呼び出しが `#if` の中にある場合
- 取り込めなかったヘッダがある場合。そこに同じ名前の関数があるかもしれません
