# TOOL0005: 申告していないルールが報告されました

分類: Tool / 既定の重要度: 警告

## 何を検出するか

アナライザが、`SupportedDiagnostics` に載せていないルールを報告した状態です。

```
Assets/Shaders/Lit.shader(12:9): warning TOOL0005: アナライザ 'MyAnalyzer' がルール 'MY0002' を
    報告しましたが、SupportedDiagnostics に含まれていません。
```

シェーダーの誤りではなく、アナライザの実装の誤りです。

## なぜ問題か

`SupportedDiagnostics` には、アナライザが扱うルールを登録します。登録内容によって、次の 2 つが決まります。

- 設定ファイルからそのルールを無効にできるか
- `--list-rules` と SARIF のルール一覧に出るか

申告し忘れたルールは、設定ファイルから無効にできません。
利用者から見ると「消し方の分からない指摘」になります。

Roslyn では、申告していないルールを報告しても、そのことを知らせる診断は出ません。
そのため、指摘を設定から無効にできないなどの問題が起きても、原因に気づきにくくなります。
このルールは申告漏れを検出して報告します。

## 指摘そのものは捨てません

報告された指摘は、そのまま出力されます。
中身は正しいかもしれないので、捨てると本当の問題が隠れます。

指摘は出したうえで、申告漏れを別に報告します。

## どう直すか

`SupportedDiagnostics` へ加えてください。

```csharp
public override ImmutableArray<DiagnosticDescriptor> SupportedDiagnostics =>
    [Rule, ForgottenRule];   // ← 報告するものはすべて並べる
```

ルールを 1 つ足すときに、`DiagnosticDescriptor` の定義と
`SupportedDiagnostics` への追加は必ず対にしてください。

## 同じ誤りは 1 度だけ報告します

ノードごとに報告するルールで申告し忘れると、
出力が同じ行で埋まって元の指摘が読めなくなります。
1 ファイルにつき、同じ組み合わせは 1 度だけ報告します。
