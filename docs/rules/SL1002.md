# SL1002: 定数バッファの uniform が Properties に公開されていません

分類: Usage / 既定の重要度: 情報

## 何を検出するか

マテリアルごとの値を収める定数バッファ (URP と HDRP では `UnityPerMaterial`) に、
`Properties` へ公開されていない uniform が含まれている状態です。

## なぜ問題か

その定数バッファに置かれた値は、定義上「マテリアルごとの値」です。
それが `Properties` に無いということは、
マテリアルのインスペクタからは触れないということです。

スクリプトから明示的に設定しない限り既定値 (通常はゼロ) のままになるため、
「シェーダーを書いたときは動いていたのに、新しくマテリアルを作ると真っ黒になる」
という形で現れます。

## どう直すか

インスペクタから調整すべき値であれば `Properties` に追加します。

```shaderlab
Properties {
    _BaseColor ("Base Color", Color) = (1,1,1,1)
    _Cutoff ("Alpha Cutoff", Range(0,1)) = 0.5    // 追加する
}
```

## 誤検出だと思ったら

既定の重要度を情報にしているのは、正当な用途があるためです。

スクリプトから設定する内部状態を、あえて公開せずに定数バッファへ置く設計があります。

```csharp
material.SetFloat("_RuntimeBlend", value);   // インスペクタには出したくない
```

この用途であれば抑制してください。

なお、次のものは報告しません。

- `unity_` で始まる名前 (Unity エンジンが値を与える組み込み変数)
- テクスチャプロパティに付随して Unity が自動的に埋める uniform
  (`_BaseMap_ST`、`_BaseMap_TexelSize`、`_BaseMap_HDR`)。
  これらは対応するテクスチャプロパティが実在する場合にのみ除外されます
- `.shader` の外 (共有ヘッダ) で宣言されている uniform。
  定数バッファを共有ヘッダで定義して複数のシェーダーから取り込む構成では、
  バッファの中身はこのシェーダーの `Properties` とは関係がありません。
  ヘッダ側の宣言を指摘しても、そのヘッダを共有する他のシェーダーのために
  変えられないので直しようがありません
- `Properties` を 1 つも持たないシェーダー。
  描画の下請けとして使われるシェーダーであり、
  バッファの中身をすべて「公開されていない」と報告しても雑音にしかなりません

また、依存関係を解決できていない場合は検査自体を行いません (SL0002 を参照)。
