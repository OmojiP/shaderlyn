# URP0002: 定数バッファにテクスチャまたはサンプラが含まれています

分類: Correctness / 既定の重要度: 情報 (Unity 2022.3 の DXC で Metal 向けにコンパイルするときはエラー)

## 何を検出するか

`CBUFFER_START(UnityPerMaterial)` … `CBUFFER_END` の中に、
テクスチャまたはサンプラの宣言が含まれている状態です。

## なぜ問題か

定数バッファに入るのは数値だけです。
テクスチャとサンプラを書いても、コンパイラはそれを定数バッファの外へ出します。

ほとんどの場合は、動作も SRP Batcher との互換も変わりません。
Unity 2022.3〜6.6 の URP で、FXC と DXC、D3D11 / D3D12 / Vulkan / Metal / OpenGL Core / OpenGL ES 3 について確かめました。
SRP Batcher の判定も、正しく書いた場合と同じく「互換」でした。

例外は **Unity 2022.3 の DXC で Metal 向けにコンパイルする場合**です。
`#pragma use_dxc` を付けると、次のエラーでコンパイルできません。

```
generated SPIR-V is invalid: [VUID-StandaloneSpirv-None-04667] In Vulkan, OpTypeStruct must not contain an opaque type.
```

2023.2 以降の DXC では通ります。

そのため、既定では情報として伝えます。
Unity のバージョンが 2022.3 と分かっていて、コンパイル先に DXC で Metal 向けのものがあるときだけ、エラーにします。
書いた場所と実際の配置が食い違うので、エラーにならない場合も外へ出しておくと読み手に親切です。

## どう直すか

テクスチャとサンプラの宣言をバッファの外へ出し、
スケールとオフセット (`_ST`) だけをバッファに残します。

```hlsl
// 誤り
CBUFFER_START(UnityPerMaterial)
    TEXTURE2D(_BaseMap);
    SAMPLER(sampler_BaseMap);
    float4 _BaseMap_ST;
CBUFFER_END

// 正しい
TEXTURE2D(_BaseMap);
SAMPLER(sampler_BaseMap);

CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
CBUFFER_END
```

## 誤検出だと思ったら

型名を判別できた宣言についてのみ報告します。
マクロを展開できなかった場合や、ユーザー定義の型の場合は報告しません。

Unity のバージョンが分からない場合 (`--unity-editor` も `--unity-project` も無いなど) は、エラーにはしません。

依存関係を解決できていない場合は検査自体を行いません (HL0005 を参照)。
