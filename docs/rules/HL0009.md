# HL0009: #error に到達する構成があります

分類: Usage / 既定の重要度: 情報

## 何を検出するか

展開が `#error` に到達する構成です。

```hlsl
#if PERMUTATION_MODE == 0
    #define STEP 1
#elif PERMUTATION_MODE == 1
    #define STEP 2
#else
    #error Unknown PERMUTATION_MODE   // PERMUTATION_MODE が 0 でも 1 でもない構成で到達する
#endif
```

どの構成でも到達するなら、「構成：…」を付けずに伝えます。
到達した `#error` が取り込んだヘッダの中にあるときは、ファイルの先頭に報告し、メッセージにヘッダの名前と行を書きます。

## なぜ伝えるか

その構成はコンパイルされません。
Unreal Engine では C++ の `ShouldCompilePermutation` がその構成を除き、シェーダーは `#else` / `#error` で念を押していることがよくあります。
汎用の HLSL でも、`#error` に到達する構成はコンパイルの指定で除かれているはずです。誤りではないので、情報として伝えます。

**その構成のコードは、宣言の有無を見る検査で考えません。**
`#if defined(_A)` / `#error` / `#else` の中でだけ宣言した名前を、「構成：_A のとき宣言が無い」(HL0315 など) とは報告しません。
ただし、どの構成でも到達する `#error` では検査を止めません。解析のマクロの状態が実際と違うためのことが多く、止めるとそのシェーダーのどの検査も行われなくなるためです。

Unity では、キーワードで決まる構成の `#error` はコンパイルに失敗するので、[UN0103](UN0103.md) (エラー) で伝えます。
どの構成でも到達するものは、Unity でもこのルールで伝えます。

## どう直すか

意図どおり除いている構成なら、直す必要はありません。

どの構成でも到達するなら、解析のマクロが実際と違うことがあります。
コンパイルの指定で定義されるマクロを、設定の `defines:` で与えてください。
