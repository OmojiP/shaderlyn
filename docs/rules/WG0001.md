# WG0001: この機能を使うには enable が必要です

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

WGSL のファイルで、`enable` で有効にしていない拡張の機能を使っている状態です。naga (wgpu の WGSL のコンパイラ) はコンパイルの誤りにします。

```wgsl
// enable f16; が無い
fn f() -> f32 {
    let h: f16 = 1.0h;  // f16 は enable f16; が要る
    return f32(h);
}
```

今は次のものを検査します (naga 30 が拡張を求めるもの)。

| 書き方 | 必要な拡張 |
| --- | --- |
| `f16`、`vec3h` などの短い名前、接尾辞 `h` の数 (`1.0h`) | `f16` |
| `i16` / `u16` | `wgpu_int16` |
| `binding_array` | `wgpu_binding_array` |
| `acceleration_structure`・`ray_query`・`RayDesc`・`RayIntersection` | `wgpu_ray_query` (`wgpu_ray_tracing_pipeline` でもよい) |
| `acceleration_structure<vertex_return>`・`ray_query<vertex_return>` | `wgpu_ray_query_vertex_return` |
| `coop_mat8x8`・`coop_mat16x16` | `wgpu_cooperative_matrix` |
| `@blend_src` | `dual_source_blending` |
| `@builtin(clip_distances)` / `@builtin(primitive_index)` / `@builtin(draw_index)` | `clip_distances` / `primitive_index` / `draw_index` |
| `@task`・`@mesh`・`@payload`・`@per_primitive`、`var<task_payload>`、メッシュシェーダーの `@builtin` (`vertices`・`primitives` など) | `wgpu_mesh_shader` |
| `@ray_generation`・`@any_hit`・`@closest_hit`・`@miss`・`@incoming_payload`、`var<ray_payload>`・`var<incoming_ray_payload>` | `wgpu_ray_tracing_pipeline` |
| `@interpolate(per_vertex)` | `wgpu_per_vertex` |

## なぜ問題か

シェーダーモジュールを作れず、パイプラインが作られません。拡張は、使うデバイスの機能 (wgpu の `Features`) と対になっています。

## どう直すか

ファイルの先頭 (宣言より前) に、必要な拡張の `enable` を書いてください。

```wgsl
enable f16;
```

デバイスがその機能を持っていなければ、`enable` を書いてもパイプラインは作れません。機能を持たないデバイス向けには、拡張を使わない書き方 (`f16` の代わりに `f32`) にしてください。

## 誤検出だと思ったら

型の名前 (`f16`・`RayDesc` など) は、同じ名前を自分で宣言していれば検査しません (WGSL ではあらかじめ宣言された名前を隠せます)。
