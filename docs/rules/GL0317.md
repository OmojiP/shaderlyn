# GL0317: 定数の式が要ります

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、定数の式でなければならない所に、定数でない式を書いている状態です。glslang はコンパイルの誤りにします。

```glsl
#version 450
layout(location = 0) out vec4 color;
layout(location = 0) uniform int count;

const int limit = count;          // 関数の外の const の変数の初期値が定数でない

void main()
{
    float values[count];          // 配列の大きさが定数でない
    float pair[(2, 3)];           // コンマの演算子は定数の式にならない
    color = vec4(values[0] + pair[0]);
}
```

次の所を見ます。

- 配列の大きさ (変数、仮引数、構造体とブロックのメンバー)
- 関数の外の `const` の変数の初期値 (構造体の宣言に続けて宣言した変数 `const struct S { … } s = …;` も含む)
- uniform の変数の初期値。専用化の定数 (`layout(constant_id = 0) const`) も使えません
- `case` のラベル

次の式は定数の式になりません。

- uniform・入力・出力などの変数、`const` でない変数、仮引数
- 定数でない式で初期化した `const` の変数 (関数の中では 4.20 から書ける)
- 定数でない組み込みの変数 (`gl_FrontFacing` など)
- コンマの演算子
- 実引数に定数でない式を含む呼び出しと値の作成

定数でないと言い切れる式だけを報告します。`a.length()` を含む配列の大きさは見ません。

関数の中の `const` の変数を定数でない式で初期化すること (ES と、4.20 より前で `GL_ARB_shading_language_420pack` の無いとき) と、
ES で関数の外の変数を定数でない式で初期化すること (`GL_EXT_shader_non_constant_global_initializers` の無いとき) は、[GL0001](GL0001.md) が報告します。

## なぜ問題か

配列の大きさと定数の値は、コンパイルのときに決まらなければなりません。glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

リテラルか、定数の式で初期化した `const` の変数を使ってください。
実行のときに決まる大きさが要るなら、大きさの決まった配列を十分な大きさで宣言するか、buffer のブロックの最後のメンバーを大きさの決まらない配列にしてください。
専用化の定数 (`layout(constant_id = 0) const int N = 4;`) は、Vulkan 向けなら配列の大きさに使えます。
