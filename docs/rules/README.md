# ルール

組み込みルールの一覧です。ID を開くと、そのルールが何を報告するか、直し方、報告しない場合の説明があります。
重要度は設定ファイルで変えたり無効にしたりできます（[設定ファイル「rules」](../guide/configuration.md#rules)）。

ID の接頭辞は、どの環境で出るかを表します。

| 接頭辞 | 対象 | 出る環境 |
| --- | --- | --- |
| `HL` | HLSL のコード、解析の状況の知らせ | どの環境でも |
| `SL` | ShaderLab (`.shader` の構文、Properties と HLSL の対応) | Unity |
| `UN` | Unity のシェーダーコンパイラ・プリプロセッサ・ファイルの読み込みの振る舞い (`.hlsl` に出るものもある) | Unity |
| `URP` | レンダーパイプライン (URP / HDRP) | Unity |
| `UE` | Unreal Engine | Unreal Engine |
| `TOOL` | このツール自身 (設定ファイル、読み込みの失敗など) | どの環境でも |

0.2.1 で、接頭辞の意味に合わせて ID を付け替えました。前の ID で書いた抑制コメント・設定ファイルの `rules:`・ベースラインは、そのまま今の ID として効きます。

| 今の ID | 前の ID |
| --- | --- |
| [HL0005](HL0005.md) / [HL0006](HL0006.md) / [HL0007](HL0007.md) | SL0002 / SL0003 / SL0004 |
| [UN0302](UN0302.md) | HL0302 |
| [UN1050](UN1050.md)〜[UN1058](UN1058.md) | SL1050〜SL1058 (番号はそのまま) |

HL0330 の推測と HL0003 は、環境で振る舞いが変わります (各ルールの説明と [Unity 以外の環境で使う](../guide/environments.md#環境によって変わること) を参照)。

## 報告しないもの

Unity と外部パッケージのヘッダの中の問題は報告しません。プロジェクトの `Library` (Package Manager が展開した `PackageCache`) と、
Unity Editor に同梱のヘッダがそれに当たり、利用者には直せないためです。
利用者が書いて取り込んだヘッダ (共通の `.hlsl` など) は、取り込むシェーダーの文脈で検査し、ヘッダの位置に報告します。

HLSL コンパイラの[エラーと警告](https://learn.microsoft.com/ja-jp/windows/win32/direct3dhlsl/hlsl-errors-and-warnings)に載っているが報告しないもの

- コンパイルしなければ分からないもの
  - レジスタの割り当て
  - 命令数
  - ループの展開
  - 一時レジスタの本数
- そのコードをコンパイルするどの方言でも使えない構文。
  [HL0003](HL0003.md) でエラーを報告し、中身は読み飛ばします。
  中身を読んでいないため、そのブロックでは「宣言が見つからない」ことを根拠とする検査も行いません
  ([HL0005](HL0005.md))
  - Unity では、テンプレート / 演算子の多重定義 / ビットフィールド / `#line`。
    `enum` は DXC でコンパイルされるパスでは読みます (FXC に届くなら API を添えて HL0003)
- 解釈しないが、報告もしないもの
  - `[[vk::binding(0, 0)]]` のような二重角括弧の注釈。
    指示するのはレジスタやディスクリプタの割り当てで、上の「コンパイルしなければ分からないもの」に入ります。
    読み飛ばしても見送る検査は 1 つも無いため、報告しません
