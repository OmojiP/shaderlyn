# SG0401: その宣言にはアクセスできません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、構造体の `private` のメンバーをその構造体の外から使っているか、`import` した別のモジュールの public でない宣言を使っている状態です。slangc はコンパイルの誤り (E30600) にします。

```slang
struct MyType
{
    private int member;
    private int func() { return member; }
    int func1() { return member; }     // 構造体の中からは使える
}

void test()
{
    MyType t;
    t.func1();                         // public のメソッドは使える
    t.func();                          // private のメソッドは使えない
    t.member = 2;                      // private のフィールドも使えない
}
```

`private` のメンバーは、その構造体と、その中に定義した構造体の中でだけ使えます。

## 別のモジュールの宣言

関数の外の宣言 (関数・構造体・列挙型・変数) は、`public` を書かなければ internal で、宣言したモジュールの中でだけ使えます。
`public` の構造体のメンバーの既定は、宣言したモジュールの言語のバージョンで決まります。2025 (既定) なら internal、2026 (`#language slang 2026`) なら public です。

```slang
// lib.slang
module lib;
public struct P { int x; public int y; }
int helper() { return 1; }

// main.slang
import lib;
int test(P p)
{
    return p.y        // 使える
         + p.x        // 報告する。2025 の言語では、public の構造体のメンバーも internal が既定
         + helper();  // 報告する。public でない関数
}
```

`module` の宣言も可視性の修飾子も無いファイルは、古い書き方のモジュールとして、すべての宣言を public とみなします (slangc と同じ)。

## なぜ問題か

slangc がコンパイルできません。

## どう直すか

宣言かメンバーを `public` にするか (同じモジュールの中だけで使うなら `internal` でもかまいません)、構造体の中の public のメソッドを通して使ってください。

## 誤検出だと思ったら

`implementing` と `__include` で複数のファイルに分けたモジュールは、どのファイルが同じモジュールかをまだ決めないので、モジュールをまたぐ検査をしません。
