# SG0351: 初期化子の並びがこの型に合いません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、初期化子の並び (`{ … }`) がその型に合わない状態です。slangc はコンパイルの誤り (E30513・E39999) にします。

```slang
struct One
{
    int x;
    __init(int v) { x = v; }
}

struct BaseCtor { int a; __init() { a = 2; } }
struct DerCtor : BaseCtor { int b = 1; }

struct WithTex { int v; Texture1D<float> t; }

void f()
{
    One o = {};                    // 誤り: 0 個を受け取る __init が存在しない
    DerCtor c = {};                // 誤り: __init を持つ構造体を継承している
    WithTex w = {1};               // 誤り: 資源の型のフィールド t を埋めていない
    Texture2D<float4> t = {};      // 誤り: 資源の型の変数
}
```

`__init` を書いた構造体の並びは、`__init` の呼び出しになります。要素の数を受け取る `__init` (既定値のある仮引数を含む) があれば通ります。
`__init` が存在しない構造体の並びは、フィールドを順に埋め、不足しているフィールドは既定の値になります (多すぎるものは [CF0412](CF0412.md) が報告します)。

`__init` が存在しない構造体で slangc が作る `__init` は、構造体と同じかそれより広い可視性のフィールドだけを仮引数にします。
public の構造体の private / internal のフィールドは並びで埋められないので、並びの要素がそれを超えるものも報告します (`S({ 1 })` の形を含む)。

ジェネリックの構造体と、extension で `__init` が追加されうる型は見ません。

## なぜ問題か

slangc がコンパイルできません。資源の型には既定の値が存在しないので、並びで省けません。

## どう直すか

要素の数を受け取る `__init` を書くか、`__init` を直接呼んでください (`One o = One(1);`)。資源の型のフィールドは、並びの中で埋めてください。
