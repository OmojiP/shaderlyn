# HL0352: 初期化の要素の個数が合いません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

波括弧による初期化で、書いた要素の個数が代入先と合っていない状態です。

```hlsl
float3 a = {1, 2};            // 3 個必要
float3 b = {1, 2, 3};         // 正しい
float3 c = {float2(1, 2), 3}; // 正しい (平らにして 3 個)

float2 d[2] = {1, 2, 3};      // 4 個必要
float2 e[2] = {1, 2, 3, 4};   // 正しい
```

平らにした成分の個数で数えます。
入れ子の波括弧も、ベクトルも、構造体も、多次元の配列も、成分に展開してから数えます。

```hlsl
struct Point { float2 uv; float w; };

Point a = {1, 2, 3};           // 正しい (2 + 1 = 3 成分)
Point b = {1, 2};              // 足りない

float m[2][3] = {1,2,3,4,5,6}; // 正しい (2 * 3 = 6)
float n[2][3] = {1,2,3};       // 足りない
```

行列は行 × 列で数えます。`float2x2 m = {1, 2, 3, 4};` が正しい形です。

### `#if` で要素やメンバーが変わる場合

構成ごとに、その構成にある要素とメンバーだけを数えて比べます。
食い違う構成があれば、その条件を添えて報告します。

```hlsl
#pragma multi_compile _ _A

float4 c = { 1, 2, 3
#ifdef _A
    , 4
#endif
};                             // !_A のとき 3 個しかない

struct Pixel {
    float4 a;
#ifdef _A
    float4 b;
#endif
};

Pixel p = { float4(1, 1, 1, 1) };   // _A のとき 8 個必要
```

メンバーと要素を同じ `#ifdef` で増やしていれば、どの構成でも釣り合うので報告しません。

## なぜ問題か

コンパイルに失敗します。

成分を増やしたり減らしたりしたときに、初期化を直し忘れると現れます。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 要素の型が 1 つでも分からない場合
- 配列の長さが数字で書かれていない場合。
  マクロや定数で書かれた長さは求めません
- Unity や外部パッケージのヘッダの構造体。指摘しても直しようがありません (利用者が書いて取り込んだヘッダの構造体は対象です)
- 入れ子が 8 段を超える構造体。そこで数えるのをやめます
- 要素やメンバーの条件に出てくるシンボルが 12 個を超える場合。構成の組み合わせが多すぎるので数えません
- 要素やメンバーの条件を追えなかった場合
