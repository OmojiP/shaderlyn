# CF0405: 関数の配列型の引数が一致しません

分類: Correctness / 既定の重要度: エラー / 0.3.1 より前の ID: HL0344

## 何を検出するか

配列の仮引数に、形の合わない実引数を渡している状態です。

```hlsl
void fill(out float dst[4]) { ... }

float ok[4];
fill(ok);              // 正しい

float wrongLength[2];
fill(wrongLength);     // 長さが違う

float2 wrongType[4];
fill(wrongType);       // 要素の型が違う
```

配列は要素の型と長さの両方が一致していなければなりません。
成分を減らす変換も、長さの違う配列の受け渡しも許されません。

## 誤検出だと思ったら

このルールは次の場合に発火しません。

- 実引数の形が分からない場合。
  配列を渡せるのは、配列として宣言された名前 (`arr`) か、構造体の配列のフィールド (`data.v`) です。
  それ以外の式は、型が分かって配列でないと言えるときだけ「配列ではない」と報告します
  (多次元配列の一部 `a[0]` のように型が分からない式は報告しません)。
  名前がその位置で指す宣言を決められないときも報告しません
  (波括弧の無い `if (x) float a[2];` のような宣言があるときなど)
- 長さが数字で書かれていない場合。
  マクロや定数で書かれた長さは求めません
- 構成によって長さか要素の型が違う場合。
  名前はその位置で指す宣言から引くので、別の関数に同じ名前の配列があっても取り違えません
