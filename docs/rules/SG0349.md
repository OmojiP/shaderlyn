# SG0349: 型引数がジェネリックの制約を満たしません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、ジェネリックの関数か型の型の仮引数に、制約 (`<T : IFoo>`・`where T : IFoo`) のインターフェイスに適合しない型を渡している状態です。
slangc はコンパイルの誤り (E38029) にします。

```slang
interface IFoo { int get(); }
struct Parent : IFoo { int get() { return 1; } }
struct Child : Parent { }          // 基底の構造体の適合は受け継がない
struct Bar { }

int f<T : IFoo>(T x) { return x.get(); }
struct G<T : IFoo> { T v; }

void main(Child c, Bar b)
{
    f(b);                          // Bar は IFoo に適合しない
    f<Bar>(b);                     // 書いた型引数も同じ
    f(c);                          // Child は IFoo に適合しない
    f(1);                          // int も適合しない
    G<Bar> g;                      // 型の型引数も同じ
}
```

型が適合するのは、型の継承の並び (`struct S : IFoo`) か `extension S : IFoo` に、そのインターフェイスか、それを継承したインターフェイスを書いたときだけです。

制約が利用者のインターフェイスで、型引数が利用者の構造体か組み込みの型のときに見ます。同じ名前の関数か型が 2 つ以上あるもの、ジェネリックのインターフェイス、
ジェネリックの extension (`extension<T : IBar> T : IFoo`) で適合しうるインターフェイス、修飾した名前の基底を持つ型は見ません。

言語のバージョンを書いたファイル (`#lang slang 2025` 以降) では、インターフェイスの型の値 (存在型) で型の仮引数を特殊化するもの (`genericFunc(obj, 3.0)` の obj が IFoo) も報告します (E33180)。
バージョンを書かないファイルでは、古い書き方として動的なディスパッチで通ります。

## なぜ問題か

slangc がコンパイルできません。ジェネリックの本体は、制約のインターフェイスの要件を使って書かれています。

## どう直すか

型の継承の並びか extension に、制約のインターフェイスを書いて、その要件を実装してください (`extension Bar : IFoo { int get() { return 0; } }`)。
