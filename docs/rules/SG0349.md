# SG0349: 型引数がジェネリックの制約を満たしません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、ジェネリックの関数か型の型の仮引数に、制約 (`<T : IFoo>`・`where T : IFoo`) のインターフェイスに適合しない型を渡している状態です。
slangc はコンパイルの誤り (E38029) にします。

```slang
interface IFoo { int get(); }
struct Parent : IFoo { int get() { return 1; } }
struct Child : Parent { }          // 基底の構造体の適合は受け継がない
struct Bar { }

int f<T : IFoo>(T x) { return x.get(); }
struct G<T : IFoo> { T v; }

void main(Child c, Bar b)
{
    f(b);                          // Bar は IFoo に適合しない
    f<Bar>(b);                     // 書いた型引数も同じ
    f(c);                          // Child は IFoo に適合しない
    f(1);                          // int も適合しない
    G<Bar> g;                      // 型の型引数も同じ
}
```

型が適合するのは、次のどれかでインターフェイスに届くときです。

- 型の継承の並び (`struct S : IFoo`) か `extension S : IFoo` に、そのインターフェイスか、それを継承したインターフェイスを書いた
- 制約を書いた、どの型にも当たる extension (`extension<T : IBar> T : IFoo`) の制約に適合する。適合が増えなくなるまでたどります
- 標準ライブラリで適合する。組み込みの数の型とベクトルと行列は、標準ライブラリの表 (slang 2026.19 から作ったもの) で決めます (`float3` は `IFloat` に適合し、`int` と `int3` は適合しない)

```slang
interface IBar { }
interface IFoo { }
extension<T : IBar> T : IFoo { }   // IBar に適合する型は、IFoo にも適合する
struct S : IBar { int v; }
struct D { int v; }

void f<T : IFoo>(T x) { }
void g<T : IFloat>(T x) { }

void main(S s, D d)
{
    f(s);                          // 通る
    f(d);                          // D は IBar に適合しないので、IFoo にも適合しない
    g<float3>(float3(1));          // 通る
    g<int>(1);                     // int は IFloat に適合しない
}
```

次のものも報告します。

- 外の関数の型の仮引数 `T` を型引数にしたもの (`g<T>(t)`) で、T の制約から要るインターフェイスに届かないもの。`where optional T : IFoo` の制約は数えません
- 制約に合わない既定の型引数 (`__generic<T : ITest = Impl2> struct GenStruct`)。既定の型引数を使う所で報告します (型なら既定の値の位置、関数なら呼び出しの位置)
- 型引数の制約のある別名 (`typealias WrappedProvider<T : IValueProvider> = Wrapper<T>;`) の型引数

インターフェイスでない制約と、関連型の制約も見ます。

- `where T == int` に、別の型 (数の型どうしか、片方が構造体) が当たるもの (E30440)。リテラルの実引数は、型が変わりうるので見ません
- `where int(T)` (T を int に変換できる) に、変換を書いていない構造体が当たるもの (E30440)。int の extension があれば見ません
- `where __hasDiffTypeInfo(T)` に、IDifferentiable に適合しない構造体が当たるもの (E30440)
- 型の宣言の関連型の制約 (`where T.Element : IMarker`・`where T.Element == int`) に、合わない関連型 (`typealias Element = float;`) を持つ型か、関連型の決まらない extern の構造体が当たるもの (E38029)
- インターフェイスの `__constraint DataType == This;` に、自分でない型の関連型 (`typealias DataType = int;`) で適合する型 (E38029)。継承の並びの位置で報告します
- ジェネリックのインターフェイスの制約 (`interface IConsumer<T> where T : IContext`) に、制約の届かない関連型を渡すもの (`associatedtype First : IConsumer<Context>;` の Context に IContext の制約が無い。E38029)
- 等しさの制約の両辺が、違う構造体の型 (`where Box<X> == Box<X>.Nested<X>`) のもの (E38029)

```slang
interface IHasElement { associatedtype Element; }
struct RequiresInt<T : IHasElement> where T.Element == int {}
struct FloatContainer : IHasElement { typealias Element = float; }

void h<T>(T x) where T == int {}

RequiresInt<FloatContainer> value;   // FloatContainer.Element は float

void main()
{
    float f = 1.0;
    h(f);                            // float は int ではない
}
```

取り込んだモジュールの extension は、そのモジュールが見えるときだけ型の適合に足します (`import a;` だけのファイルからは、a が `__exported` でなく取り込んだモジュールの extension は見えません)。

同じ名前の関数か型が 2 つ以上あるもの、ジェネリックのインターフェイス、修飾した名前の基底を持つ型、ジェネリックの型への extension (`extension<T> Box<T> : IFoo`) で適合しうる型は見ません。
標準ライブラリの型のうち、数の型・ベクトル・行列でないもの (`Optional` など) は、表にある適合だけを確かめ、表に無いインターフェイスには適合しないと言いません (標準ライブラリの C++ の部分が作る適合があるかもしれないため)。

言語のバージョンを書いたファイル (`#lang slang 2025` 以降) では、どの型か決まらないインターフェイスの型の値 (存在型) で、型の仮引数を特殊化するものも報告します (E33180)。
特殊化はコードを作るときに起きるので、エントリポイント (`[shader]`・`[numthreads]` の関数) から届く関数の中だけを見ます。
値がどの型か決まらないのは、2 つ以上の違う型の値を返す関数の戻り値・`createDynamicObject<IFoo>(…)`・それを受け取った変数と仮引数と、そのメソッドが返す関連型の値です
(1 つの型しか返さない関数の値は、slangc がその型に決めるので通ります)。

- ジェネリックの関数とメソッドの、型の仮引数に当たる実引数 (`genericFunc(obj, 3.0)`・`b.eval(df)`・`process(obj.transform(1.0))`)
- インターフェイスの型を型引数に書いた呼び出し (`genericFunc<IFoo>(obj, 3.0)`・`b.eval<IFoo>(df)`)
- どの型にも当たる extension のメソッドを、その値で呼ぶもの (`extension<T : IFoo> T { float twice() … }` の `obj.twice()`)

```slang
#lang slang 2025
interface IFoo { float calc(float x); }
struct A : IFoo { float calc(float x) { return x; } }
struct B : IFoo { float calc(float x) { return x * 2; } }
float genericFunc<T : IFoo>(T obj, float x) { return obj.calc(x); }
IFoo make(uint id) { if (id == 0) return A(); return B(); }

RWStructuredBuffer<float> output;

[numthreads(1, 1, 1)]
void computeMain(uint3 id : SV_DispatchThreadID)
{
    IFoo obj = make(id.x);
    output[0] = genericFunc(obj, 3.0);   // obj は A か B か決まらない
}
```

バージョンを書かないファイルでは、古い書き方として動的なディスパッチで通ります。
ただし、`ByteAddressBuffer` の `Load<IFoo>(…)` (インターフェイスの型の値を読むもの) は、バージョンによらず、エントリポイントから届く関数の中で報告します。

## なぜ問題か

slangc がコンパイルできません。ジェネリックの本体は、制約のインターフェイスの要件を使って書かれています。

## どう直すか

型の継承の並びか extension に、制約のインターフェイスを書いて、その要件を実装してください (`extension Bar : IFoo { int get() { return 0; } }`)。
