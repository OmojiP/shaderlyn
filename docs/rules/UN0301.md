# UN0301: シェーダーステージが指定されていません

分類: Correctness / 既定の重要度: エラー (0.3.2 までは警告)

## 何を検出するか

`HLSLPROGRAM` / `CGPROGRAM` のブロックに、
どの関数をどのステージとして使うかを指定する `#pragma` が足りない状態です。

- `.shader` では、`#pragma vertex` と `#pragma fragment` の両方が要ります。片方だけでも報告します。
  サーフェスシェーダー (`#pragma surface`) とレイトレーシング (`#pragma raytracing`) は、この 2 つを書かないので報告しません
- `.compute` では、`#pragma kernel` が 1 つも無いものを報告します

Unity の環境だけのルールです。汎用の HLSL・Unreal の環境では、ステージは設定ファイルの `units:` の `target` で決まるので出ません。

## なぜ問題か

Unity はエラーにせず、次の警告を出してその Pass をコンパイルから外します。

```
Both vertex and fragment programs must be present in a shader snippet. Excluding it from compilation.
```

ほかの Pass が正しくても、その SubShader ごと「not supported on this GPU」になり、シェーダーが使えなくなります (Unity 6.3 で確かめました)。
Unity の表示は警告ですが、描画できないので、Shaderlyn はエラーとして報告します。

よくある経緯は、共通コード片に書いたつもりの `#pragma` が届いていない場合です。

```shaderlab
SubShader
{
    CGINCLUDE
    #pragma vertex vert       // HLSLPROGRAM には届かない
    #pragma fragment frag
    ENDCG

    Pass { HLSLPROGRAM ... ENDHLSL }
}
```

共通コード片は、ファイルの中のどこに書いても、同じ種類のコードブロックすべてに差し込まれます
(Pass より後に書いたものも、別の `SubShader` のものも)。
ただし `CGINCLUDE` は `HLSLPROGRAM` に、`HLSLINCLUDE` は `CGPROGRAM` に届きません (Unity 6.6 で確かめました)。
`CGPROGRAM` を `HLSLPROGRAM` に書き換えたときに起きがちです。

## どう直すか

必要な `#pragma` をそのブロックか、同じ種類の共通コード片 (`HLSLPROGRAM` なら `HLSLINCLUDE`) に書きます。

```hlsl
#pragma vertex vert
#pragma fragment frag
```

## 判定できる範囲

取り込まれる前提の断片 (`.hlsl` / `.cginc` / `.hlslinc`) を単体で解析したときは報告しません。
ステージは取り込む側の `.shader` が決めるためです。
`.compute` は 1 ファイルで完結するので報告します。

## 誤検出だと思ったら

このツールが知らない書き方でステージが決まる場合、
「指定が無い」と誤って報告される可能性があります。
その場合は抑制コメントを使い、あわせて不具合として報告してください。

```hlsl
// shaderlyn-disable-next-line UN0301
```
