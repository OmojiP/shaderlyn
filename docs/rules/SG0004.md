# SG0004: リテラルの書き方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

Slang のファイルで、文字・文字列・整数のリテラルを、slangc の字句の決まりに合わない形で書いている状態です。slangc は字句の誤りにします。

- 使用できないエスケープ (`\q`・`\e`・`\8`)、中身が存在しない `\x`・`\x{}`、閉じない `\u{12`、32 ビットに収まらない `\x` の値 (E10007)
- 16 進の数の桁が不足している `\u` (ちょうど 4 桁) と `\U` (ちょうど 8 桁) (E10008)
- 文字列の中の、1 バイト (0～255) に収まらない `\x` の値 (E10009) と、UTF-8 にできない符号位置 (E10013)
- 中身がちょうど 1 文字でない文字のリテラル (`''`・`'ab'`) (E10001)
- 64 ビットの符号無しの整数にも収まらない整数のリテラル (E10012)

```slang
uint a = '\q';                        // 報告する。使用できないエスケープ
uint b = '\u12';                      // 報告する。\u は 16 進 4 桁
uint c = 'ab';                        // 報告する。文字のリテラルは 1 文字
String d = "\xFEDC";                  // 報告する。文字列の \x は 1 バイト
uint64_t e = 18446744073709551616;    // 報告する。64 ビットに収まらない
uint f = '\u{41}';                    // 正しい
```

使用できるエスケープは `\' \" \ \? \a \b \f \n \r \t \v`、8 進 (1～3 桁)、`\x` (16 進。`\x{…}` も)、`\u` (16 進 4 桁か `\u{…}`)、`\U` (16 進 8 桁) です。
`import "…"` のパスは、エスケープとして読みません。

## なぜ問題か

slangc がファイルを解析できません。

## どう直すか

エスケープを正しく書くか、`\` そのものを書く場合は `\` にしてください。大きな数は浮動小数のリテラル (`1.8e19`) にしてください。
