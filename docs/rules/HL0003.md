# HL0003: この環境では使えない構文です

分類: Syntax / 既定の重要度: エラー

## 何を検出するか

HLSL の文法にはあっても、HLSL 2018 (Unity のシェーダーはこれでコンパイルされる) ではエラーになる構文です。
Unity では `#line` 指令も報告します。

文の後半は環境で変わります。Unity では「Unity のシェーダーでは使えません」、汎用の HLSL・Unreal で `hlsl: version: 2018` のときは「HLSL 2018 では使えません」です。

```hlsl
interface ILight { half3 Shade(half3 normal); };   // interface 宣言
class PointLight : ILight { ... };                 // class 宣言
enum Mode { First, Second };                       // enum 宣言
template<typename T> T Twice(T x) { return x + x; } // template 宣言

struct S
{
    float4 v;
    S operator+(S o) { ... }                       // operator による演算子の多重定義
    uint flags : 4;                                // ビットフィールド (4 の位置を報告する)
};

#line 100                                          // #line 指令
```

Unity は次のようなエラーで拒みます。

```
syntax error: unexpected token 'operator'
syntax error: unexpected token 'line'
```

## 環境による違い

この指摘が出るのは HLSL の言語のバージョンが 2018 のとき (Unity の環境、`hlsl: version: 2018`) だけです。
汎用の HLSL の既定 (2021) では、`enum` / 演算子の多重定義 / `template` などは正しい構文なので報告しません。
`enum`・演算子の多重定義・`template` (明示的な特殊化 `template<>` を含む)・`class`・`interface`・ビットフィールドは、中身も読んで検査します。
`template` の型引数 `T` を含む型は、分からない型として扱います。`class` と `interface` は構造体と同じに扱います。
`#line` は Unity の環境だけで報告します。

## 読めるもの

構造体のメソッドは使えます。構造体の外での定義 (`uint Wave::GetIndex() { ... }`) も読みます。
SRP の `ThreadingEmuImpl.hlsl` がこの書き方をしていて、D3D11 でもコンパイルされます。

## この構文があると何が起きるか

その構文は読み飛ばします。中のメソッドもフィールドも、
波括弧の後ろに続く変数 (`class Foo { ... } foo;` の `foo`) も木に載りません。

そのコードブロックでは「宣言が見つからない」ことを根拠とする検査を行いません。
uniform の一覧に抜けがある状態で「対応する宣言が無い」と報告すれば、
書かれていない誤りを指摘することになります。
見送ったことは [SL0002](SL0002.md) が同じファイルに報告します。

## どう直すか

`struct`・`#define` の定数・通常の関数で書き直してください。

```hlsl
struct PointLight
{
    half3 color;
};

half3 Shade(PointLight light, half3 normal)
{
    return light.color * normal;
}
```

- `enum` は `#define` か `static const uint` の定数に
- `template` は型ごとの関数か、型名を `#define` で切り替える形に
- `operator` は通常の関数 (`S Add(S a, S b)`) に
- ビットフィールドは `uint` 1 つに詰めて、シフトとマスクで取り出す形に
- `#line` は消す
