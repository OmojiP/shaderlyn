# SL1003: プロパティの型と HLSL の型が一致しません

分類: Correctness / 既定の重要度: 警告

## 何を検出するか

`Properties` に宣言された型と、対応する HLSL の uniform の型が
噛み合っていない組み合わせです。

| Properties                            | HLSL に必要な型                            |
| ------------------------------------- | ------------------------------------------ |
| `Color` / `Vector`                    | `float4` / `half3` などのベクトル型        |
| `Float` / `Range` / `Int` / `Integer` | `float` / `half` / `int` などのスカラー型  |
| `2D`                                  | `Texture2D` (または Cg 記法の `sampler2D`) |
| `3D`                                  | `Texture3D`                                |
| `Cube`                                | `TextureCube`                              |
| `2DArray`                             | `Texture2DArray`                           |
| `CubeArray`                           | `TextureCubeArray`                         |

Pass ごとの宣言をすべて見ます。どれか 1 つの Pass でも食い違っていれば報告します。

## なぜ問題か

Unity はこれをエラーにせず、値の一部だけを転送するか、まったく転送しません。

```hlsl
// Properties: _Color ("Color", Color) = (1,1,1,1)
float _Color;   // x 成分しか届かない
```

この場合、カラーピッカーで選んだ色の R 成分だけが `_Color` に入り、
G と B は失われます。「色を変えても赤くしかならない」という形で現れます。

逆の取り違えも起きます。

```hlsl
// Properties: _Smoothness ("Smoothness", Range(0,1)) = 0.5
float4 _Smoothness;   // x にしか値が入らず、yzw は不定
```

## どう直すか

どちらかを他方に合わせます。値の意味から考えて、
`Properties` 側と HLSL 側のどちらが正しいかを決めてください。

## 誤検出だと思ったら

成分数の違いは報告しません。

```hlsl
// Properties: _EmissionColor ("Emission", Color) = (0,0,0,1)
half3 _EmissionColor;   // 報告しない
```

`Color` を `half3` で受けるのは Unity 同梱のシェーダーでも普通に行われている書き方で、
アルファを使わない場合の正当な最適化です。
報告するのはスカラーとベクトル、ベクトルとテクスチャのような、
必ず不具合になる粒度の食い違いだけです。

また、このツールが型名を判別できない場合 (ユーザー定義の型、
マクロを展開できなかった場合など) も報告しません。
判別できないことは、合っていないことの証拠にならないためです。
