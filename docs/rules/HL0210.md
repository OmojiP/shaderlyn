# HL0210: セマンティクスが重複しています

分類: Correctness / 既定の重要度: 警告 (DXC でコンパイルするエントリポイントの入出力ではエラー)

## 何を検出するか

同じ構造体の複数のメンバーに同じセマンティクスが付いている状態です。

```hlsl
struct Varyings
{
    float4 positionCS : SV_POSITION;
    float2 uv         : TEXCOORD0;
    float2 uvLightmap : TEXCOORD0;   // 番号を付け忘れた
};
```

## なぜ問題か

エントリポイントの入出力に使う構造体 (メンバーの構造体を含む) では、コンパイラによって結果が変わります。

| コンパイラ | 結果 |
| --- | --- |
| DXC | コンパイルできない (`Semantic 'TEXCOORD' overlap` の検証の誤り) |
| FXC | 警告 X4711 を出して通る |

DXC でコンパイルするとき (汎用の HLSL と Unreal の既定、Unity の DXC のパス) はエラー、FXC だけのときは警告として報告します。
FXC で通っても、どのメンバーに値が入るかは保証されず、「片方の値が常にもう片方と同じになる」という形で現れます。
入出力に使わない構造体は、どちらのコンパイラも何も言いませんが、書き間違いなので警告として報告します。
スタンドアロンの FXC・DXC 1.8 と、Unity 6.3 (FXC と `#pragma use_dxc` の DXC) で確かめた結果です。

`TEXCOORD` の番号の付け間違いで起きることがほとんどです。
メンバーを追加した際に番号を振り直し忘れる、
コピーした行の番号を直し忘れる、といった経緯で入り込みます。

## どう直すか

セマンティクスの番号を振り直します。

```hlsl
struct Varyings
{
    float4 positionCS : SV_POSITION;
    float2 uv         : TEXCOORD0;
    float2 uvLightmap : TEXCOORD1;
};
```

## 誤検出だと思ったら

別々の構造体が同じセマンティクスを使うのは報告しません。
頂点入力と頂点出力で同じ `TEXCOORD0` を使うのはむしろ普通です。

`register(...)` や `packoffset(...)` は検査から外します。
構文上はセマンティクスと同じ形をしていますが、意味が違います。

検査するのは、利用者が書いた構造体だけです。そのシェーダーと、利用者が書いて取り込んだヘッダ (共通の `.hlsl` など) にあるものです。
Unity や外部パッケージのヘッダの中の構造体を指摘しても直しようがありません。
