# GL0325: 協調行列の使い方が正しくありません

分類: Correctness / 既定の重要度: エラー

## 何を検出するか

GLSL のファイルで、協調行列 (`GL_KHR_cooperative_matrix` の `coopmat`、`GL_NV_cooperative_matrix` の `fcoopmatNV` など) に使えない書き方です。

- 型の違う協調行列どうしの演算 (要素の型・スコープ・行の数・列の数・用途のどれかが違う)
- 協調行列と協調行列でない値の `+`・`-`・`/`
- 要素と違う型のスカラーとの `*` (`float16_t` の協調行列に `2.0` を掛けるなど)
- NV の協調行列どうしの `*`
- `[ ][ ]` で要素を引くもの (`[ ]` は 1 つだけ書けます) と、成分の選択 (`.x`)
- 値の作成の 2 つ以上の実引数と、スカラーでも協調行列でもない実引数 (`mat4` など)

```glsl
#version 450 core
#extension GL_KHR_cooperative_matrix : enable
#extension GL_KHR_memory_scope_semantics : enable
#extension GL_EXT_shader_explicit_arithmetic_types : enable
layout(local_size_x = 64) in;

void main()
{
    coopmat<float16_t, gl_ScopeSubgroup, 16, 8, gl_MatrixUseA> a;
    coopmat<float16_t, gl_ScopeSubgroup, 8, 8, gl_MatrixUseA> b;

    a + b;          // 型 (行の数) が違う
    a + 1.0;        // 協調行列でない値との +
    a * 2.0;        // 要素は float16_t なので、2.0 (float) は掛けられない
    a[0][0];        // [ ] は 1 つだけ
    a.x;            // 成分は選べない
}
```

型の違う協調行列の代入と、協調行列でない値の代入は、[CF0410](CF0410.md) が報告します。

## なぜ問題か

協調行列は暗黙に型を変換しないので、glslang (Vulkan の SDK の `glslangValidator` と `glslc`) がコンパイルを止めます。

## どう直すか

型をそろえるには値の作成 (`coopmat<float, gl_ScopeSubgroup, 16, 8, gl_MatrixUseA>(a)`) を使ってください。
スカラーは要素と同じ型にしてください (`a * float16_t(2.0)`)。
