Visual Studio and Rider support.

- **Visual Studio extension** (Visual Studio 2022 17.14 or later, and 2026): diagnostics, quick fixes, hover, completion, go to definition, references and rename. Works alongside HLSL Tools
- **Rider plugin** (Rider 2026.3 or later): diagnostics and quick fixes. Rider's own shader support stays as it is
- **Automatic fixes**: diagnostics with a single correct fix can be fixed with editor quick fixes and the CLI's `--fix` (`--fix-dry-run`)
- **Custom rules can target GLSL, Godot, Slang and WGSL** (`ShaderRuleAnalyzer.Languages`)
- `.usf` and `.ush` files are analyzed as Unreal Engine even when no environment is configured
- New rules CF0302, CF0303 and CF0316. Memory allocated during analysis is reduced by 4–23%
- **Breaking change** (custom rules): `ShaderEntryPoint` now has a stage

See the [CHANGELOG](https://github.com/OmojiP/shaderlyn/blob/main/CHANGELOG.md#035---2026-11-22) (in Japanese) for details.

Visual Studio と Rider に対応。

- **Visual Studio 拡張** (Visual Studio 2022 17.14 以降と 2026): 指摘・クイックフィックス・ホバー・補完・定義へ移動・参照・名前の変更。HLSL Tools と併用可能
- **Rider プラグイン** (Rider 2026.3 以降): 指摘とクイックフィックス。Rider 自身のシェーダーの支援もそのまま使用可能
- **自動の修正**: 修正の方法が 1 つに決まる指摘に、エディタのクイックフィックスと CLI の `--fix` (`--fix-dry-run`) で修正を適用可能
- **自作ルールを GLSL・Godot・Slang・WGSL にも適用可能** (`ShaderRuleAnalyzer.Languages`)
- 環境を決めていない場合も、`.usf`・`.ush` を Unreal Engine の環境で解析
- ルール CF0302・CF0303・CF0316 を追加。解析で確保するメモリーを 4〜23% 削減
- **破壊的変更** (自作ルール向け): `ShaderEntryPoint` にステージを追加

詳細は [CHANGELOG](https://github.com/OmojiP/shaderlyn/blob/main/CHANGELOG.md#035---2026-11-22) を参照。
