Faster editing, Windows on Arm, and Unreal Engine without configuration.

- **Faster language server**: the analysis is shared between diagnostics, inactive regions and hover, and saving no longer rereads unchanged headers (URP `Lit.shader`: diagnostics after saving in 0.1 s instead of 5–7 s, results after opening in 5.5 s instead of 10–12 s)
- **Windows on Arm**: native CLI and VS Code extension for Windows arm64. The Visual Studio extension and the Rider plugin start a native arm64 language server
- **Unreal Engine**: the engine and project are found from the analyzed file (a file inside the engine, or a `.uproject` above it), so `unreal: engine` / `unreal: project` are no longer required
- **New rules**: HL0355 / SG0364 (`GetAttributeAtVertex` given a value that is not a vertex input), HL0356 / SG0365 (`discard`, `clip`, derivatives and implicit-LOD sampling reached from a stage that cannot use them), SG0366 (`#language` directives)
- **Slang**: many more slangc errors are reported (automatic differentiation, visibility inside `extension`, `constexpr` parameters, `[ForceUnroll]`, user-defined attributes and more). `units:` can now give the entry point and stage chosen with `-entry` / `-stage`
- **Editor pages**: the VS Code, Visual Studio and Rider pages share the same English description, and each extension README has an English and a Japanese version. The Rider plugin now has an icon, and the garbled Visual Studio Marketplace description is fixed

See the [CHANGELOG](https://github.com/OmojiP/shaderlyn/blob/main/CHANGELOG.md#未リリース) (in Japanese) for details.

編集時の高速化、Windows の Arm への対応、Unreal Engine の設定の省略。

- **言語サーバーの高速化**: 指摘・効いていない範囲・ホバーで解析の結果を共有し、保存のときに変わっていないヘッダを読み直さない (URP の `Lit.shader` で、保存後の指摘が 5〜7 秒から 0.1 秒、開いたときの結果が 10〜12 秒から 5.5 秒)
- **Windows の Arm**: Windows の arm64 向けの CLI と VS Code 拡張。Visual Studio 拡張と Rider プラグインも arm64 の言語サーバーを起動
- **Unreal Engine**: エンジンとプロジェクトを解析するファイルから検出 (エンジンの中のファイルか、上のフォルダーの `.uproject`)。`unreal: engine` / `unreal: project` の記述が不要に
- **ルールの追加**: HL0355 / SG0364 (`GetAttributeAtVertex` に頂点の入力でない値)、HL0356 / SG0365 (使用できないステージから届く `discard`・`clip`・微分・LOD を指定しないサンプリング)、SG0366 (`#language` の指令)
- **Slang**: slangc の誤りの検出を拡大 (自動微分、`extension` の中の可視性、`constexpr` の仮引数、`[ForceUnroll]`、利用者の属性など)。`-entry` / `-stage` で選ぶエントリポイントとステージを `units:` に記述可能
- **エディタのページ**: VS Code・Visual Studio・Rider のページの説明を同じ英語の文に統一し、拡張機能の README を英語と日本語の 2 つに。Rider プラグインのアイコンの追加と、Visual Studio Marketplace の説明の文字化けの修正

詳細は [CHANGELOG](https://github.com/OmojiP/shaderlyn/blob/main/CHANGELOG.md#未リリース) を参照。
